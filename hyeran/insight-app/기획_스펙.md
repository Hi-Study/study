# 인사이트 — 기획·기능 스펙 (현행 v2.4)

> 이 문서는 **현재 구현된 프로토타입 기준**의 기능 명세다. 디자인 토큰·컴포넌트 스타일은 `design.md`가 담당하고, 이 문서는 **무엇을 / 어떻게 동작하는가(기능·데이터·규칙)**를 담는다.
> 구현 스택: Next.js(App Router) · Supabase(Postgres/Auth/RLS) · Gemini(요약).
> **이 문서 하나가 단일 기준이다.**

---

## 0. 목적과 비전

흩어진 테크 기업 기술블로그를 한곳에 모아, IT 종사자가 최신 흐름과 트렌드를 놓치지 않게 한다.

글을 읽고 끝나지 않도록 각자의 **인사이트**를 남기게 하고, 서로의 해석이 겹쳐지며 생각을 더 뾰족하게 만든다.

쌓인 인사이트는 개인에게 **성장 노트**가 되고, 서비스에는 같은 문제를 겪는 사람들이 모여 논의하는 **장**이 된다.

> **우리가 만드는 것은 글 모음이 아니라, 같은 글을 읽은 사람들의 생각이 만나는 자리다.**

## 1. 개요

**한 문장**: 기업 기술·기획 블로그의 좋은 글을 모아 읽고, 각자의 **인사이트**를 남겨 공유하는 모바일 커뮤니티.

**핵심 가치**: 글 자체보다 **"누가 이 글에서 무엇을 얻었는가(인사이트)"** 가 본질. → `인사이트` 탭이 서비스의 심장.

**사용자(인사이터)**: 기획자·디자이너·개발자 등 프로덕트 종사자. **구글 로그인**으로 누구나 가입.

**콘텐츠 소스**
- 시스템이 기업 블로그를 **자동 수집(크롤)** → AI 요약 자동 생성
- 수집되지 않은 글은 사용자가 **직접 등록**(URL) → 크롤링+AI 요약 자동, 등록 시 인사이트 필수

## 4. 콘텐츠 소스 & AI

**자동 수집 파이프라인** (`scripts/collect.mjs`)
- 기업 RSS → 원문 추출(Readability) → 봇 차단(403 등) 시 RSS 본문(content:encoded)으로 폴백
- 본문은 **구조형 블록 배열**로 저장 (§7 posts.body 참조)
- Gemini 요약 → `problem`/`solution`/`learning`(각 한 문장) + `category` + `tags`

**직접 등록** (`/register`)
- URL 입력 → **중복 확인** + 인사이트 3문항(최소 1개 필수)
- 등록 시 원문 크롤링 → 블록 본문 + AI 요약 + 카테고리/태그/기업 자동 판별 → 상세로 이동

**AI 요약 3문항** (상세 상단 카드)
1. 무슨 문제를 다뤘나 (problem)
2. 어떻게 해결했나 (solution)
3. 기획 관점에서 무엇을 배울 수 있나 (learning)

> AI 요약은 **원문 읽기를 대체하지 않는다.** 빠르게 판단해 원문으로 진입시키는 것이 목적이다.

### 카테고리 — **11개** *(v2.4 확장, 기존 4개에서 변경)*

`프로덕트 · UIUX · 디자인 · AI · 비즈니스 · 데이터 분석 · 프론트엔드 · 백엔드 · 데이터베이스 · 보안 · 모바일`

- 글 1개당 카테고리 **1개** (AI 자동 판별)
- 피드에서는 **다중 선택 필터**로 사용

**색상 계열 그룹** — 카드 좌측 3px 카테고리 바에 사용. 11색은 식별이 불가능하므로 **4계열로 묶어 색을 부여**한다.

| 계열 | 카테고리 | 색 |
|---|---|---|
| 프로덕트 | 프로덕트 · 비즈니스 | `--blue` |
| 디자인 | UIUX · 디자인 | `--orange` |
| 개발 | 프론트엔드 · 백엔드 · 데이터베이스 · 보안 · 모바일 | `--lime` |
| 데이터·AI | AI · 데이터 분석 | `--sky` |

> 칩은 11개로 세분화하되 **색은 4계열만** 쓴다. 색은 "정확히 어떤 카테고리인지"가 아니라 "대략 어느 갈래인지"를 알려주는 장치다. 구체적 토큰은 `design.md`.

## 5. 화면별 기능

### 5-1. 홈 — 8개 큐레이션 섹션

**홈의 목적**: **빠르게 발견하고, 인사이트를 남기게 한다.**
섹션 채택 기준 — ⓐ "이 글 읽고 싶다"를 만드는가(발견) ⓑ "나도 뭔가 남기고 싶다"를 만드는가(활성화).

| # | 섹션 | 데이터 기준 | 노출 | 타이틀 | 부제 | 더보기 |
|---|---|---|---|---|---|---|
| ① | 오늘의 글 | 최근 **7일** (읽음 수 + 인사이트 수) 최다 | 1편 · 히어로 카드 | **없음** (섹션 헤더 미노출) | — | — |
| ② | 인기 키워드 칩 | 최근 **2주** `posts.tags` 빈도 상위 | **8개** · 칩 1줄 | 요즘 이 단어들이 자주 보여요 | 없음 | — |
| ③ | 인기 글 | 최근 **30일** 인사이트 수 상위 | 10개 · 스와이프 | 인사이트를 많이 남겼어요 | 없음 | — |
| ④ | 인기 인사이트 | 최근 **30일** `review_likes` 상위 | 10개 · 스와이프 | 이 생각에 공감을 많이했어요 | 없음 | — |
| ⑤ | 아직 안 끝난 글 | **조회한 글**(완독+미완독) 중 **인사이트 미작성**, 최근 조회순 | 10개 · 스와이프 | 마저 끝내볼까요? | 다 읽고 인사이트도 남겨보세요 | **마이 > 조회한 글** |
| ⑥ | 추천 글 | 내 활동 태그 유사도 상위 | 10개 · 세로 리스트 | 이 글도 관심이 있을 것 같아요 | 없음 | — |
| ⑦ | 즐겨찾기 기업 새 글 | `favorites` 기업 새 글, 최신순 | 10개 · 스와이프 | 관심 기업에 새 글이 올라왔어요 | 없음 | **피드 > 즐겨찾기 칩** |
| ⑧ | 사용자 등록 글 | `source='direct'` 최신순 | 10개 · 스와이프 | 인사이터가 직접 소개하는 글이에요 | 없음 | **피드 > 직접 등록 칩** |

**존 구분**

```
발견        ① 오늘의 글   ② 인기 키워드 칩   ③ 인기 글   ④ 인기 인사이트
나          ⑤ 아직 안 끝난 글   ⑥ 추천 글
관심        ⑦ 즐겨찾기 기업 새 글   ⑧ 사용자 등록 글
```

**레이아웃 규칙**

- **홈에서 2열 그리드를 사용하지 않는다.** ①(히어로)과 ⑥(세로 리스트)을 제외한 전 섹션은 **가로 스와이프**.
  - 근거: 2열 그리드 8개는 약 900px로 가로 스와이프 3.5개분을 차지한다. 그리드는 피드의 기본 형태이므로 홈에서 빼도 잃는 것이 없고, **홈=가로로 훑는 화면 / 피드=세로로 파는 화면**으로 역할이 갈린다.
- **섹션 간격은 2단계로 운용한다.** 구분선 대신 여백으로 구분.
  - 섹션 타이틀 ↔ 콘텐츠: 좁게 / 섹션 ↔ 섹션: 기본 / **존 ↔ 존: 기본보다 넓게**. px 토큰은 `design.md`.
- **북마크 섹션은 홈에 두지 않는다** — 피드에 항상 북마크 탭이 있으므로 중복.
- **② 인기 키워드 칩 탭 시 → 검색 결과 화면으로 이동**(해당 키워드로 검색된 상태). 홈을 필터링하지 않는다. 홈에서 필터링이 걸리면 "홈이 곧 피드"가 되어 탭 정체성이 무너진다.

**⑤ 아직 안 끝난 글 — 상태 정의**

| 상태 | 조건 | 배지 |
|---|---|---|
| **읽던 중** | `post_views`에 있고 `reads`에 없음 | 회색 |
| **남길 차례** | `post_views`·`reads` 모두 있음 | 강조 |

- 정렬: **최근 조회순** 10개 · **인사이트 미작성 필터 필수**
- **자동 소멸**: 인사이트를 쓰면 섹션에서 사라짐 → 섹션 자체가 하나의 루프
- 0건이면 섹션 숨김

**폴백**

| # | 조건 | 처리 | 폴백 타이틀 / 문구 | 액션 |
|---|---|---|---|---|
| ③ | 인사이트 부족 | 최신순 정렬 | 막 이야기가 시작됐어요 | — |
| ④ | 좋아요 없음 | 최신순 정렬 | 먼저 읽은 사람들의 생각은? | — |
| ⑤ | 0건 | **섹션 숨김** | — | — |
| ⑥ | 내 활동 0건 | **섹션 숨김** | — | — |
| ⑦ | 즐겨찾기 0개 | **유도 배너** | 자주 보는 기업을 골라두세요 | 관심 기업 설정(피드 All 셀렉트)으로 이동 |
| ⑧ | 0건 | **유도 배너** | 좋은 글을 찾으셨다면 인사이터들에게 알려주세요 | **[글 등록]** → 글 등록 화면 |

> ①②는 항상 데이터가 있어 폴백을 정의하지 않는다. ⑤⑥⑦⑧만 숨기는 이유는 폴백 콘텐츠를 넣으면 **섹션 이름이 거짓이 되기** 때문이다. 신규 유저에게는 **①②③④**가 남아 빈 홈이 되지 않는다.

### 5-2. 피드 — 기준 화면 *(v2.4 필터 구조 개편)*

- **언더라인 탭**: 전체 / 북마크

**필터 1줄 — 출처(기업)**

```
[ All ▾ ] [ 즐겨찾기 ] [ 직접 등록 ] [ 토스 ] [ 카카오 ] …   ← 가로 스와이프
```

| 항목 | 동작 |
|---|---|
| **`All` 셀렉트** | 탭 시 **전체 기업 목록 시트** 오픈. 12개 기업 전체 노출 + **각 행에서 즐겨찾기(★) 설정/해제** |
| **`즐겨찾기` 칩** | **즐겨찾기 1개 이상일 때만 노출.** 선택 시 즐겨찾기 기업 전체로 필터 |
| **즐겨찾기한 기업 칩** | 즐겨찾기한 기업들이 개별 칩으로 `즐겨찾기` 칩 뒤에 함께 노출, 가로 스와이프 |
| **`직접 등록` 칩** | `posts.source = 'direct'` 필터. 출처가 *기업*이 아니라 *사용자*인 글 |
| 선택 상태 | **브랜드색 채움**(비선택 = 흰 칩) |

> **즐겨찾기 설정은 `All` 셀렉트 시트 안에서 한다.** (v2.3의 별도 ⚙ 버튼은 폐지 — 기능이 중복됨)
> 즐겨찾기가 0개면 칩 줄은 `All ▾ · 직접 등록`만 남는다.

**필터 2줄 — 카테고리**

```
[ All ▾ ] [ 프로덕트 ] [ UIUX ] [ AI ] …   ← 선택한 것만 칩으로, 가로 스와이프
```

| 항목 | 동작 |
|---|---|
| **`All` 셀렉트** | 탭 시 **카테고리 목록 시트** 오픈. 11개 전체 노출, **다중 선택** |
| **선택한 카테고리 칩** | 선택한 것만 칩으로 노출, 가로 스와이프. 칩 탭 시 해제 |

- **리스트**: 2열 커버 카드 그리드
- URL 파라미터: `?tab=bookmark`, `?company=<id>`, `?source=direct`, `?category=<slug>`

### 5-3. 인사이트 탭 — 감상 피드
- **언더라인 탭**: 전체 / 북마크(내가 북마크한 글의 인사이트)
- **인사이트 카드**: 좌 글 썸네일 + 작성자·날짜 + 글 제목 + **Q&A 전체(길면 더보기/접기)** + **좋아요 수** + 댓글 수
- 카드 클릭 → 상세로 이동하며 **해당 인사이트로 스크롤·강조(포커싱)**

> **§6의 "다른 인사이터 인사이트 기본 접힘" 규칙은 이 탭에 적용하지 않는다.** 인사이트 탭은 애초에 다른 사람의 생각을 보러 오는 맥락이므로 전부 노출한다.

### 5-4. 검색
- 실시간 필터(제목·기업·태그) → **리스트 로우** 결과
- **최근 검색어**(기기 저장, 개별 삭제) · **추천 검색어(문장형)** · **급상승 검색어**
- **홈 ② 인기 키워드 칩에서 진입 시 해당 키워드로 검색된 결과 화면**이 바로 열린다

### 5-5. 마이 — **4탭** *(v2.4 순서 변경)*

- 프로필(아바타·이름) + **로그아웃**
- **4탭(개수 표시)** → **리스트 로우**

| 순서 | 탭 | 데이터 |
|---|---|---|
| **1** | **조회한 글** | `post_views` 최근 조회순 **전체** *(기본 선택 탭)* |
| 2 | 인사이트 남긴 글 | 기존 |
| 3 | 댓글 단 글 | 기존 |
| 4 | 하이라이트한 글 | 기존 |

> 홈 ⑤와의 차이: 홈 ⑤는 **인사이트 미작성 필터가 걸린 할 일 목록**, 마이 `조회한 글`은 **필터 없는 전체 열람 이력**(아카이브). 마이에서까지 걸러내면 "내가 본 글 다시 찾기"가 안 되므로 필터를 맞추지 않는다.

### 5-6. 글 상세

**구성 순서 (위→아래)**

```
카테고리 바 · 제목 · 기업/작성자 · 날짜 · 태그
AI 요약 카드 (3문답)
원문 리더
──────────────────────────────
[ 이 글에서 무엇을 느끼셨어요? ]    ← 최상위 CTA (풀와이드)
──────────────────────────────
다른 인사이터의 인사이트 N개  [ 보기 ]   ← 기본 접힘
```

**기본 요소**
- 카테고리 바 + 제목 + 기업/작성자 + 날짜 + 태그
- **직접 등록 글**: 작성자 카드(아바타·이름·"직접 등록" 배지) 강조 / 본인이면 앱바에 **수정·삭제**(삭제 시 달린 인사이트·댓글 수 명시)
- **AI 요약 카드**(3문답)
- **원문 리더** (본문을 불러온 글):
  - **구조형 렌더** — 헤딩/문단/목록/인용/코드/이미지 위계 유지
  - **원문 링크**(↗) 제공
  - **문단 단위 하이라이트 + 메모**(아이콘→모달, 나만 보기)
  - 불러오지 못한 글은 원문 링크 카드만
- **진입 시 `post_views` upsert** · **90% 스크롤 시 `reads` 기록** · **북마크** 토글

**인사이트 작성 CTA**

| 항목 | 규칙 |
|---|---|
| 위치 | 원문 리더 종료 직후, **다른 인사이터 인사이트보다 위** |
| 형태 | 풀와이드 강조 버튼. 글 상세의 **단일 최상위 CTA** |
| 문구 | 미작성 시 **`이 글에서 무엇을 느끼셨어요?`** *(v2.4 변경)* / 작성 후 **`내 인사이트 수정`** |
| 스크롤 | CTA를 지나치면 **하단 고정 바(sticky)** 로 전환 |
| 위계 | 북마크·공유·원문 링크는 **아이콘 또는 보조 버튼**으로 위계를 낮춘다 |

**다른 인사이터의 인사이트 — 기본 접힘**

| 항목 | 규칙 |
|---|---|
| 기본 상태 | **접힘**. 헤더에 `다른 인사이터의 인사이트 N개` + 작성자 아바타 3개 미리보기 |
| 펼침 | **[보기]** 클릭 시 펼침. **강제 잠금 없음** |
| 유지 | 접기 버튼 제공. 해당 글에서는 세션 동안 펼침 상태 유지 |
| 자동 펼침 | **내 인사이트 게시 직후 자동 펼침** + 안내 1줄 `이제 다른 인사이터들의 생각을 볼 차례예요` |
| 내 인사이트 | 접힘 대상이 아님. 항상 CTA 자리에 노출 |
| 설계 의도 | 남의 해석을 먼저 보면 내 생각이 물든다. **먼저 쓰고, 그다음에 열어봐야** 두 해석이 진짜로 겹쳐진다 (§0) |

**펼친 뒤 인사이트 목록**
- 각 인사이트 = 작성자 + 3문답 + **좋아요**(`review_likes`) + **인라인 "댓글 및 토론"**(입력창 + 댓글 + **대댓글** + 댓글 좋아요)
- 내 인사이트엔 **⋯ 점 메뉴 → 수정**
- 인사이트 탭에서 포커싱 진입한 경우: **해당 인사이트만 펼친 상태**로 진입하고 스크롤·강조

### 5-7. 알림
- 종류: **새 글** / **인사이트 댓글**(내 인사이트에 댓글, 내 댓글에 답글)
- 탭(전체/새 글/인사이트 댓글) · 진입 시 읽음 처리
- **좋아요는 알림 대상이 아니다** — 양이 많아 댓글 알림이 묻힌다
- **즐겨찾기 기업 설정은 이 화면에 두지 않는다** — 알림은 결과를 보는 화면. 설정은 피드 `All` 셀렉트(§5-2)

### 5-8. 로그인
- **구글 로그인 전용**. 미로그인 시 `/`(로그인) 외 접근 → 로그인으로 리다이렉트.

## 6. 핵심 규칙·로직

### 홈 큐레이션 산정

- **오늘의 글** = 최근 7일 글 중 (읽음 수 + 인사이트 수) 최대, 동률 시 최신. (7일 내 글 없으면 전체에서 선정)
- **인기 글** = **최근 30일** 인사이트 수 내림차순 → 동률 최신, 상위 10 (오늘의 글 제외)
- **인기 인사이트** = **최근 30일** `review_likes` 수 상위 10, 동률 시 댓글 수 → 최신
- **인기 키워드** = 최근 2주 등록 글의 `posts.tags` 빈도 상위 8
- **아직 안 끝난 글** = `post_views` 중 내 `reviews`가 없는 글, `viewed_at` 내림차순 10
- **추천 글** = 내가 북마크·인사이트·댓글 남긴 글의 태그와 유사도 상위 10
- **읽음 수** = `reads` 완독 수 (뷰수 대체)
- **통일 카드 메타**(전 화면 공통): 이미지·북마크·제목·작성자/출처·읽음 수·인사이트 수·등록일

### 중복 노출 제거

1. 렌더 순서대로 노출된 `post_id`를 `노출됨` 집합에 누적
2. 하위 섹션은 `노출됨`에 있는 글을 건너뛰고 **다음 순위로 채움**
3. 적용 대상: **① → ③ → ⑥ → ⑦ → ⑧**
4. **예외 ④ 인기 인사이트** — 인사이트 단위 섹션이므로 글 중복 허용
5. **예외 ⑤ 아직 안 끝난 글** — 개인 상태 기반. 여기서 빠지면 섹션 목적이 훼손됨

### 콜드스타트

- 기간 확장: **지정 기간 → 전체 기간**, 그래도 미달이면 최신순으로 채우고 타이틀을 폴백 문구로 교체
- 최소 임계값: ③ 인기 글은 **인사이트 2개 이상**, ④ 인기 인사이트는 **좋아요 1개 이상**인 항목만 후보

### 인사이트

- **인사이트 = 글당 유저 1개** (수정 가능), 3문항 중 최소 1개 필수
- **글 상세에서 다른 인사이터의 인사이트는 기본 접힘**, [보기] 클릭 시 펼침
- **내 인사이트 게시 직후 자동 펼침**
- **`이 글에서 무엇을 느끼셨어요?`는 글 상세의 단일 최상위 CTA**
- 접힘 규칙은 **글 상세에만 적용**. 인사이트 탭(§5-3)은 전부 노출
- **인사이트 좋아요는 자기 인사이트에도 가능하다. 예외 없음.**

### 기타

- **비로그인 북마크 시도** → 로그인 안내 (현재는 전 화면 로그인 필수라 방어 코드)

### 기능 판단 원칙

1. 글보다 인사이트가 먼저다
2. 남기는 것이 보는 것보다 쉬워야 한다
3. 내 생각이 먼저, 남의 생각은 그다음
4. 자동화(수집·AI 요약)는 목적이 아니라 입구다

**posts.body 블록 포맷**: `string[]`, 타입 접두어 —
`::h2::` · `::h3::` · `::p::` · `::li::` · `::quote::` · `::code::` · `::img::URL` · `::cap::`

**RLS**: 공용 콘텐츠는 로그인 유저 읽기, 쓰기는 본인 것만. 자동 수집은 서비스 롤로 삽입.

### 마이그레이션

```sql
-- 00X_review_likes.sql
create table review_likes (
  review_id  uuid not null references reviews(id)  on delete cascade,
  user_id    uuid not null references profiles(id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (review_id, user_id)
);
create index review_likes_review_idx  on review_likes(review_id);
create index review_likes_created_idx on review_likes(created_at desc);
alter table review_likes enable row level security;
create policy "read_all"   on review_likes for select to authenticated using (true);
create policy "insert_own" on review_likes for insert to authenticated with check (auth.uid() = user_id);
create policy "delete_own" on review_likes for delete to authenticated using (auth.uid() = user_id);

-- 00X_post_views.sql
create table post_views (
  user_id   uuid not null references profiles(id) on delete cascade,
  post_id   uuid not null references posts(id)    on delete cascade,
  viewed_at timestamptz not null default now(),
  primary key (user_id, post_id)
);
create index post_views_recent_idx on post_views(user_id, viewed_at desc);
alter table post_views enable row level security;
create policy "read_own"   on post_views for select to authenticated using (auth.uid() = user_id);
create policy "insert_own" on post_views for insert to authenticated with check (auth.uid() = user_id);
create policy "update_own" on post_views for update to authenticated using (auth.uid() = user_id);
```

**주의**

- `comment_likes` 미실행 마이그레이션(§9)과 **함께 실행**한다.
- **`reads`는 확장하지 않고 `post_views`를 신설한다.** `reads`는 §6의 **읽음 수(뷰수 대체 지표)** 로 쓰이므로, 미완독을 섞으면 전 화면 카드의 `읽음 N`이 왜곡된다.
- `review_likes`는 기존 인사이트에 **소급 적용 없음** → 오픈 직후 홈 ④는 폴백(최신순)으로 동작한다.
