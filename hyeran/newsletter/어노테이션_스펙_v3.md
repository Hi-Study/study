# 어노테이션 (가명) — 프로토타입 스펙 v3

> **용도**: 이 문서를 Lovable / Bolt.new / v0.dev / Claude에 통째로 붙여넣으면 클릭 가능한 모바일 프로토타입이 생성됩니다.
>
> **v2와 차이 (major pivot)**:
> - **핵심 가치가 원문 어노테이션 → 첫 번째 리더의 사유**로 이동
> - URL 파싱 실패에 취약하지 않도록 파싱은 부가 기능화
> - 사유 폼 4개 필드로 재구성, 2개 이상 필수
> - 등록 플로우 2단계 → 원스텝으로 단순화
> - 파싱 성공/실패에 따라 상세 페이지 구조 분기
> - 홈 카드 스니펫 제거 (제목+출처만)

---

## 1. 프로젝트 요약

**한 문장**: 매주 각자 좋은 글에서 얻은 사유를 4개 축으로 나눠 그룹에 공유하는 사유 공유 앱

**핵심 메커니즘**:
1. 원문은 참조 자료, **사유가 본질** — URL 파싱 실패해도 서비스 성립
2. 사유 폼 4개 필드 (인상깊은 부분 / 떠오른 생각 / 업무 접목 / 스터디원 질문) 중 2개 이상 채워야 게시
3. 원문이 파싱될 때만 하이라이트·코멘트·AI 요약·용어 추출이 부가 기능으로 활성
4. 사유는 페이지 최하단 — 원문 먼저 접하고 스터디원 스스로 사유한 뒤 리더 사유를 봐야 독립적 사유 유지

**사용자**: 폐쇄형 소그룹 (초대 코드로 가입)
**플랫폼**: 모바일 웹 프로토타입 (뷰포트 360-390px 폭 기준)
**결과물**: 클릭 가능한 정적 프로토타입, 로컬 state만 사용

## 3. 네비게이션 흐름

```
[온보딩] 초대 코드 → "계속"
   ↓
[홈 - 전체 피드]
   ├─ 상단 세그먼트 "큐레이션" → [홈 - 큐레이션 피드]
   ├─ 카드 탭 → [상세 - 파싱 성공] 또는 [상세 - 파싱 실패]
   ├─ FAB (+) → [등록]
   ├─ 종 아이콘 → [알림]
   ├─ 하단 탭 "검색" → [검색]
   └─ 하단 탭 "마이" → [마이]

[등록]
   ├─ 닫기(X) → 임시저장 여부 확인 후 이전 화면
   ├─ 임시저장 → 마이 임시저장 목록에 저장 후 이전 화면
   └─ 게시하기 (사유 4개 축 중 2개 이상 입력 시 활성) → [홈] (내 글 상단 추가)
       └─ 백그라운드에서 원문 파싱 시도 (성공/실패 자동 처리)

[상세 - 파싱 성공]
   ├─ 뒤로 → 이전 화면
   ├─ 상단 북마크 → 토글
   ├─ 상단 공유 → 시스템 공유 시트
   ├─ 상단 눈 아이콘 → 다른 사람 하이라이트 토글
   ├─ 상단 더보기 → 편집/삭제(본인) + 원문 열기
   ├─ 문장 탭 → 문장 하이라이트 or 하이라이트 해제
   ├─ 여백 버블 탭 → [버블 클릭 드로어]
   ├─ "원문 보기" 버튼 → 시스템 웹뷰로 원문 오픈
   ├─ "얘기하고 싶어요 · N명" CTA 탭 → 토글
   └─ 하단 액션 바 "코멘트 · 모아보기" → [코멘트 모아보기]

[상세 - 파싱 실패]
   ├─ 뒤로 → 이전 화면
   ├─ 상단 북마크 / 공유 / 더보기 (하이라이트 토글은 없음)
   ├─ URL 링크 카드 탭 → 새 탭에서 원문 열기
   ├─ "얘기하고 싶어요 · N명" CTA 탭 → 토글
   └─ (하단 액션 바 없음, 코멘트 없음)

[버블 클릭 드로어] 하단에서 슬라이드업
   ├─ 닫기(X) → 상세로 복귀
   ├─ 기존 코멘트 리스트 조회
   └─ 하단 입력 → 새 코멘트 저장

[코멘트 모아보기]
   ├─ 뒤로 → 상세
   └─ 카드 탭 → 상세의 해당 하이라이트 위치로

[마이]
   ├─ 상단 프로필 / 설정 아이콘 
   ├─ 임시저장 카드 탭 → 등록 화면으로 (저장된 내용 프리필)
   ├─ 4개 세그먼트 (내 글 / 하이라이트 / 북마크 / 큐레이션)
   ├─ 리스트 카드 탭 → 상세
   └─ 하단 탭 이동

[검색]
   ├─ 검색바 입력 → 결과 갱신
   ├─ 태그 필터
   └─ 결과 카드 탭 → 상세

[알림]
   ├─ 뒤로 → 이전 화면
   └─ 알림 항목 탭 → 상세
```

## 4. 화면별 상세 스펙

### 4.1 온보딩

- **레이아웃**: 상단 여백 → 로고 아이콘 (라운드 사각형, 액센트 색) → 앱 이름 "어노테이션" → 카피 **"이 글의 첫 번째 리더가 되어보세요"** → 하단 폼 (초대 코드 입력, "계속" 버튼)
- **카피 톤**: 헤드라인은 앱 이름 아래 살짝 큰 폰트(18-20px, weight 500)로 임팩트
- **인터랙션**: 초대 코드 입력 없어도 "계속" 누르면 홈으로 이동

### 4.2 홈 피드

**공통 구성**
- 상단: 앱 헤더 (좌: 앱 이름 or "홈", 우: 종 아이콘)
- 그 아래: 세그먼트 컨트롤 "전체 피드" / "큐레이션 피드"
- 메인: 카드 리스트 (시간 역순)
- 우하단: FAB (+ 아이콘, 원형, 액센트 색)
- 하단: 탭 바 3개 (홈 / 검색 / 마이)

**카드 컴포넌트 (v3에서 단순화)**
- 좌: 썸네일 (48×48, 라운드, 회색 배경 + 콘텐츠 아이콘)
- 우:
  - 제목 (1-2줄, 미디엄 웨이트)
  - 메타 라인: 출처 도메인 (액센트 색) · 공유자 · 상대 날짜
  - 태그 칩들
  - 하단 액션 라인: 얘기하고 싶어요 카운트, 코멘트 카운트 (파싱 성공 시), 하이라이트 카운트 (파싱 성공 시)
- **본문 스니펫 미포함** — 제목·출처·태그·메타만. 사유 축약은 AI 필요해서 우선 제외.

**상대 날짜 표기**
- 오늘 / 어제 / 이번주 / M/D

**전체 vs 큐레이션 차이**
- 전체: 모든 게시된 글 표시
- 큐레이션: "얘기하고 싶어요"가 1회 이상 눌린 글만 필터, 카운트를 액센트 색으로 강조

### 4.3 검색

- **상단**: 뒤로 아이콘 / "검색" 타이틀 / (우측 공백)
- **검색바**: 회색 pill 형태, 돋보기 아이콘 + 입력 필드 + X 아이콘
- **태그 필터**: "태그 필터" 라벨 아래 chip cloud, 선택된 태그는 액센트 색
- **결과 리스트**: "결과 N" 헤더 + 컴팩트 카드 리스트
- **하이라이트**: 검색어와 매칭된 부분에 `<mark>` 태그 (액센트 배경)
- **하단**: 탭 바 (검색 활성)

### 4.4 마이

- **상단**: 좌측 공백 / "마이" 타이틀 / 우측 설정 아이콘
- **프로필 섹션**: 아바타 (원형, 회색 배경 + 이니셜 "다") + 이름 "다람쥐" + 서브 라벨 "기획자 스터디"

- **임시저장 섹션** (프로필 아래, 세그먼트 위)
  - 헤더: "임시저장 N" (연필 아이콘 + 액센트 색)
  - 각 카드: 문서 아이콘 + 제목 (1줄 말줄임) + 출처·최종수정일
  - 카드 탭 → 등록 화면으로 (저장된 내용 프리필)
  - **v3 참고**: Step 개념 없어졌으니 Step pill도 없음. 그냥 임시저장된 폼으로 복귀.

- **4개 세그먼트** (세그먼트 컨트롤)
  - 내 글 N (게시 완료 글)
  - 하이라이트 N (내가 남긴 하이라이트 총 개수 — 파싱 성공 글에서만)
  - 북마크 N
  - 큐레이션 N

- **리스트 아이템**
  - 내 글 / 북마크 / 큐레이션: 컴팩트 카드
  - 하이라이트: 다른 구조 — 하이라이트 문장 인용(노란 배경) + "○○ 글에서 · 며칠 전" 메타. 탭 시 그 글의 그 위치로

- **하단**: 탭 바 (마이 활성)

### 4.5 알림

- **상단**: 뒤로 아이콘 / "알림" 타이틀 / (우측 공백)
- **세그먼트**: "전체" / "안읽음 N"
- **알림 항목**:
  - 좌측: 안읽음이면 액센트 색 dot (6×6), 읽음이면 공백
  - 우측: "{이름}님이 {행동}" + 관련 콘텐츠 스니펫 + 상대 시간
- **인터랙션**: 항목 탭 → 상세로 이동, 읽음 처리
- **알림 종류**: 새 글 등록, 내 글에 코멘트(파싱 성공 글에 한함)

### 4.6 상세 (파싱 성공 케이스) — 핵심 화면 A

**전체 순서 (위→아래, 스크롤)**
1. 제목 · 메타 (출처·공유자·날짜) · 태그
2. **AI 요약 카드** (첫 섹션, 3줄 내외)
3. **원문 본문** (리더 모드 파싱, 문장 단위 저장) — 하이라이트 인라인 + 여백 코멘트 버블
4. **알고 가면 좋을 용어 카드** (최대 5개, 접힘 상태 or 펼침)
5. "**원문 보기 ↗**" 버튼 (아웃라인, 전체 폭) — 시스템 웹뷰
6. **첫 리더의 사유 카드** — 4개 필드
   - avatar + "{이름}의 사유"
   - 어떤 부분이 인상깊었는지 (텍스트)
   - 어떤 생각을 떠올렸는지 (텍스트)
   - 어떤 부분을 현재 업무·프로젝트에 접목하고 싶은지 (텍스트)
   - 스터디원에게 어떤 질문을 던져보고 싶은지 (텍스트)
   - **작성 안 한 필드는 섹션 자체를 렌더링하지 않음**
7. "**얘기하고 싶어요 · N명**" CTA (액센트 배경, 전체 폭 큰 버튼)

**상단 헤더 (고정)**
- 좌: 뒤로 아이콘
- 우: 북마크 · 공유 · 눈 (다른 사람 하이라이트 토글, ON시 액센트) · 더보기 4개 아이콘

**하단 액션 바 (고정, 스크롤 하이드)**
- 단일 pill: "코멘트 · 모아보기 N"

**원문 렌더링 (문장 단위)**
- 원문은 파싱 시 문장 배열로 저장 (마침표·물음표·느낌표·줄바꿈 기준으로 분리)
- 각 문장은 flex row: 좌측 문장 텍스트 + 우측 여백 24-30px에 코멘트 버블
- 문장 탭 → 하이라이트 토글 (하이라이트 만들기 or 해제)

**하이라이트 시각화**
- 노란 배경: 본인 하이라이트 (`bg-warning` 계열)
- 파란 배경: 다른 사람 하이라이트 (`bg-accent` 계열) — 상단 눈 토글 ON일 때만

**여백 코멘트 버블**
- 크기: 높이 18-20px, 최소 폭 28-30px, 라운드 pill
- 색상: 하이라이트 색과 매칭
- 내용: 말풍선 아이콘 + 코멘트 수
- 탭 → 버블 클릭 드로어

### 4.7 상세 (파싱 실패 케이스) — 핵심 화면 B

**전체 순서 (위→아래)**
1. 제목 · 메타 · 태그
2. **URL 링크 카드** (큰 카드, 클릭 시 새 탭에서 원문 열기)
   - 카드 안: 외부 링크 아이콘 + URL + "원문은 이 링크에서 확인하세요" 안내
3. 첫 리더의 사유 카드 (4개 필드, 4.6과 동일)
4. "얘기하고 싶어요 · N명" CTA

**상단 헤더**
- 좌: 뒤로
- 우: 북마크 · 공유 · 더보기 (다른 사람 하이라이트 토글 없음)

**하단 액션 바 없음**

### 4.8 상세 - 버블 클릭 드로어 (파싱 성공 케이스에서만)

- 여백 버블 탭 시 하단에서 슬라이드업
- 원문 body는 위쪽 일부 노출 (drawer가 화면 하단 절반 정도)
- **드로어 구성**:
  - drag handle
  - 헤더: "이 문장에 남긴 코멘트 N" + X 닫기
  - 하이라이트 문장 인용 박스
  - 코멘트 리스트 (시간순, 24px avatar + 이름·시간 + 본문)
  - 하단 인풋 (텍스트 pill + 원형 전송 버튼)

### 4.9 상세 - 코멘트 모아보기 (파싱 성공 케이스에서만)

- **상단**: 뒤로 / "코멘트 모아보기 · N" / (우측 공백)
- **본문**: 카드 리스트
- **각 카드 = 하나의 하이라이트 + 그에 붙은 코멘트들**
  - 카드 상단: 하이라이트 문장 인용 (노랑/파랑)
  - 카드 하단: 코멘트 리스트
- **정렬**: 원문 순서
- **인터랙션**: 카드 탭 → 상세의 해당 하이라이트 위치로

### 4.10 등록 (원스텝)

**상단**: X 닫기 / "글 등록" / [게시하기] 버튼 (사유 2개 이상 채워지면 활성)

**본문 스크롤**

## 5. 핵심 인터랙션

## 8. 인터랙션 규칙 (프로토타입 범위)

- 모든 화면 이동은 로컬 라우팅
- **하이라이트**: 문장 탭 → boolean 토글, state에 저장
- **코멘트**: 드로어 인풋 → 전송 → state에 추가
- **다른 사람 하이라이트 토글**: 눈 아이콘 → boolean 반전 → 파란 하이라이트 조건부 렌더링
- **얘기하고 싶어요**: CTA 클릭 → boolean 반전
- **북마크**: 상단 아이콘 → boolean 반전
- **태그**: chip 클릭 → 선택 배열 add/remove
- **등록 필수 조건**: `[Q1, Q2, Q3, Q4].filter(Boolean).length >= 2` → 게시하기 활성
- **임시저장**: state 배열에 draft 추가 (URL·태그·사유 상태 포함)
- **파싱 시뮬레이션**: 게시 후 hardcoded `parsed: true/false` 플래그로 성공/실패 구분. 상세 페이지에서 이 플래그 기준으로 4.6 vs 4.7 렌더링
- **원문 보기**: 실제 URL을 `target="_blank"`로 열기
- **문장 단위 저장**: Post 1 원문처럼 문장 배열로 하드코딩

> - 상세 페이지는 Post의 `parsed: true/false` 플래그로 두 가지 구조 분기 렌더링
>   - `parsed: true`: 원문(문장 단위) + 하이라이트 + AI 요약 + 용어 + 리더 사유 + CTA
>   - `parsed: false`: URL 링크 카드 + 리더 사유 + CTA
> - 파싱 성공 상세 페이지에서 문장 탭 → 하이라이트 토글
> - 여백 버블 탭 → 하단 드로어 슬라이드업 → 코멘트 조회·작성
> - 상단 눈 아이콘 → 다른 사람(파란) 하이라이트 표시/숨김 토글
> - 상세 최하단 "얘기하고 싶어요" CTA → 토글, 카운트 반영, 큐레이션 피드에 노출
> - 임시저장은 state 배열에 draft 추가, 마이 페이지에서 이어서 진행
>
> **범위**
> - 실제 백엔드 호출 없음, 모두 로컬 state
> - Readability 실제 실행 없음 (샘플 원문 하드코딩, 파싱 결과 시뮬레이션)
> - AI 생성 결과도 하드코딩
>
> 각 인터랙션이 실제로 동작해야 하고, 팀원에게 URL로 공유해서 전체 플로우를 클릭으로 따라갈 수 있어야 합니다.
