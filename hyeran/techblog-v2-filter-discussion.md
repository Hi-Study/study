# 관점 아카이브 — 글 거르기: Gemini 가벼운 모델이 잘 못 거른다

- 작성: 혜란 · 2026-10-13
- 대상 사이트: https://study-beta-ten-70.vercel.app (영진님 `techblog-archive-v2`)
- 거르는 기준(프롬프트): `src/core/1-analyze/analyze.ts` 의 `GATE_SYS`. **이번 비교에서는 프롬프트를 바꾸지 않았다.**
- 시험 자료: [techblog-v2-gate-test/](./techblog-v2-gate-test/README.md)

## 1. 문제

피드에 개발자용 글이 너무 많이 올라가 있다. 수집 97건 중 73건이 통과했고, 그중 약 60건이 사내 운영·개발 이야기다.
(예: 「Python GC와 Airflow」「Aurora MySQL 인덱스 DDL」「Redis vs MongoDB」)

## 2. 확인한 것 — 같은 프롬프트, 모델만 바꿔서

### 숫자 읽는 법

```
사이트가 모은 글 97건
├─ 사이트(Gemini)가 올린 글 73건
│   ├─ Claude도 올린 글 48건
│   └─ Claude는 뺀 글 25건  ← "갈린 25건": Gemini가 잘못 통과시켰을 가능성이 높은 글
└─ 사이트(Gemini)가 뺀 글 24건 → Claude도 24건 모두 뺐다
```

- **97건** — 사이트가 지금까지 모은 글 전체.
- **25건(갈린 글)** — 사이트는 올렸는데 Claude는 빼야 한다고 본 글. 반대로 사이트가 뺀 글을 Claude가 올린 경우는 한 건도 없었다.
- **40건(시험 묶음)** — 다른 모델을 시험할 때 97건을 다 돌리기엔 비용이 커서 골라 만든 묶음.
  - 갈린 글 25건 — 새 모델이 이걸 잘 빼는지 본다 (가장 중요)
  - 둘 다 올린 글 8건 — 좋은 글을 실수로 빼지 않는지 본다
  - 둘 다 뺀 글 7건 — 뺄 글을 실수로 올리지 않는지 본다

### 97건 전체 결과

| 판정 | 97건 중 통과 |
|---|---|
| 사이트: Gemini `flash-lite` (가장 가벼운 Gemini) | **73** |
| Claude Sonnet 5.5 | **48** |

갈린 25건은 대부분 개발 구현·개발자 내부 이야기다 (예: 「Python 멀티프로세싱과 Airflow」「Redis vs MongoDB」「낙관적 락」「항공 프론트엔드 구축기」「컬리 AI 오케스트레이션」).

### 40건 시험 결과 — Claude 가장 가벼운 모델(Haiku 4.5)도 돌려 봤다

| 판정 (40건) | 40건 중 통과 | 갈린 25건 중 통과 |
|---|---|---|
| Gemini flash-lite (사이트) | 33 | 25 |
| Sonnet 5.5 | 8 | 0 |
| Haiku 4.5 | 12 | 6 |

**→ 같은 프롬프트에서 Gemini flash-lite 만 유독 너그럽다.** Claude는 가장 가벼운 Haiku도 Sonnet과 비슷하게 걸렀다.

지금 프롬프트는 "주로 무엇을 다루는지 보라", "'운영'이라는 말만 보고 통과시키지 마라" 같은 미묘한 판단을 요구하는데, flash-lite 는 이를 잘 지키지 못하고 "운영 문제를 기술로 풀었다"는 큰 문장 쪽으로 기우는 것으로 보인다.

### 이 비교의 한계
- Claude 판정은 API가 아니라 Claude Code 에이전트로 했고, 원문을 웹에서 다시 받아 읽었다. 한 번씩만 돌렸다.
- 상위 Gemini(flash, pro)는 아직 시험하지 않았다.
- 어느 쪽이 "정답"인지는 사람이 정해야 한다. 지금은 Claude가 더 엄격하다는 것까지 확인했다.

## 3. 같이 시험할 것 — 쪼갠 질문 방식

AI에게 "넣을까 뺄까"를 한 번에 묻지 않고, ① 글이 주로 다루는 것 ② 실제로 바뀐 사람 ③ 근거 원문 문장만 고르게 한 뒤 **코드가 결정**하는 방식. (영진님 문서의 "AI는 읽고 쓰고, 결정은 코드가 한다" 원칙과 같다.)

- Haiku에서는 정확도가 지금 프롬프트와 같았다(Sonnet과 40건 중 32건 일치).
- 장점: 넣고 뺀 이유가 라벨로 남고, 기준을 바꿀 때 코드 조건만 고치면 된다.
- **가벼운 Gemini에서 효과가 있는지는 아직 모른다** — 그래서 같이 시험한다.

## 4. 다음 순서

1. **모델 비교 시험** (영진님 — 원문과 키 보유)
   같은 40건을 Gemini flash-lite / Gemini flash / Claude Haiku 4.5 × 지금 프롬프트 / 쪼갠 질문 방식으로 돌린다. 방법: [시험 묶음 README](./techblog-v2-gate-test/README.md)
2. **정답 정하기** (팀)
   갈린 25건에 대해 팀이 "넣는다/뺀다"를 정한다. 1번 결과를 이 정답과 맞춰 본다.
3. **모델 정하기** (팀)
   - 상위 Gemini가 충분하면 → 거르는 단계만 상위 Gemini로 (키 그대로, 변경 쉬움)
   - 아니면 → 거르는 단계만 Claude Haiku로 (Anthropic 키·결제 추가 필요)
   - 쪼갠 질문 방식을 넣을지도 이때 함께 정한다.
4. **기존 글 다시 판정** — 정한 모델·방식으로 기존 글 전체를 다시 거른다.
