## 왜 바꾸나

| 지금 (기술 분류 14개) | 문제 |
|---|---|
| "앱·웹 화면 구조", "서버·성능 개선", "데이터·실험 플랫폼" | 기술 이름이 아니라 **바구니**다. 워크숍 후기·웰컴키트·디자인 시스템·폰트 도입이 한 칸에 섞였다 |
| "생성형 AI" | 너무 넓다. AI 에이전트, AI 코딩, 사내 지식 검색, 이미지 생성이 전부 여기 들어간다 |
| 글에 나온 구체적 이름 (자유 텍스트) | 80건에서 120종, 2번 이상 나온 이름은 "Lynx" 하나. 너무 세세해서 묶이지 않는다 |

**목표: 업계에서 실제로 부르는 이름이면서, 여러 회사의 글이 함께 묶이는 굵기.**

## 고르는 원칙

1. **해결에 실제로 쓴 기술만.** 스쳐 지나간 언급은 붙이지 않는다.
2. **글 하나에 0~3개.** 맞는 게 없으면 비운다 — 억지로 넣지 않는다.
3. **원문에 그 기술(또는 별칭)이 실제로 나와야 한다.** 코드가 별칭 목록으로 원문을 대조한다.
4. **목록에 없는 기술은 "후보"로 모은다.** 같은 기술이 **3건 이상** 쌓이면 목록에 추가를 검토한다.

## 목록에 넣지 않은 것

**후보 — 1건뿐이라 지금은 목록 밖** (같은 기술이 3건 쌓이면 추가 검토)

인증·본인확인(당근 인증) · 서버 주도 화면(HTMX, 오늘의집) · 피처 플래그(무신사 웨이팅) · API 설계(채널톡 Open API) · 화면 상태 관리(React Query, 오버레이 큐) · 로드밸런싱(화해) · RSS(G마켓)

**키워드 없음 — 기술이 해결의 중심이 아닌 글**

조직·문화(AI 코칭, DevEx, 웰컴키트, 동료 밥 한 끼, 워크숍, 코드리뷰 문화) · UI 인터랙션(토스 플로팅 카드) · 문제 정의 방법론(하이퍼커넥트 볼록 완화) · 언어·런타임 디테일(Python fork, 폴더 컨벤션)
