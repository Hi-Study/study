# 분류 기준 ② — 분류한 글을 홈에 놓기

[분류 기준 ①](./01_분류기준.md)의 8단계까지 마친 글을 받아서, **홈의 어느 자리에 어떤 순서로 놓을지** 정한다.
단계 번호는 ①에서 이어진다(9단계~).

> 이건 **배치 기준**이다. 글을 새로 판정하지 않는다. ①에서 정해진 값만 읽어서 고르고, 세고, 줄 세운다.
>
> 정본은 코드다 — `src/app/page.tsx`(홈) · `src/core/3-place/home.ts`(고르고 세는 규칙) · `src/components/home/`(각 자리의 UI). 코드가 바뀌면 코드가 맞다.
> 2026-10-06 기준

**이 문서 전체를 꿰는 원칙 세 가지**

1. **경험 자리는 STRONG 만 센다.** "조금 덜었다고 볼 수도 있는" 글(WEAK)과 "분명히 덜어낸" 글을 같은 무게로 세지 않는다.
2. **사내 운영·개발 경험도 똑같이 센다.** 부담의 모양이 같으면 같은 경험이다. 🛠 태그로만 구분한다.
3. **한 자리에는 한 가지 기준만.** 최신순 자리, 경험 자리, 기술 자리를 섞지 않는다. 경험은 경험 자리에서만 묶는다.

```
① 1~8단계 결과
   └ 9 홈에 올릴 글 고르기
      ├ 10 맨 위 — 새로 들어온 글          (최신순)
      ├ 11 어떤 변화가 궁금한가요?         (경험 · STRONG)
      ├ 12 이런 문제를 어떻게 풀었을까요?  (회사별 최신 · STRONG)
      └ 13 요즘 자주 나오는 기술           (기술 분류)
```

---

## 9단계 — 홈에 올릴 글 고르기

①에서 넘어오는 값 중 홈이 읽는 것:

| 값 | ① 어디서 | 홈에서 쓰는 곳 |
|---|---|---|
| 포함 / 제외 | 1단계 | 포함된 글만 홈에 올린다. 제외 글 수는 요약 줄에만 |
| 대표 경험 · 적합도 | 6단계 | 11·12단계 |
| 보조 경험 | 6단계 | 11단계의 경험 페이지 "함께 볼 글" |
| 누구의 부담 | 5단계 | 🛠 태그, 경험 페이지 필터, 대표 사례 고를 때 우선순위 |
| 방식(Product Pattern) | 7단계 | 11단계 근거 행, 경험 페이지 묶음 |
| 기술 분류 | 7단계 | 13단계 |
| 카드 문장 · 문제 제목 · 문제 요약 | 8단계 | 10·11·12·13단계의 문구 |
| 발행일 · 썸네일 · 회사 로고 | 0단계 | 10·12·13단계 |

**가르는 선 — 해당 없음(NONE) 글**

- 경험으로 고르는 자리(11·12단계)에서는 **빠진다.**
- 최신순·기술로 고르는 자리(10·13단계)에는 **나올 수 있다.** 경험은 없어도 새 글이고, 쓴 기술은 있기 때문이다.

## 10단계 — 맨 위: 새로 들어온 글

**고르는 질문: 지금 막 들어온 글은 무엇인가?** 분류와 관계없이 최신순이다.

| 항목 | 기준 |
|---|---|
| 개수 | 발행일 최신 **4건** |
| 넘김 | 카드 한 장씩 **4.5초마다 자동**, 마지막 다음은 처음. 마우스를 올리거나 손을 대고 있으면 멈춤. 기기의 "동작 줄이기" 설정이면 자동으로 넘기지 않음 |

**카드 한 장 (위 → 아래)**

| 자리 | 내용 | 없을 때 |
|---|---|---|
| 이미지 | 글 썸네일 | 회사 대표 색 + 크게 키운 로고를 **블러 처리한 배경** 위에 선명한 로고 |
| 표시 | NEW · 발행일 · 🛠 사내 운영·개발 | — |
| 큰 문장 | 카드 문장 | 원래 글 제목 |
| 보조 줄 | 경험 이름 · 원래 글 제목 | 해당 없음이면 경험 이름 생략 |
| 버튼 | 읽으러 가기 | — |

## 11단계 — 어떤 변화가 궁금한가요?

**고르는 질문: 어떤 부담을 분명히 덜어낸 사례가 가장 많이 모였나?**

### 11-1. 세는 법과 순서

| 항목 | 기준 |
|---|---|
| 셈 | 대표 경험이 그 경험이고 **STRONG** 인 글만. WEAK·보조 경험은 세지 않는다 |
| 사내 글 | 같이 센다 |
| 순서 | **많이 모인 경험부터** |
| 0건인 경험 | 카드로 만들지 않고 아래 한 줄로만 — "아직 사례가 모이지 않은 경험 · 다시 말하지 않아도" |
| 넘김 | 경험 하나 = 카드 한 장. 모바일 한 장, PC 두 장씩 |

### 11-2. 카드 한 장 — 상황 → 결과 → 근거 → 행동

| 자리 | 예 | 어떻게 정하나 |
|---|---|---|
| 상황 | 결과를 기다리느라 지쳤다면 | 경험별 고정 문구 |
| 결과 (굵게 두 줄) | 기다림 없이 / **결과가 바로 나와요** | 경험별 고정 문구 |
| 대표 사례 | 우아한형제들 사례 · 사장님 입점 승인 대기 시간, 12분에서 10초로 줄었어요 | 그 경험 STRONG 글 중 **서비스 사용자 글을 먼저, 그다음 최신** → 카드 문장 |
| 관련 글 | 6건 | STRONG 글 수 |
| 참여 회사 | 4곳 | STRONG 글을 쓴 회사 수 |
| 주로 쓴 방식 | 먼저 처리하기 | STRONG 글에서 가장 많이 나온 방식의 짧은 이름 |
| 새 소식 | NEW 최근 30일 새 사례 2건 | 최근 **30일** 발행 STRONG 글 수. 없으면 "N개 회사의 사례를 모았어요" |
| 버튼 | '기다림 없이' 사례 보기 | → 경험 페이지 |

**경험별 고정 문구**

| 경험 | 상황 | 결과 |
|---|---|---|
| 기다리지 않아도 | 결과를 기다리느라 지쳤다면 | 기다림 없이 / 결과가 바로 나와요 |
| 찾지 않아도 | 원하는 걸 찾아 헤맸다면 | 헤매지 않고 / 찾던 게 먼저 보여요 |
| 비교하지 않아도 | 선택지 앞에서 고민이 길었다면 | 고민은 덜고 / 맞는 선택지만 남겨줘요 |
| 입력하지 않아도 | 같은 정보를 또 입력하고 있다면 | 입력은 덜고 / 알아서 채워줘요 |
| 다시 설명하지 않아도 | 같은 설명을 반복하고 있다면 | 다시 말하지 않아도 / 이전 이야기를 기억해요 |
| 직접 처리하지 않아도 | 여러 단계를 손으로 처리하고 있다면 | 손대지 않아도 / 알아서 처리돼요 |
| 확인하지 않아도 | 잘 됐는지 계속 확인하고 있다면 | 확인하지 않아도 / 먼저 알려줘요 |

### 11-3. 경험 페이지 — 경험 → 방식 → 글

카드를 누르면 가는 곳. 피그마의 그룹핑 순서(Problem Taxonomy → Experience → Product Pattern → Article)를 그대로 따른다.

| 자리 | 기준 |
|---|---|
| 머리말 | 질문형 "사용자를 기다리지 않게 하려면?" + 방법 + 줄어든 부담 |
| 필터 | 전체 / 서비스 사용자 / 🛠 사내 운영·개발 경험 |
| 본문 | STRONG 글을 **방식별로 묶는다.** 많이 모인 방식부터, 방식이 없는 글은 "그 밖의 방식"으로 맨 뒤 |
| 함께 볼 글 | **WEAK 글** + 이 경험을 **보조 경험**으로 가진 글 — "이 부담도 일부 덜어줬지만, 주로 다른 이야기를 다룬 글이에요" |

## 12단계 — 이런 문제를 어떻게 풀었을까요?

**고르는 질문: 회사마다 최근에 분명히 풀어낸 문제는 무엇인가?**

| 항목 | 기준 |
|---|---|
| 고르기 | **회사마다 최신 글 1건**, STRONG 만 (사내 글 포함) |
| 개수 | 최대 8장, 좌우로 넘김 |
| 배경 | 회사 대표 색. 밝은 색(노랑·연두 등)이면 글자를 어둡게 |

**카드 한 장 — 누구 → 무슨 문제 → 어떻게 풀었나**

| 자리 | 내용 | 없을 때 (임시) |
|---|---|---|
| 서비스명 | 작은 로고 + 회사 이름 | 회사 이름 첫 글자 |
| 문제 제목 | 해결 **전에** 누가 어떤 곤란을 겪었나 — 8단계 문제 제목 | 카드 문장 |
| ✦ 아카이브 요약 | 무엇이 문제였고, 어떻게 풀어서 무엇이 달라졌나 — 8단계 문제 요약 | 읽기 가이드 리드("왜 했대요" + "그래서 어떻게 됐대요") |

> 임시 문구는 개발 용어가 남아 있을 수 있다. 분류 v3 를 돌리면 8단계 문구로 바뀐다.

## 13단계 — 요즘 자주 나오는 기술

**고르는 질문: 요즘 테크 블로그에 어떤 기술이 많이 나오고, 그 기술로 쓴 글은 무엇인가?**
여기서는 **경험으로 묶지 않는다.** 경험은 11단계가 맡는다.

| 항목 | 기준 |
|---|---|
| 키워드 | 7단계 기술 분류 14개 중 글이 있는 것. **최근 120일 글 수가 많은 순**, 같으면 전체 글 수 순. 상위 **8개** |
| 매핑 | 기술 분류에 그 기술이 들어 있는 글 (해당 없음 글 포함) |
| 탭 | `# 기술 이름 글 수`. 처음엔 1위가 선택돼 있고, 누르면 아래 목록만 바뀐다 |
| 목록 | 그 기술의 **최신 글 4건** — 썸네일 자리에 **회사 로고**, 회사 · 발행일, 카드 문장 |
| 아래 | "# 기술 글 N건 모두 보기" → 기술 페이지 |

**기술 페이지**

| 자리 | 기준 |
|---|---|
| 머리말 | 기술을 개발을 모르는 사람이 읽는 한 줄로 설명 · 글 수 |
| 이 기술이 바꾼 경험 | 이 기술 글 중 해당 없음이 아닌 글의 대표 경험별 글 수 → 경험 페이지로 (상세 페이지라 남겨 둠) |
| 기술 이름으로 거르기 | 글에 실제로 나온 구체적인 기술 이름 상위 16개 |
| 목록 | 이 기술 글 전체, 최신순 |

## 부록 A — 피그마 원안에서 다시 잡은 것

피그마 「01. 콘텐트 구조화 프로세스 상세」와 「02. 해당 로직으로 실제 구현해본 프로토타이핑」을 출발점으로,
실제 테크 블로그 글(포함 79~80건)에 적용해 보며 바꾼 것을 모은다.

> 원안 확인 범위: 01 섹션 전체(이미지 속 표·코드 포함), 02 섹션은 홈 프로토타입의 상단 ~ "기술이 바꾸고 있는 경험" 첫 카드까지.

### A-1. 원안을 그대로 따른 것

| 항목 | 원안 | 지금 |
|---|---|---|
| 구조화 흐름 | 원문 → FACT → Problem Taxonomy → 사용자 관점 해석 → Experience → Product Pattern → Technology | ① 3~7단계 |
| 부담 7 ↔ 경험 7 | `time_burden` … ↔ `WAIT_LESS` … | ① 4단계. AI 는 부담만 고르고 경험은 코드가 정함 |
| Product Pattern 9개 | 사용자 표현은 8개만 정의 | ① 7단계. `EXPLANATION_LAYER` = "결과의 이유를 함께 설명하는 방식"으로 정함 |
| 홈 그룹핑 순서 | Problem Taxonomy → Experience → Product Pattern → Article, 기술은 1차 기준 아님 | 11-3 경험 페이지 |
| 한 글 = 여러 경험 | 같은 AI Agent 도 여러 경험에 들어갈 수 있음 | ① 6단계 대표 1 + 보조 최대 2 |

### A-2. 분류에서 새로 만들거나 바꾼 것

| 항목 | 원안 | 지금 | 왜 |
|---|---|---|---|
| 해당 없음 | 모든 글이 7개 중 하나 | 사슬이 끊기면 경험 없음 + 글 성격 (① 6-3) | 웰컴키트·워크숍 후기·동료와 밥 한 끼에도 경험이 붙었다 |
| 적합도 | 없음 | STRONG · WEAK · NONE (① 6-2) | 조금 덜어준 글과 분명히 덜어낸 글을 같은 무게로 세면 카드가 흐려진다 |
| 누구의 부담 | 사용자 관점만 | 서비스 사용자 · 사내 운영자 · 개발자 (① 5단계) | 79건 중 66~70건이 사내 운영·개발 이야기였다 |
| 사내 경험 취급 | — | 사용자 경험과 같이 센다, 🛠 태그만 | 결정: 부담의 모양이 같으면 같은 경험. 홈의 "사내 N" 표시는 이 결정으로 없앰 |
| 부담 판단 규칙 | 이름과 예시 1개 | 해결 전 부담으로 고르기, 사내 사례 포함 정의, 직접 처리는 마지막, 걱정은 확인 부담 (① 4단계) | "직접 처리" 쏠림 39% → 10% |
| 경험 사슬 | 사용자 관점 해석 1단계 | ① 누가·어려움 → ② 부담 → ③ 개선 (① 3단계) | 결정 과정: "누가 무엇을 겪었나" → "사람의 고통인가" 분류는 **기술 내부 문제도 Pain point** 라서 폐기 → 3단계 사슬로 확정 |
| 판단 입력 | 원문 | "더 들어가 볼까요?" 칸 (① 2단계) | 원문 표현에 덜 끌려가고, 상세 화면의 칸으로 추적 가능 |
| 코드 규칙 | AI 판단 | 실제 결과 판정, 대표·보조 결정, 직접 처리+WEAK→NONE (① 6단계) | 같은 글이 실행마다 흔들리는 폭을 줄이려고 |
| 단어 사전 | — | 교차 확인만 (① 6-4) | 단어로 매핑하면 "확인"에 더 심하게 끌려간다 |
| 기술 분류 | 11개 (AI 중심) | 14개 — 데이터·실험 플랫폼, 서버·성능 개선, 앱·웹 화면 구조 추가 | AI 가 아닌 글이 많았다 |
| 방식 짧은 이름 | 문장형만 | "대신 실행하기" 등 9개 | 좁은 자리에서 문장이 어색하게 잘렸다 |
| 카드 문구 | 원문 문제 문장·해시태그 | 새로 쓴 카드 문장·문제 제목·문제 요약 (① 8단계) | "지오코딩", "형상관리"가 그대로 노출됐다 |

### A-3. 홈에서 새로 만들거나 바꾼 것
