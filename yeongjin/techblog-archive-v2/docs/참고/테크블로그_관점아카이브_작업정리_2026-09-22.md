## 1. 이 서비스가 하는 일 (한 줄 요약)

국내 테크 기업 블로그 글을 자동으로 모아온 뒤, **"기획자 관점"에서 읽기 쉽게 가공**한다.
단순 아카이빙/요약이 아니라 원문을 **문제 정의 → 가설/기술 → 경험 변화 → 기회**라는 사고 흐름으로 재구성하는 것이 핵심 가치다.

---

## 2. 콘텐츠 파이프라인

```
RSS 수집(13개 회사 블로그)
  → 1차 게이트 판단 (Gemini, 저비용 호출)
     "이 글이 순수 기술 구현 디테일만 다루는가, 아니면 기획/제품 맥락이 있는가?"
     → 기획 관점 없음 → 제외 (exclusionReason 기록, /excluded 페이지에서 투명 공개)
  → 2차 상세 분석 (Gemini, 게이트를 통과한 글만)
     → 아래 3장의 구조화 데이터 생성
  → SQLite 저장 (learning_json 컬럼에 통째로 저장)
```

**왜 2단계로 나눴는가**: 처음엔 한 번의 호출로 게이트 판단 + 상세 분석을 같이 시켰더니, 제외될 글에 대해서도 억지로 상세 데이터를 만들어내려다 응답이 중간에 끊기거나(반복 생성 루프) 필드를 비워두는 문제가 반복됐다. 게이트를 먼저 싸고 저렴하게 분리하니 안정성이 크게 좋아졌다.

## 3. AI가 추출하는 구조화 데이터 (`learning_json`)

| 필드 | 설명 |
|---|---|
| `hook` | 클릭하고 싶어지는 미끼 문장 (결론 스포일러 금지) |
| `tags` | 관점 태그 2~4개 (자유 텍스트) |
| `audience` | 가장 도움될 직무 (PM/기획자/디자이너/데이터분석가/프로덕트오너) |
| `difficulty`, `readingTime` | 난이도, 예상 읽기 시간 |
| `conclusion` | "결론부터 말하면" — 배경 설명이 아니라 판단 기준/결론만 |
| `before` / `after` | 기술 적용 전/후 사용자가 겪는 상황 변화 (Before/After) |
| `experiencePattern` | **고정 7개 값 중 정확히 하나** (아래 4장 참고) — 홈 화면 테마와 100% 동일한 값을 씀 |
| `productPatterns` | 기업에 종속되지 않는 재사용 가능한 패턴명 (예: "Local First Processing") |
| `plannerQuestions` | 자기 서비스에 대입해볼 질문 — **정답/아이디어 제시 금지, 반드시 질문형** |
| `tradeoffs` | `{ benefits[], considerations[] }` — 이 접근의 장점과 함께 고려할 조건 |
| `quickView` | `{ summary, whyItMatters[], keywords[] }` — 3줄 요약 |
| `problem.items[]` | `{ title, description, originalExcerpt }` — 문제 정의, 원문 발췌 포함 |
| `technology[]` | `{ name, simpleExplanation, plannerExplanation, originalExcerpt }` |
| `experienceImpact[]` | `{ technology, capability, uxImpact, description, originalExcerpt }` |
| `discussionQuestions[]` | 찬반이 갈리는 질문 + 선택지 (정답 유도 금지) |

`originalExcerpt`가 붙은 필드는 전부 **"원문에 실제로 등장하는 문장을 한 글자도 바꾸지 않고 그대로 복사"** 하도록 프롬프트에 강제했다 — 이 값들이 바로 본문 하이라이트(5장)의 재료가 된다.

## 4. 홈 화면 — "문제/경험" 중심 큐레이션

기술명이 아니라 **사용자 부담(problem)**에서 시작하도록 설계했다 (참고 문서: `tech_blog_planner_prompt_v3_focus_reading.md`의 7가지 축).

- **어떤 변화가 궁금한가요?** — 고정 7개 테마 카드, 실제 수집 데이터로 카운트됨
  1. 기다리지 않아도 되는 경험
  2. 찾지 않아도 되는 경험
  3. 비교하지 않아도 되는 경험
  4. 입력하지 않아도 되는 경험
  5. 다시 설명하지 않아도 되는 경험
  6. 직접 처리하지 않아도 되는 경험
  7. 확인하지 않아도 되는 경험
- **이런 문제를 어떻게 풀었을까요?** — 회사별 최신 글의 "문제 정의" 헤드라인 카드 (회사 브랜드 컬러)
- **기술이 바꾸고 있는 경험** — `experienceImpact.uxImpact` 를 여러 글에서 모아 집계
- **요즘 기획자가 알아둘 주제** — `technology.name` 을 여러 글에서 모아 집계
- 테마 카드를 누르면 `/search?q=...`로 이동해 관련 글 목록을 보여줌 (검색은 `title/hook/tags/company/learning_json` 전체를 대상으로 함)

## 5. 글 상세 화면 — 원문 중심 읽기 + 관점 하이라이트

**중요한 방향 전환**: 처음엔 "먼저보기→문제이해→기술이해→경험연결→생각확장" 5단계로 원문을 잘게 쪼개 보여주는 스텝퍼 UI였는데, "원문이 너무 잘려 보인다"는 피드백을 받고 **원문 전체를 그대로 보여주고, 그 위에 관점을 주석(annotation)으로 얹는 방식**으로 전면 교체했다.

### 5.1 화면 구성 (위→아래)
1. 헤드라인(`hook`) + AI 3줄 요약(`quickView.summary`)
2. "AI가 원문을 분석해서 정리했어요 · N분" 표시줄
3. **결론부터 말하면** (`conclusion`)
4. **달라진 경험** (`after`, 파란 박스)
5. 회사 카드
6. **"✦ 기획자 관점 보기"** 버튼 → 바텀시트 (5.2)
7. **원문 전체** — 실제 원문 HTML을 그대로 렌더링하되, 관련 문장에 인라인 하이라이트 적용 (5.3)
8. 원문에서 보기 ↗ (외부 링크)

### 5.2 바텀시트 — "기획자 관점 보기" (세로 스택 3섹션)
스와이프 카드 방식이 아니라 **세로로 이어지는 고정 3섹션**:
- **핵심 변화**: BEFORE 박스(회색) → AFTER 박스(연두) → 경험 패턴 태그
- **적용 관점**: "정답이 아니라, 질문이에요" + `plannerQuestions` 불릿
- **적용 조건**: "기대할 수 있는 것"(`tradeoffs.benefits`) / "함께 고려할 점"(`tradeoffs.considerations`)
- 하단에 토론 질문(`discussionQuestions`, 선택지 클릭 가능하지만 정답 판정 없음) + AI 생성 콘텐츠 disclaimer

### 5.3 본문 하이라이트 — 어떤 기준으로 동작하는가 (`src/lib/annotate.ts`)
1. `problem.items`, `technology`, `experienceImpact` 각각의 `originalExcerpt`를 후보로 모음
2. 원문 HTML 안에서 해당 문장을 찾되, **공백 차이**(AI는 공백 정리된 텍스트를 봄)와 **태그 끼어듦**(`<strong>` 등이 문장 중간을 끊는 경우)을 모두 허용하는 정규식으로 매칭
3. 찾으면 실제 원문 텍스트를 색깔 있는 `<mark>`로 감싸고 호버/탭 시 설명 툴팁 표시
   - 🟡 문제 정의 / 🔵 기술 이해 / 🟢 경험 변화
4. 8자 미만 발췌문은 애초에 시도하지 않음
5. 못 찾은 항목은 사라지지 않고 본문 위 **"본문 위치를 정확히 표시하지 못한 관점"** 목록에 별도로 표시 (정보 유실 방지)
6. 같은 문장이 여러 번 나와도 첫 번째 매칭 위치 한 곳만 하이라이트

## 6. 그 외 화면

- **/feed** — 전체 글 최신순 목록 + 회사/태그/직무 필터

| 항목 | 선택 | 이유 |
|---|---|---|
| Frontend | Next.js 16 (App Router, Turbopack) | — |
| DB | **`node:sqlite`** (Node 내장, 파일 기반) | 원래 Prisma를 쓰려 했으나, 설치된 Prisma CLI가 완전히 다른 클라우드 플랫폼 아키텍처(v8)로 바뀌어 있어서, git/docker 없이 바로 도는 경량 대안으로 전환 |

| 인증 | 없음 | 팀 협업(로그인/댓글/알림)까지는 이번 범위에 포함하지 않음 (8장 참고) |
| 원문 콘텐츠 | RSS `content:encoded` 우선, 500자 미만이면 원문 페이지 재요청 | 일부 회사(뱅크샐러드/쏘카/LY) RSS가 티저만 제공하는 문제를 겪고 나서 추가한 안전장치 |

## 10. 운영용 스크립트 (`package.json`)

```bash
npm run dev              # 로컬 서버 실행
npm run collect           # RSS 기반 신규 글 수집 + 분류
npm run add-url -- <URL>  # RSS 없는 블로그 글 1건 수동 추가
npm run check-gemini      # Gemini 키/스키마 정상 동작 확인
npm run backfill-content  # 원문이 비정상적으로 짧게 저장된 글의 본문 재수집
npm run reclassify        # 기존 글 전체를 최신 스키마로 재분류 (스키마 필드 추가될 때마다 실행)
```
