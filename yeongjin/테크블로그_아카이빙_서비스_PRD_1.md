# 테크 블로그 아카이빙 서비스 PRD (Product Requirements Document)

- 문서 버전: v0.1 (Draft)
- 작성일: 2026-07-30
- 작성 대상: 팀 내부 사이드 프로젝트 / 스터디용 서비스
- 문서 상태: 초안 (팀 리뷰 후 확정 필요)

## 1. 개요

### 1.1 배경
네이버, 컬리, 당근마켓, 토스, 우아한형제들, 오늘의집 등 국내 빅테크/스타트업 기업들이 운영하는 기술 블로그에는 실무에 도움이 되는 아키텍처, 조직 문화, 트러블슈팅 사례가 많지만, 흩어져 있는 글을 팀원들이 각자 찾아 읽고 개인적으로만 소비하는 경우가 많습니다. 좋은 글을 발견해도 팀 내에 공유되지 않거나, 공유되더라도 링크만 던져지고 논의가 이어지지 않아 휘발되는 문제가 있습니다.

### 1.2 목적
팀원들이 함께 기술 블로그 글을 **모으고(아카이빙), 읽고, 이해하고, 토론**할 수 있는 소규모 팀 전용 아카이빙 서비스를 만든다. 특히 어려운 글을 혼자 읽다 포기하지 않도록 **AI 요약/설명 기능**을 결합해 진입장벽을 낮춘다.

### 1.3 핵심 가치 제안 (Value Proposition)
- **모은다**: 흩어진 기술 블로그 글을 한 곳에 아카이빙
- **함께 읽는다**: 팀원의 댓글과 반응을 통해 혼자 읽는 글이 아니게 만든다
- **쉽게 읽는다**: AI 요약과 형광펜 기반 AI 설명으로 어려운 글의 진입장벽을 낮춘다
- **다시 찾는다**: 북마크와 마이페이지로 나중에 다시 꺼내볼 수 있게 한다

### 1.4 타겟 사용자
- 1차 타겟: 함께 스터디하거나 기술 트렌드를 공유하고 싶은 소규모 팀(사내 스터디 그룹, 소수 팀 단위, 10~30명 내외)
- 사용자는 모두 로그인된 팀 구성원이며, 외부 공개 서비스가 아닌 **팀 전용(클로즈드) 서비스**를 우선 가정

### 1.5 페르소나 (예시)
| 페르소나 | 특징 | 니즈 |
|---|---|---|
| 주니어 개발자 A | 좋은 아티클을 발견하면 저장은 하지만 끝까지 안 읽고 방치 | AI 요약으로 핵심만 빠르게 파악, 어려운 용어는 형광펜으로 바로 이해 |
| 시니어 개발자 B | 좋은 글을 팀에 공유하고 토론하고 싶음 | 글에 댓글/의견을 남기고 팀원 반응을 확인, 깊이 논의하고 싶은 글은 토론을 신청해 팀원을 모음 |
| PM/기획자 C | 기술 용어가 낯설어 완독이 어려움 | AI가 어려운 부분만 쉽게 풀어서 설명해주길 원함 |

## 2. 정보 구조 (IA) — 하단 탭바 구성

앱은 하단 탭바 4개 탭을 기본 골격으로 한다.

```
┌─────────────────────────────────────────────────┐
│                                                 │
│                 (콘텐츠 영역)                     │
│                                                 │
├─────────────────────────────────────────────────┤
│  🧭 탐색   ✨ 큐레이션   🔍 검색   👤 마이         │
└─────────────────────────────────────────────────┘
```

| 탭 | 역할 |
|---|---|
| **탐색** | **자동 수집 + 팀원 등록 글이 함께 모이는 최신순 피드.** 네이버/컬리/당근마켓/토스/우아한형제들/오늘의집 등 빅테크·스타트업 기술 블로그의 새 글을 시스템이 자동으로 수집해 뿌려주고, 팀원이 직접 등록한 글도 함께 노출한다. "우리 팀이 함께 쌓아가는 아카이브"이자 "업계 전체의 최신 글을 놓치지 않는 창구" 역할. 회사별/카테고리별 필터 제공 |
| **큐레이션** | **사용자가 선택한 관심 키워드 기반 추천 피드.** 최신순이 아니라 "나에게 맞는 글"을 우선 보여주는 영역으로, 탭 진입 시 상단에 노출되는 질문형 키워드 칩(예: "A/B 테스트, 어떻게 설계하지?")을 선택하면 해당 카테고리의 글이 우선 노출됨(3.6 참조) |
| **검색** | 키워드/태그/회사/작성자 기반 검색, 최근 검색어 |
| **마이** | 내 프로필, 북마크한 글, 내가 올린 글, 내가 쓴 댓글, 관심 키워드 설정, 설정 |

> 기존 "홈" 탭 하나가 담당하던 "최신 피드 + 추천"의 역할을 **탐색(최신·전체)**과 **큐레이션(개인화 추천)**으로 분리한 구조다.

## 3. 핵심 기능 명세

### 3.1 콘텐츠 소싱 구조 — 자동 수집(크롤링) + 팀원 수동 등록 (신규)

**목표**: 팀원이 일일이 링크를 등록하지 않아도 "탐색" 탭에 업계 주요 기술 블로그의 새 글이 자동으로 쌓이게 하고, 팀원 등록 글과 자연스럽게 함께 노출한다.

- **자동 수집 대상(초기 목록, 확장 가능)**: 네이버(D2) / 컬리 / 당근마켓 / 토스 / 우아한형제들 / 오늘의집 — 이후 팀 요청에 따라 대상 회사 추가
- **수집 방식**: 각 블로그가 제공하는 **RSS/Atom 피드를 우선 사용**해 신규 글 메타데이터(제목/링크/발행일/저자 등)를 주기적으로 폴링. RSS 미제공 사이트는 오픈그래프 파싱으로 대체하되, robots.txt·이용약관 확인 후 허용 범위 내에서만 수집(6.3 참조)
- **수집 주기 (확정)**: **실시간에 가까운 주기**로 폴링(예: 5~15분 간격) — 사이트별 서버 부담과 이용약관을 고려해 과도한 요청은 지양하고, 필요 시 사이트별로 폴링 간격을 조정(6.3 참조)
- **글 출처 구분(데이터 모델에 반영)**: 각 글은 `출처 타입` 값(`자동 수집` / `팀원 등록`)을 가진다
  - **자동 수집 글**: 등록자가 없으므로 처음에는 **AI 요약만** 노출된 채로 탐색 피드에 등록. **팀원 누구나 "등록자 노트 추가하기"로 핵심 인사이트/정리할 기술 지식/바로 적용할 점(3.4)을 나중에 작성할 수 있다(확정)** — 이 경우 노트를 작성한 팀원이 "노트 작성자"로 표시되며, 여러 팀원이 각자 노트를 추가하면 작성자·작성일이 표시된 노트 카드가 함께 쌓여 노출됨
  - **팀원 등록 글**: 기존과 동일하게 3.4의 등록 노트(권장, 건너뛰기 가능) + AI 요약 함께 노출
- **중복 방지**: 자동 수집 글과 동일한 원문 URL을 팀원이 나중에 수동 등록하려는 경우, 이미 존재하는 글로 안내 후 "등록자 노트만 추가 작성"하는 흐름으로 유도(완전히 새 글로 중복 생성하지 않음)

### 3.2 아카이빙 구조 (요구사항 #1)

**목표**: 여러 회사의 기술 블로그 글을 구조화된 형태로 저장하고 분류한다.

- **데이터 모델(초안)**
  - 글(Post): 제목, 원문 URL, 출처 회사(네이버/컬리/당근마켓/토스/우아한형제들/오늘의집 등 태그), 저자, 발행일, 썸네일, **본문 전체(자체 스토리지에 저장, 서비스 내 렌더링용)**, **출처 타입(자동 수집/팀원 등록)**, 등록자(팀원 등록인 경우), 등록일, 태그(예: 백엔드/프론트엔드/데이터/조직문화 등)
  - **카테고리(필수, 단일 선택)**: 예) 백엔드 / 프론트엔드 / 데이터·AI / 인프라·DevOps / 조직문화·프로세스 / 기타 — 회사 태그와는 별개로 "어떤 기술 영역의 글인지"를 분류하는 필수 값. 자동 수집 글은 AI가 초기 분류를 제안하고, 팀원이 확인·수정 가능
  - **등록자 작성 노트(팀원 등록 글에 한해 권장, 3종 세트, 건너뛰기 허용)**: 아래 3.4 참조 — 등록자가 직접 작성하는 `핵심 인사이트` / `정리할 기술 지식` / `바로 적용할 점`
  - 회사(Company/Source): 이름, 로고, 블로그 홈 URL, RSS 피드 URL(자동 수집용)
  - 컬렉션(선택 기능): 팀원이 특정 주제로 글을 묶어 폴더처럼 관리 (예: "MSA 전환기 모음")
  - **사용자-글 관계(User-Post, 신규)**: 사용자별로 글마다 갖는 상태값 — 북마크 여부, **읽기 상태**(읽기 전 / 읽는 중 / 다 읽음), 마지막 열람일, 개인 메모 존재 여부 — 3.9, 3.10 참조
- **분류 방식**
  - 회사별 아카이브 (네이버 / 컬리 / 당근마켓 / 토스 / 우아한형제들 / 오늘의집 / 기타 — 자동 수집 시 자동 매칭, 수동 등록 시 자동 추출 또는 수동 태깅)
  - 주제 태그 (자유 태그 + 추천 태그)
- **원문 보존 정책 (확정)**
  - **본문 전체를 자체 스토리지에 저장**해 서비스 내에서 직접 렌더링한다 — 형광펜/하이라이트(3.8), AI 쉬운 설명 등 본문 위에서 동작하는 기능을 서비스 내에서 구현하려면 원문 텍스트가 자체 서버에 있어야 하기 때문
  - 저장 시점의 "아카이빙 시점 스냅샷"도 함께 포함 — 원문이 나중에 삭제/수정되어도 팀 내부에서는 저장된 시점의 본문을 계속 볼 수 있음
  - 팀 전용 클로즈드 서비스 내부에서만 노출(비로그인/외부 공개·검색엔진 노출 없음)하고, 본문 상단에 원저작자·출처·[원문 바로 읽기] 링크를 항상 함께 노출해 재배포가 아닌 "팀 내부 열람용 보관"임을 명확히 함
  - 각 블로그의 `robots.txt`·이용약관 확인은 계속 필요(6.3 참조) — 수집이 명시적으로 금지된 사이트는 본문 저장 대신 링크+요약만 제공하는 예외 처리

### 3.3 팀원 간 댓글/소통 구조 (요구사항 #2)

- 글 하나당 **쓰레드형 댓글**(대댓글 1단계 이상 지원)
- 댓글 작성자, 작성시간, 수정/삭제(본인 댓글만) 지원
- 팀원 멘션(@이름) 지원 → 알림 발송
- 이모지 리액션(👍 😮 💡 등) 지원해 가볍게 반응 가능하게 함
- (선택) 댓글 정렬: 최신순/좋아요순

### 3.4 글 등록/삭제 기능 (요구사항 #3)

**목표**: 단순히 링크만 던지고 끝나는 아카이빙이 되지 않도록, 등록 시 **등록 노트 작성을 권장하는 입력 구조**를 두어 등록자 스스로 한 번 더 생각하고 정리하게 만든다. 다만 참여 부담을 낮추기 위해 등록 노트 작성은 건너뛸 수 있다(확정). 이는 팀원들이 "왜 이 글을 공유했는지, 뭘 배웠는지"를 함께 볼 수 있게 하는 장치이기도 하다.

- **등록 항목**

  | 순서 | 항목 | 성격 | 설명 |
  |---|---|---|---|
  | 1 | **카테고리 선택** | 필수·선택형 | 백엔드/프론트엔드/데이터·AI/인프라·DevOps/조직문화 등 중 택1 |
  | 2 | **원문 URL** | 필수·입력형 | URL 입력 시 오픈그래프 기반으로 제목/썸네일/발행일/회사 자동 추출 시도, 실패 시 수동 입력 |
  | 3 | **핵심 인사이트** | 권장·서술형(건너뛰기 가능) | "이 글에서 얻은 핵심 인사이트는?" — 자유 서술 (최소 글자 수 가이드, 예: 20자 이상 권장) |
  | 4 | **정리해야 할 기술 지식** | 권장·서술형(건너뛰기 가능) | "이 글을 이해하기 위해/더 알아보기 위해 정리가 필요한 개념·용어는?" — 이후 다른 팀원이 형광펜으로 `용어·개념 정리 필요`(3.8)로 표시한 하이라이트들이 이 항목 아래에 함께 모여 노출됨 |
  | 5 | **내가 바로 적용할 수 있는 점** | 권장·서술형(건너뛰기 가능) | "우리 팀/내 업무에 바로 적용해볼 수 있는 부분은?" — 실무 연결을 명시적으로 요구 |

  - 등록 흐름: `카테고리 선택` → `원문 URL 입력(메타데이터 자동 추출)` → `등록 노트 작성 또는 건너뛰기` → `미리보기 확인` → `등록 완료`
  - 3~5번 항목은 등록 화면에서 하나의 "등록 노트" 폼으로 묶어서 보여주고, 상단에 "건너뛰기" 버튼을 함께 제공. 항목별 placeholder(예시 문구)를 제공해 작성 부담을 낮춤
  - **필수 항목(카테고리, 원문 URL)만 채워지면 등록 가능(확정)** — 등록 노트를 건너뛴 글은 상세 화면에 "등록자의 노트" 박스 없이 AI 요약만 노출되며, 이후 등록자 본인 또는 다른 팀원이 "노트 추가하기"로 채울 수 있다(자동 수집 글의 노트 추가 방식과 동일, 3.1 참조)
  - (선택) 임시저장 기능 — 바로 다 못 쓰는 경우 초안으로 저장 후 나중에 이어 작성
  - 등록 노트를 작성한 경우, 이 3가지 서술형 항목은 글 상세 화면 상단에 **"등록자의 노트"**로 AI 요약과 나란히 노출되어, 다른 팀원이 AI 요약뿐 아니라 등록자의 관점도 함께 볼 수 있게 함
  - 중복 URL 등록 방지(이미 등록된 글이면 안내 후 기존 글로 이동)

- **삭제 (확정: 소프트 삭제)**
  - 기본 원칙: **등록자 본인만 삭제 가능** + 운영자(관리자) 권한으로 부적절 게시물 삭제 가능
  - 자동 수집 글은 등록자가 없으므로 팀원 삭제 불가 — **관리자만 숨김/삭제 가능** (예: 수집 오류, 중복, 팀과 무관한 글)
  - **삭제 요청 시 즉시 영구 삭제하지 않고, 소프트 삭제(숨김) 처리 후 일정 유예기간이 지나면 영구 삭제한다** — 유예기간 동안은 목록/검색/큐레이션에서 숨겨지되 데이터는 보존되어 실수로 삭제한 경우 복구 가능. 정확한 유예기간(예: 7일/30일)은 오픈 이슈로 남김(9장 참조)
  - 삭제 시 확인 모달("유예기간 내 복구 가능" 안내 포함), 댓글이 달린 글 삭제 시 경고 문구 추가

### 3.5 마이 페이지 — "내 라이브러리" (요구사항 #4, #5)

마이 탭은 "내 라이브러리"라는 이름으로, 개인이 쌓아온 아카이빙 활동을 한 곳에서 확인하는 공간으로 구성한다.

- **프로필 요약** (이름, 프로필 이미지, 가입일)
- **활동 통계 카드(3종, 상단 고정)**: `저장한 아티클`(북마크 수) / `읽은 아티클`(읽기 상태=다 읽음 수, 3.9 참조) / `작성한 메모`(개인 메모 수, 3.10 참조)
- **이어서 읽을 아티클 (신규)**: 저장했지만 아직 다 읽지 않은 글(읽기 상태 ≠ 다 읽음)을 카드형으로 상단 노출 — 카드 구성은 5장 카드 공통 규격 참조(썸네일+원문 바로 읽기 버튼, 회사/발행일, 제목, 요약 한 줄, 태그, 읽기 상태 배지)
- **저장한 아티클 목록**: 북마크한 전체 글(최근 저장순, 회사/태그/읽기 상태 필터 가능), 카드 UI는 위와 동일
- **내가 올린 글 목록** (등록순, 각 글의 조회수·댓글수·북마크 수 확인 가능)
- **내가 쓴 댓글 모아보기** (어떤 글에, 언제, 무슨 댓글을 남겼는지)
- **작성한 메모 모아보기 (신규)**: 3.10 참조 — 어떤 글에 남긴 메모인지 목록으로 확인
- (선택) 내가 형광펜 표시한 하이라이트 모음 — 3.8 기능과 연계
- **관심 키워드 설정**: "큐레이션" 탭에서 선택한 관심 키워드 칩을 마이 탭에서도 확인·수정 가능(주 진입점은 큐레이션 탭, 3.6 참조). 온보딩 시 별도로 강제 설정하지 않음(확정)
- 설정: 알림 설정, 로그아웃, 프로필 수정

### 3.6 큐레이션 로직 (요구사항 #신규 — 큐레이션 탭)

**목표**: "탐색" 탭의 최신순 전체 피드와 달리, 팀원 개인이 관심 있는 주제에 맞는 글을 우선적으로 보여줘 정보 과부하를 줄인다.

- **온보딩 강제 없음(확정)**: 가입 시 관심 키워드 설정을 요구하지 않는다. 대신 **큐레이션 탭에 진입하면 관심 키워드 칩 UI가 상단에 항상 노출**되고, 팀원이 원하는 칩을 선택하면 그 즉시 해당 키워드 위주로 피드가 구성된다
- **키워드 칩 예시(확정 방향)**: 카테고리성 단어(백엔드, MSA 등)보다 실제 관심사에 가까운 **질문형/문장형 키워드**를 제공 — 예) `A/B 테스트, 어떻게 설계하지?`, `데이터로 의사결정하는 법`, `사용자 피드백 어떻게 모으지?`, `사용성 테스트 어떻게 하지?` 등. 칩은 팀 내 인기 카테고리/태그를 바탕으로 구성하며 실제 데이터가 쌓이면 주기적으로 갱신
- **다중 선택**: 여러 칩을 동시에 선택 가능하며, 선택한 칩은 사용자의 "관심 키워드"로 저장되어 마이 탭(3.5)에서도 동일하게 확인·수정 가능
- **매칭 방식(MVP, 확정)**: 각 키워드 칩은 특정 **카테고리(3.2)** 에 매핑되어 있어, 선택한 칩의 카테고리와 일치하는 글을 우선 노출하는 **카테고리 기준 매칭**을 기본으로 한다
- **정확도가 낮을 때의 폴백(확정)**: 매칭된 글이 부족하거나 카테고리 매칭만으로 피드가 빈약할 경우, **이번 주 팀 내 조회수가 높은 인기 글**로 나머지 피드를 채워 노출한다
- **매칭 방식(고도화, v1.1+)**: 단순 카테고리/태그 매칭을 넘어 AI 임베딩 기반 의미 유사도로 추천 정교화 고려
- **자동 수집 글도 큐레이션 대상에 포함**: 등록자 노트가 없는 자동 수집 글이라도 AI 요약·태그가 있으면 큐레이션 매칭 대상이 됨

### 3.7 AI 요약 기능 (요구사항 #6)

**목표**: 글이 등록(또는 자동 수집)되면 AI가 본문을 분석해 짧은 요약을 자동 생성, 팀원이 완독 전에 핵심을 빠르게 파악하게 한다.

- **트리거 시점**: 팀원 등록 직후 또는 자동 수집 직후 서버에서 비동기로 요약 생성 (등록자를 기다리게 하지 않음, 완료되면 "요약 준비완료" 표시). 자동 수집 글은 수집 배치 직후 큐에 쌓여 순차 처리
- **요약 형태(제안)**
  - 3~5줄 핵심 요약
  - 핵심 키워드/태그 자동 추천 (등록자가 승인/수정)
  - "이런 분께 추천" 한 줄 코멘트(선택 기능)
- **재생성**: 팀원이 "다시 요약하기" 요청 가능(잘못된 요약 보완용, 단 남용 방지를 위한 rate limit 필요)

### 3.8 형광펜 + AI 쉬운 설명 + 북마크 + 댓글 (요구사항 #7, Notion 인라인 댓글 참고)

**목표**: 본문 내 어렵거나 낯선 부분을 드래그하면 AI가 그 부분만 쉽게 풀어 설명해주고, 그 지점에 댓글/북마크를 남길 수 있게 한다.

- **동작 흐름**
  1. 사용자가 본문에서 텍스트 드래그(선택)
  2. 플로팅 툴바 노출: `형광펜 표시` / `AI로 쉽게 설명` / `이 부분에 댓글 달기` / `이 부분 메모 남기기` / `이 부분 북마크`
  3. **형광펜 (확정)**: 선택 영역에 하이라이트 색상 적용 — **팀 전체 공개가 기본값**이며, 토글(ON/OFF)로 켜면 해당 하이라이트를 나에게만 보이는 개인 전용으로 전환 가능
  4. **AI 쉬운 설명**: 선택한 문장/용어를 AI가 쉬운 말로 풀어쓰거나 필요 시 번역(영문 인용구 등) → 팝오버/사이드패널에 표시
  5. **인라인 댓글/메모**: 특정 하이라이트 구간에 댓글(팀 공개, 3.3) 또는 메모(개인 비공개, 3.10)를 연결 (Notion처럼 본문 옆 여백에 마커 표시, 클릭 시 해당 구간으로 스크롤)
  6. **부분 북마크**: 글 전체 북마크와 별개로, 특정 문단/하이라이트만 콕 집어 북마크 가능 → 마이페이지에서 "하이라이트 모음"으로 조회
- **인라인 댓글/메모 작성 시 유형 구분 (확정: 선택 사항)**: `이 부분에 댓글 달기` 또는 `이 부분 메모 남기기`를 선택하면, **원하는 경우에만** 유형을 지정할 수 있다 — 불러온 원문 글에 필요할 때마다 자유롭게 남기는 개인 도구라는 성격상, 매번 유형 선택을 강제하지 않고 건너뛸 수 있게 함
  - **내 의견**: 이 문장/개념에 대한 생각, 질문, 논의하고 싶은 포인트를 자유롭게 남기는 용도
  - **용어·개념 정리 필요**: 기술 용어나 개념이 어려워서 별도로 찾아보거나 정리가 필요하다고 표시하는 용도
  - 유형을 지정하면 하이라이트 마커의 색상/아이콘을 다르게 표시(예: 의견=말풍선 아이콘, 정리 필요=물음표 아이콘)해 본문 옆 여백만 훑어봐도 "의견이 달린 곳"과 "다들 어려워하는 곳"을 구분할 수 있게 함. 유형을 지정하지 않으면 기본 마커로 노출
  - **정리 필요**로 표시된 하이라이트는 3.4의 "정리해야 할 기술 지식" 항목과 자동 연결되어, 글 상세에서 등록자 노트 + 팀원들이 표시한 정리 필요 구간을 한눈에 모아볼 수 있음
  - 이 유형 구분은 팀 공개 댓글(3.3)과 개인 메모(3.10) 모두에 동일하게 적용
- **UI 참고 포인트(노션 스타일)**
  - 본문 옆 여백에 댓글/메모 아이콘·마커로 존재를 표시하고, 스크롤 위치와 연동
  - 하이라이트 색상으로 "내 형광펜"과 "AI가 설명해준 부분"을 구분, 마커 아이콘으로 "의견"과 "정리 필요"를 구분

### 3.9 읽기 상태 & 이어서 읽기 (신규 — 마이 라이브러리)

**목표**: 저장만 해두고 방치되는 글을 줄이기 위해, 각 글의 "읽음 여부"를 자동으로 추적하고 아직 다 읽지 않은 글을 마이 탭 상단에서 바로 이어볼 수 있게 한다.

- **읽기 상태(사용자별·글별)**: `읽기 전` → `읽는 중` → `다 읽음` 3단계
  - `읽기 전` → `읽는 중`: 글 상세 화면에 진입하는 순간 자동 전환
  - `읽는 중` → `다 읽음`: 본문 스크롤이 일정 비율(예: 90% 이상) 도달 시 자동 전환. 팀원이 "읽음으로 표시" 버튼으로 수동 전환도 가능
  - 정밀한 스크롤 위치(%) 저장은 MVP 이후 "정확한 위치로 이어보기" 기능으로 확장(8장 v1.1+ 항목 참조)
- **이어서 읽을 아티클(마이 탭 상단 노출)**: 북마크(저장)한 글 중 읽기 상태가 `다 읽음`이 아닌 글을 최근 저장·열람순으로 노출
- **활동 통계 반영**: 마이 탭 상단 통계 카드에 `저장한 아티클`(북마크 수) / `읽은 아티클`(읽기 상태 = 다 읽음 수) / `작성한 메모`(3.10) 3종을 카드형으로 노출

### 3.10 개인 메모 (신규 — 마이 라이브러리)

**목표**: 팀 전체에 공개되는 "댓글"과 별개로, 나만 보는 개인용 정리 메모를 남길 수 있게 한다.

- **작성 위치**: 글 상세 화면에서 "메모 작성" 진입 — 글 전체 단위 메모가 기본이며, 형광펜으로 하이라이트한 특정 구간에 메모를 남기는 것도 가능(3.8 하이라이트와 연계). 하이라이트 구간 메모는 3.8과 동일하게 `내 의견` / `용어·개념 정리 필요` 유형을 선택해 작성
- **공개 범위 (확정)**: 기본값은 **비공개**(작성자 본인만 열람) — 댓글(팀 공개, 토론 목적)·등록자 노트(팀 공개, 3.4)와 구분되는 개인 아카이빙 도구. 메모별로 **"팀에 공개" 토글(ON/OFF)**을 제공해, 작성자가 원할 때만 특정 메모를 팀 전체에 공개로 전환할 수 있다(공개로 전환된 메모는 "메모" 라벨을 유지한 채 팀원에게도 노출됨)
- **마이 탭 노출**: "작성한 메모" 탭에서 모아보기 — 어떤 글에 언제 어떤 메모를 남겼는지 목록으로 확인, 클릭 시 글 상세로 이동

### 3.11 토론 신청 (신규)

**목표**: 글을 읽다가 "이건 팀원들과 제대로 이야기해보고 싶다"는 생각이 들 때, 가벼운 댓글(3.3)과는 별개로 **토론을 신청**하고 관심 있는 팀원을 모아 논의를 이어갈 수 있게 한다. 찬성/반대 같은 의견 표시가 아니라, "함께 논의할 자리를 만드는" 것이 목적이다.

- **진입점**: 글 상세 화면에 **[댓글] / [토론]** 탭을 분리해 배치. "토론" 탭에는 해당 글에 걸린 토론 신청 목록이 노출되고, 상단에 **"토론 신청하기"** 버튼 제공
- **토론 신청 항목**:
  - 토론 주제/신청 이유(필수, 서술형) — "이 글의 어떤 부분에 대해 왜 이야기하고 싶은지" 간단히 작성
  - (선택) 특정 하이라이트 구간을 지정해 신청 가능 — 3.8 형광펜 구간과 연계
- **댓글 → 토론 전환 유도 (확정)**: 하나의 댓글 스레드에 답글이 일정 개수 이상(예: 10개 이상) 쌓이면, "이 주제로 토론을 열어볼까요?"라는 플로팅 버튼을 자동으로 노출해 토론 신청 화면으로 자연스럽게 유도한다. 댓글과 토론은 여전히 독립된 흐름이며, 이 유도는 제안일 뿐 강제 전환은 아님
- **참여 흐름**:
  1. 팀원이 "토론 신청하기"로 주제 작성 → 신청 완료
  2. **팀 전체에 브로드캐스트 알림**을 발송(3.3 멘션 알림과 동일한 알림 체계 재사용) — 관심 키워드/카테고리가 맞는 팀원에게 우선 알리는 방식은 MVP 이후 고도화 항목
  3. 관심 있는 팀원은 **"참여하기"** 버튼으로 참여 의사 표명 → 참여자 목록에 이름이 추가됨. **참여 인원 제한은 두지 않으며, 참여 후 언제든 "참여 취소"로 중도 이탈 가능(확정)**
  4. 참여자들은 해당 토론 전용 스레드(댓글과 별도 스레드)에서 의견을 주고받음
- **상태 관리 (확정)**: `모집 중` → `진행 중`(참여자 1명 이상 생기면 자동 전환) → `종료`(**토론을 개설한 신청자만 종료 처리 가능**, 활동 없음에 따른 자동 종료는 두지 않음)
- **MVP 범위**: 비동기 텍스트 스레드 기반 토론까지만 지원. 특정 시간에 모이는 오프라인/온라인 미팅 일정 잡기(캘린더 연동)는 MVP 이후 확장
- **마이 탭 연계**: "내가 신청한 토론" / "내가 참여 중인 토론"을 마이 라이브러리에서 모아보는 기능은 MVP 이후 고려

## 4. 대표 사용자 플로우 (User Flow)

### 4.1 자동 수집 플로우 (시스템, 신규)
```
[스케줄러가 실시간에 가까운 주기(5~15분)로 반복 실행]
  → 등록된 회사(네이버/컬리/당근마켓/토스/우아한형제들/오늘의집 등) RSS 피드 폴링
  → 신규 글 감지 → 원문 URL 중복 확인(이미 수집/등록된 글이면 스킵)
  → 메타데이터 저장(제목/썸네일/회사/발행일/저자), 출처 타입 = 자동 수집
  → (비동기) AI 요약·카테고리·키워드 생성
  → "탐색" 탭 최신 피드에 노출, 큐레이션 매칭 대상에도 포함
```

### 4.2 글 등록 플로우 (팀원 수동 등록)
```
[탐색 또는 마이] → [+ 글 등록] 버튼
  → 카테고리 선택 (필수)
  → 원문 URL 입력 → 메타데이터 자동 추출 (제목/썸네일/회사/발행일)
     → 이미 자동 수집된 글이면 기존 글로 안내 후 "등록자 노트만 추가 작성"으로 유도
  → 태그 확인·수정 (없으면 수동 입력)
  → "등록 노트" 작성 또는 건너뛰기 (권장이지만 필수 아님)
      - 핵심 인사이트
      - 정리해야 할 기술 지식
      - 내가 바로 적용할 수 있는 점
  → 미리보기 확인
  → 등록 완료 (카테고리·원문 URL만 필수, 등록 노트는 나중에 추가 가능)
  → (비동기) AI 요약 생성 → 요약 준비 완료 알림
  → 글 상세 화면에 "등록자의 노트"(3가지 서술) + AI 요약이 함께 노출
```

### 4.3 큐레이션 확인 플로우 (신규)
```
[큐레이션 탭] 진입 (온보딩에서 별도로 설정을 강제하지 않음)
  → 상단에 노출된 관심 키워드 칩 목록에서 원하는 칩 선택(다중 선택 가능)
  → 선택한 칩(카테고리) 기준으로 매칭된 글이 우선 노출, 매칭 결과가 부족하면 이번 주 인기 글로 보충
  → 글 선택 → 글 상세로 이동
  → (마이 탭에서도 동일한 관심 키워드를 확인·수정 가능)
```

### 4.4 글 읽기 → 어려운 부분 이해 플로우
```
[탐색 또는 큐레이션 피드에서 글 선택] → [글 상세 화면]
  → AI 요약 먼저 확인 (등록자 노트가 있으면 함께 확인)
  → 본문 읽던 중 어려운 문장 드래그
  → "AI로 쉽게 설명" 탭 → 팝오버로 풀이 확인
  → 필요 시 그 구간 형광펜 표시 + 북마크
  → 그 구간에 댓글/메모 남기기 선택 → 유형 선택(내 의견 / 용어·개념 정리 필요) → 내용 작성
      - "내 의견"으로 남기면 팀원이 확인하고 답변/토론 가능
      - "정리 필요"로 남기면 등록자 노트의 "정리해야 할 기술 지식" 항목에 함께 모여 노출
```

### 4.5 토론 신청 플로우 (신규)
```
[글 상세 화면] → [토론] 탭 선택
  → "토론 신청하기" → 토론 주제/신청 이유 작성(필수, 특정 하이라이트 구간 지정 선택 가능)
  → 신청 완료 → 팀 전체에 알림 발송
  → 다른 팀원이 [토론] 탭에서 신청 목록 확인 → "참여하기"로 참여 의사 표명
  → 참여자들과 토론 전용 스레드에서 의견 교환 (상태: 모집 중 → 진행 중)
  → (선택) 신청자가 "토론 종료" 처리
```

### 4.6 마이페이지("내 라이브러리") 확인 플로우
```
[마이 탭] → 활동 통계 카드(저장/읽은/메모) 확인
  → "이어서 읽을 아티클"에서 다 읽지 않은 글 바로 선택 → 글 상세로 이동(이어서 읽기)
  → 저장한 아티클 / 내가 올린 글 / 내 댓글 / 작성한 메모 / 관심 키워드 설정 탭 전환
  → 목록에서 카드 선택 → 글 상세로 이동, 또는 카드의 [원문 바로 읽기] 버튼으로 원문 바로 이동
```

## 5. 화면 구성 (초안)

### 5.0 아티클 카드 공통 규격 (신규)

탐색/큐레이션/검색 결과/마이 라이브러리(이어서 읽을 아티클·저장한 아티클) 등 목록 형태로 글이 노출되는 모든 화면은 아래 카드 UI를 공통으로 사용한다.

- **썸네일 영역**: 회사 로고 배지(좌상단) + 대표 이미지/일러스트 위에 **[원문 바로 읽기] 버튼을 오버레이로 배치** — 상세 화면에 들어가지 않고도 바로 원문 URL로 이동 가능
- **본문 영역**: 회사명 · 발행일, 제목, 한 줄 요약(AI 요약 첫 줄 또는 등록자 노트 요약), 태그 칩, 하단에 상태 배지(예: 읽기 전 / 읽는 중 / 다 읽음) 및 북마크·댓글 수
- 카드를 탭하면 글 상세로 이동, 썸네일 위 [원문 바로 읽기] 버튼을 탭하면 상세를 거치지 않고 원문으로 바로 이동 — **인앱 브라우저로 여는 것을 기본값**으로 하며(확정), 플랫폼(iOS/Android/웹)별 세부 동작은 추가 확인 필요(오픈 이슈 참조)

| 화면 | 주요 구성 요소 |
|---|---|
| 탐색 | **자동 수집 글 + 팀원 등록 글이 함께 모이는 최신순 피드.** 상단 카테고리/회사 필터 칩(전체/백엔드/프론트엔드/…, 네이버/컬리/당근마켓/토스/우아한형제들/오늘의집…), 5.0 공통 카드 UI로 구성된 피드(등록자 또는 "자동 수집" 배지 포함) |
| 큐레이션 | **관심 키워드 기반 추천 피드.** 상단에 질문형 관심 키워드 칩 목록을 상시 노출(예: "A/B 테스트, 어떻게 설계하지?" 등, 다중 선택 가능) — 칩 선택 즉시 해당 카테고리 위주로 피드 재구성, 매칭 결과가 부족하면 이번 주 인기 글로 보충. 매칭된 글은 5.0 공통 카드 UI로 노출 |
| 검색 | 검색창, 최근 검색어, 인기 태그, 검색 결과 리스트(5.0 공통 카드 UI) |
| 글 상세 | 제목/출처/등록자(또는 "자동 수집" 배지), **등록자의 노트 박스**(팀원 등록 글에 한해 핵심 인사이트 / 정리할 기술 지식 / 바로 적용할 점), AI 요약 박스, [원문 바로 읽기] 버튼, 본문(드래그 시 툴바 노출), 우측 여백 댓글 마커, "메모 작성" 진입 버튼, 하단 **[댓글] / [토론] 탭**(댓글: 기존 전체 댓글 스레드, 토론: 토론 신청 목록 + "토론 신청하기" 버튼) |
| 글 등록 | 카테고리 선택(필수) → URL 입력(필수, 미리보기 카드, 이미 자동 수집된 글이면 기존 글로 안내) → 태그/회사 확인 → **등록 노트 작성(핵심 인사이트/정리할 지식/적용할 점, 권장이지만 건너뛰기 가능)** → 등록 버튼(카테고리·URL만 채워지면 활성화) |
| 마이 (내 라이브러리) | 프로필 요약, **활동 통계 카드 3종**(저장한 아티클/읽은 아티클/작성한 메모), **이어서 읽을 아티클** 섹션(5.0 공통 카드 UI), **저장한 아티클** 섹션(5.0 공통 카드 UI), 탭(내가 올린 글 / 내 댓글 / 작성한 메모 / 하이라이트), **관심 키워드 설정**, 설정 진입 |

## 6. 기술 스택 및 AI 연동 제안

### 6.1 전체 스택 방향 (제안, 팀 상황에 맞게 조정 가능)
- **Frontend**: **웹 우선 출시(확정)** — Next.js로 반응형 웹 서비스를 먼저 구축. 이후 앱이 필요해지면 React Native 등 크로스플랫폼으로 확장 고려
- **Backend**: Node.js(NestJS) 또는 Python(FastAPI) — 메타데이터 크롤링·AI 연동이 많으므로 Python도 좋은 선택지
- **DB**: PostgreSQL (관계형 데이터: 글/댓글/북마크/하이라이트 구조에 적합)
- **메타데이터 추출**: URL의 Open Graph 태그 파싱 (제목/썸네일/설명 자동 추출), 실패 시 수동 입력 폴백
- **자동 수집(크롤링) 배치**: 네이버/컬리/당근마켓/토스/우아한형제들/오늘의집 등 대상 회사의 RSS/Atom 피드를 주기적으로 폴링하는 스케줄러(예: 서버 내 cron, 또는 서버리스 스케줄 함수)로 구현. 신규 글 감지 시 메타데이터 저장 → AI 요약 큐에 적재
- **인증**: 팀 전용 서비스이므로 초대 코드 기반 가입 + 이메일/소셜 로그인

### 6.2 무료 LLM 기반 AI 요약 기능 구현 방안 (요구사항 #6, #7 관련)

소규모 팀 내부용 서비스는 트래픽이 크지 않으므로, 아래와 같은 **무료 티어 LLM API**로 충분히 MVP를 운영할 수 있습니다. (단, 무료 티어 정책은 각 회사가 수시로 변경하므로 실제 구축 시점에 공식 문서로 최종 확인이 필요합니다.)

#### 6.2.1 제공사 비교 및 조합 제안

| 제공사 | 특징 | 이 서비스에 적합한 이유 |
|---|---|---|
| **Google Gemini API (Flash / Flash-Lite)** | <cite index="7-1">신용카드 등록 없이 무료로 시작 가능하며, 100만 토큰 컨텍스트 윈도우를 제공</cite>. <cite index="3-1">2026년 기준 무료 티어는 Flash와 Flash-Lite 모델을 중심으로 운영</cite> | 긴 기술 블로그 글 전체를 한 번에 넣고 요약·설명을 뽑기 좋은 대용량 컨텍스트. 팀 내부 소규모 트래픽이면 무료 한도 내에서 충분히 운영 가능 |
| **Groq API** | <cite index="12-1">별도 카드 등록 없이 분당 30회, 일 1,000회 수준의 무료 요청 한도를 제공</cite>하며, <cite index="9-1">LPU 하드웨어 기반의 매우 빠른 추론 속도</cite>가 특징. 오픈소스 모델(Llama, Gemma 계열 등)만 제공 | 응답 속도가 빨라 "형광펜 → AI 설명" 같은 실시간성이 중요한 인터랙션에 적합 |
| **자체 호스팅 오픈소스 모델 (Ollama 등, 대안)** | API 요청 한도 자체가 없음(완전 무료) — 대신 팀이 GPU/서버 인프라를 직접 운영해야 함 | 무료 API 한도를 자주 초과하거나 데이터를 외부로 보내고 싶지 않을 때의 대체 옵션. 소규모 팀 MVP 단계에서는 인프라 부담 대비 우선순위 낮음 |

**제안하는 조합**
- **AI 요약(글 전체 3~5줄 요약)**: Gemini Flash/Flash-Lite — 긴 본문을 통째로 넣어도 컨텍스트 여유가 있고 무료 한도가 넉넉함
- **형광펜 구간 AI 설명(짧은 문장 단위 실시간 응답)**: Groq — 응답 속도가 중요한 인터랙션이므로 활용
- 두 서비스 모두 무료 한도가 있으므로, 한도 초과 시 오류 처리 및 "잠시 후 다시 시도" UX, 두 제공사를 상호 폴백(fallback)으로 구성
- 팀 내부 코드/민감 정보가 아닌 "공개된 기술 블로그 글" 요약이 목적이므로 데이터 민감도 이슈는 상대적으로 낮지만, 무료 티어는 입력 데이터가 모델 학습에 활용될 수 있다는 정책이 있는 경우가 있어 이용약관 확인 필요

#### 6.2.2 AI 요약 처리 파이프라인 (기술 상세)

무료 티어를 실제로 안정적으로 운용하려면 단순히 API를 호출하는 것을 넘어 아래와 같은 처리 흐름이 필요합니다.

1. **본문 추출**: 원문 HTML에서 광고/내비게이션/댓글 등을 제거하고 본문만 뽑아내는 리더빌리티 계열 라이브러리(예: Mozilla Readability, Trafilatura) 사용 → 이 텍스트가 LLM 입력이 됨
2. **길이 확인 및 청킹**: 추출한 본문의 토큰 수를 계산해 모델 컨텍스트 한도 내인지 확인. Gemini Flash-Lite는 컨텍스트가 넉넉해 대부분의 글은 한 번에 처리 가능하나, 매우 긴 글은 섹션 단위로 나눠 1차 부분 요약 후 2차로 통합 요약하는 map-reduce 방식 적용
3. **프롬프트 설계**: 출력 형식을 JSON 스키마로 강제(예: `{ "summary": ["...", "...", "..."], "keywords": ["...", "..."], "recommend_for": "..." }`) → 파싱 실패 시 1회 재시도
4. **비동기 처리 큐**: 글 등록(팀원 수동) 또는 자동 수집 직후 요약 작업을 큐(자체 DB의 job 테이블 또는 경량 메시지 큐)에 적재 → 워커가 순차로 꺼내 처리해 등록자를 기다리게 하지 않음(3.7 트리거 시점과 연계)
5. **무료 한도(rate limit) 대응**: 제공사별 분당/일별 요청 한도를 고려해 워커의 동시 처리 수를 제한하고, 한도 초과 응답(429 등) 수신 시 지수 백오프로 재시도
6. **폴백 체인**: 1차 Gemini 요청 실패(한도 초과·오류) → 2차 Groq로 자동 폴백 → 둘 다 실패 시 큐에 재적재 후 지연 재시도, 그동안 사용자에게는 "요약 준비 중" 상태 유지
7. **캐싱/중복 호출 방지**: 원문 URL 또는 본문 해시 기준으로 이미 요약이 존재하면 재호출하지 않음 — 자동 수집 글을 팀원이 나중에 수동 등록해 같은 글을 가리키게 되는 경우에도 기존 요약을 재사용(3.1 중복 방지와 연계)
8. **형광펜 구간 AI 설명은 별도 경량 엔드포인트로 분리**: 선택한 짧은 텍스트만 Groq에 전달해 응답 속도를 최적화하고, 글 전체 요약 파이프라인(비동기 배치)과는 독립적으로 실시간 처리

#### 6.2.3 무료 한도 초과 시 대응 전략 (권장안)

무료 API 한도 초과는 언젠가 반드시 마주치는 문제이므로, 아래와 같은 단계적 대응을 권장합니다.

1. **1차 방어 — 폴백 체인(6.2.2의 6번)**: Gemini 한도 초과 시 Groq로 자동 전환. 두 제공사의 무료 한도가 겹치지 않는 트래픽 패턴이라면 대부분의 요청을 무료로 커버 가능
2. **2차 방어 — 사용량 모니터링**: 일별/월별 API 호출 수를 자체 로깅해 무료 한도의 70~80%에 도달하면 관리자에게 알림(운영 대시보드 또는 슬랙 알림 등) — 실제 한도 초과 전에 미리 대응할 시간을 확보
3. **유료 전환 판단 기준(권장)**: 아래 중 하나에 해당하면 유료 플랜 전환을 검토
   - 팀 규모가 커져(예: 30명 초과) 무료 한도로 안정적인 응답이 어려워질 때
   - 폴백 체인(Gemini↔Groq)에도 불구하고 한도 초과로 인한 "요약 준비 중" 지연이 반복적으로 발생할 때
4. **유료 전환 시 우선순위**: 사용량이 크고 배치성인 글 전체 요약(Gemini)부터 종량제로 전환하고, 형광펜 실시간 설명(Groq)은 무료 한도 내에서 최대한 유지 — 비용에 더 직접적으로 연동되는 쪽부터 우선 전환
5. **최후 대안**: 두 제공사 모두 유료 전환이 부담스러운 경우, 6.2.1의 자체 호스팅 오픈소스 모델(Ollama 등)로 전환해 API 비용 자체를 없애는 방안도 검토(단, 인프라 운영 부담과의 트레이드오프 고려)
6. **비용 최소화 공통 원칙**: 6.2.2의 캐싱(중복 요약 방지)을 최대한 활용하고, "다시 요약하기" 재생성 요청에는 rate limit을 유지해 남용으로 인한 불필요한 API 호출을 방지

### 6.3 크롤링/메타데이터 관련 유의사항
- 각 기술 블로그(네이버/컬리/당근마켓/토스/우아한형제들/오늘의집 등)의 `robots.txt` 및 이용약관을 확인해 허용된 범위 내에서만 메타데이터를 수집
- 가능한 경우 각 블로그의 **공식 RSS/Atom 피드**를 우선 사용하고, 페이지 스크레이핑은 RSS 미제공 시에만 보조적으로 사용
- **본문 전체를 자체 스토리지에 저장하는 정책(3.2 확정)을 취하는 만큼 저작권 리스크 관리가 중요** — 팀 전용 비공개 서비스 내부에서만 노출하고 외부 공개·검색엔진 노출은 하지 않으며, 본문 상단에 원저작자·출처·[원문 바로 읽기] 링크를 항상 표시해 "재배포"가 아닌 "팀 내부 아카이빙"임을 명확히 함
- 실시간에 가까운 폴링 주기(5~15분, 3.1 확정)를 적용하되, 사이트별 서버 부담을 고려해 과도한 요청은 지양하고 필요 시 사이트별로 간격을 조정
- 수집 대상 회사가 늘어날수록 사이트별 RSS 포맷/필드 차이, 수집 실패(사이트 개편 등) 대응 로직이 필요 — 회사별 수집 어댑터 구조로 관리 권장

## 7. 비기능 요구사항

- **권한/보안**: 팀 전용 클로즈드 서비스 — 초대 없이는 가입 불가, 글/댓글 삭제는 작성자 본인 또는 관리자만 가능. 원문 본문 전체 저장 데이터는 팀 내부에만 노출(외부 비공개)
- **데이터 보존**: 글 삭제는 소프트 삭제 후 유예기간을 두고 영구 삭제(3.4 확정, 정확한 유예 일수는 오픈 이슈)
- **성능**: AI 요약은 비동기 처리(등록 즉시 사용자를 기다리게 하지 않음)
- **알림**: 댓글/멘션/요약 완료 시 인앱 또는 푸시 알림(선택 기능, MVP 이후 고려 가능)
- **접근성**: 형광펜 색상은 색약 사용자도 구분 가능하도록 색상+아이콘 병행 고려

## 8. MVP 범위 제안

빠르게 팀 내에서 써볼 수 있는 MVP 범위를 아래와 같이 제안합니다. 우선순위는 팀 논의를 통해 조정 가능합니다.

**MVP (1차 출시 범위)**
0. **웹 우선 출시(확정)** — Next.js 기반 반응형 웹으로 MVP를 구축, 앱은 이후 확장 검토
1. 하단 탭바(탐색/큐레이션/검색/마이) 골격 + **아티클 카드 공통 UI**(썸네일 위 [원문 바로 읽기] 버튼 포함, 인앱 브라우저로 열기 기본값, 5.0 참조)
2. **자동 수집(크롤링) 파이프라인** — 네이버/컬리/당근마켓/토스/우아한형제들/오늘의집 RSS 기반 신규 글을 실시간에 가까운 주기(5~15분)로 자동 수집하고 **본문 전체를 자체 저장**해 탐색 탭 최신 피드에 노출
3. 카테고리 선택 + URL 기반 글 등록(**등록 노트는 권장이지만 건너뛰기 가능**) + 회사·태그 분류 + 삭제(본인만, 소프트 삭제 후 유예기간), 자동 수집 글과의 중복 방지, **자동 수집 글·건너뛴 글에 팀원이 나중에 등록자 노트 추가 가능**
4. 글 목록/상세 조회 + 전체 댓글(대댓글 없이 1단계)
5. 북마크(글 단위) + **읽기 상태 트래킹**(읽기 전/읽는 중/다 읽음, 스크롤 90% 기준, 3.9) + **마이 라이브러리**(활동 통계 3종, 이어서 읽을 아티클, 저장한 아티클, 내가 올린 글)
6. **개인 메모 기능**(글 단위, 기본 비공개 + "팀에 공개" 토글 옵션, 3.10)
7. AI 요약(글 전체 3~5줄 요약, Gemini 무료 티어 + 6.2.2 처리 파이프라인, 한도 초과 대응은 6.2.3) — 자동 수집 글에도 동일 적용
8. **관심 키워드 설정 + 큐레이션 탭**(온보딩 강제 없음, 큐레이션 탭 내 질문형 키워드 칩 선택 → 카테고리 매칭, 부족 시 이번 주 인기 글로 보충)
9. **토론 신청 기능**(글 상세 [댓글]/[토론] 탭 분리, 참여 인원 무제한·중도 이탈 허용, 팀 전체 브로드캐스트 알림, 개설자만 종료 가능, 3.11)

**MVP 이후(v1.1+)**
10. 형광펜 + 하이라이트 구간 인라인 댓글 (Notion 스타일, 팀 공개 기본 + 개인 전용 토글)
11. 하이라이트 구간 AI 쉬운 설명(Groq 연동)
12. 대댓글, 멘션 알림, 이모지 리액션
13. 컬렉션(주제별 글 모음) 기능
14. 검색 고도화(태그/회사/작성자 복합 필터)
15. 큐레이션 고도화(AI 임베딩 기반 의미 유사도 추천)
16. 자동 수집 대상 회사 확장 + 회사별 수집 어댑터 안정화
17. 정밀 스크롤 위치 기반 "정확한 위치로 이어보기"(MVP는 3단계 읽기 상태까지만 지원, 3.9 참조)
18. 토론의 오프라인/온라인 미팅 일정 잡기(캘린더 연동), 마이 탭에서 "내가 신청/참여한 토론" 모아보기
19. 토론 신청 알림을 관심 키워드/카테고리가 맞는 팀원에게 우선 발송

## 9. 정책 결정 사항 및 남은 오픈 이슈

팀 논의를 통해 대부분의 정책을 확정했습니다. 아래 9.1은 확정된 정책 요약이며, 9.2는 아직 세부 사항이 더 필요한 소수의 잔여 이슈입니다.

### 9.1 확정된 정책

- **원문 보존**: 본문 전체를 자체 저장해 서비스 내에서 렌더링(하이라이트 기능 지원 목적), 팀 내부 전용 비공개, [원문 바로 읽기] 링크 상시 노출 (3.2)
- **형광펜 공개 범위**: 팀 전체 공개가 기본값, 토글로 개인 전용 전환 가능 (3.8)
- **삭제 정책**: 소프트 삭제 후 유예기간을 두고 영구 삭제 (3.4) — 정확한 유예 일수는 9.2 참조
- **AI 무료 한도 초과 대응**: 폴백 체인 → 사용량 모니터링 → 유료 전환 기준 → 부분 유료화 → 자체 호스팅 순의 단계적 대응 전략 채택 (6.2.3)
- **서비스 이름**: 미정 — 가칭 유지, 추후 확정
- **출시 플랫폼**: 웹 우선 출시 확정(Next.js), 앱은 이후 확장 검토
- **등록 노트 강제성**: 카테고리·원문 URL만 필수, 등록 노트(핵심 인사이트/정리할 지식/적용할 점)는 권장이지만 건너뛰기 허용 (3.4)
- **자동 수집 주기**: 실시간에 가까운 폴링(5~15분 간격) 적용 (3.1)
- **자동 수집 글의 등록자 노트**: 팀원 누구나 나중에 "등록자 노트 추가하기"로 작성 가능, 작성자가 노트 작성자로 표시 (3.1)
- **큐레이션 키워드 설정**: 온보딩 강제 없음, 큐레이션 탭 진입 시 질문형 키워드 칩에서 선택하는 방식으로 대체 (3.6)
- **큐레이션 매칭**: 카테고리 기준 매칭이 기본, 매칭 결과가 부족하면 이번 주 팀 내 인기(조회수) 글로 보충 (3.6)
- **읽음 판정 기준**: 스크롤 비율 90% 도달 시 자동으로 "다 읽음" 처리, 보조 지표 결합은 하지 않음 (3.9)
- **개인 메모 공개 범위**: 기본 비공개, 메모별 "팀에 공개" 토글 제공 (3.10)
- **원문 바로 읽기**: 인앱 브라우저로 열기를 기본값으로 채택 (5.0)
- **댓글 → 토론 전환 유도**: 답글이 일정 개수 이상 쌓이면 "토론을 열어볼까요?" 플로팅 버튼으로 유도(강제 전환은 아님) (3.11)
- **토론 참여**: 인원 제한 없음, 참여 후 중도 이탈(참여 취소) 허용 (3.11)
- **토론 종료**: 토론을 개설한 신청자만 종료 처리 가능 (3.11)
- **토론 알림**: MVP는 팀 전체 브로드캐스트, 관심 키워드/카테고리 기반 우선 알림은 v1.1 이후 (3.11)
