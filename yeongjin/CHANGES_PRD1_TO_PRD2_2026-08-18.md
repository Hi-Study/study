## 1. 트리거 — 2026-08-06 회의록 반영

`common/회의록/2026-08-06.md` 회의에서 정보구조와 토론 기능의 정의가 크게 바뀌었고, 이를 기준으로 PRD를 v0.1 → v0.2로 전면 갱신한 뒤, 실제 코드에도 반영했다.

## 2. 정보구조(IA) 변경

| 항목 | v1 | v2 |
|---|---|---|
| 하단 탭 | 탐색 / 큐레이션 / 검색 / 마이 (4탭) | **홈 / 피드 / 토론 / 검색 / 마이 (5탭)** |
| 탐색·큐레이션 | 최신 전체 피드(탐색) + 개인 관심 키워드 매칭 추천(큐레이션)을 분리 | **홈**(추천 글 + 기업 칩 다중선택 + 기업별 스와이프)과 **피드**(전체 최신 목록)로 재편. 개인 키워드 매칭 로직은 폐기 |
| 토론 | 탭 없음(댓글 기능에 포함) | **신규 5번째 탭**, "우리 서비스의 핵심 가치"로 격상 |

## 3. 글 등록 — "등록자 노트" → "독후감"

| v1 | v2 |
|---|---|
| 핵심 인사이트 / 정리해야 할 기술 지식 / 바로 적용할 점 | **인상 깊은 부분 / 접목하고 싶은 방법 / 질문·토론하고 싶은 것** |

코드에서는 DB 컬럼(`core_insight`/`tech_knowledge`/`action_point` → `impressive_part`/`apply_idea`/`discussion_question`), 등록 폼, 상세 화면 라벨을 모두 리네이밍했다(마이그레이션 `005_reading_note_rename.sql`).

## 4. 토론 기능 재정의 — 두 번 바뀜

1. **v1 → v2(회의록 반영 시점)**: v1의 "토론 신청"(모집 중/진행 중/종료 상태, 참여하기/참여 취소, 개설자만 종료 가능, 전용 스레드)을 **완전히 폐기**. 독후감 자체가 토론 노출 단위가 되고, 독후감에 댓글을 다는 것만으로 토론이 성립하도록 단순화.
2. **v2 → 오늘 작업본(같은 날 후반)**: 사용자가 "참여 인원을 보여주고 참여하기 버튼을 두자"고 재요청. v1의 무거운 상태 관리(모집/개설/종료, 전용 스레드)는 다시 들여오지 않되, **가벼운 참여/참여 취소 토글 + 참여 인원 표시**만 재도입했다. 신청 절차·정원 제한·전용 스레드는 여전히 없음.

추가로 토론 탭에 **인기/최신/추천 정렬 탭 + 카테고리 필터**를 신설했다(인기 = 참여 인원+댓글 수, 추천 = 북마크 수 기준).

구현: `discussion_participants` 테이블(마이그레이션 `017_discussion_participants.sql`), `POST /api/articles/[id]/participate`, `components/participate-button.tsx`.

## 5. AI 요약 — 자유 서술 → 3항목 구조화

| v1 | v2 |
|---|---|
| 3~5줄 핵심 요약 + 키워드 3~5개 | **무슨 문제를 다뤘나? / 어떻게 해결했나? / 디자이너·PM 관점에서 무엇을 배울 수 있나?** 3항목 |

`ai_summary`/`ai_key_points` 컬럼을 `ai_problem`/`ai_solution`/`ai_takeaway`로 교체(마이그레이션 `006_ai_summary_restructure.sql`), Gemini 프롬프트·스키마도 동일하게 변경. 참고로 코드에 하드코딩돼 있던 모델명(`gemini-2.0-flash`)이 단종되어 `gemini-3.6-flash`로 교체했다(모델 세대가 바뀐 것일 뿐 PRD 내용과는 무관).

## 6. 인증 — 초대코드+이메일/소셜 → 구글 전용

v1: 초대 코드 기반 가입 + 이메일/소셜 로그인. v2(확정): **구글 로그인만 지원**.

구현: 이메일/비밀번호 기반 로그인·회원가입·비밀번호 찾기 페이지와 컴포넌트를 전부 제거하고, `signInWithOAuth({provider:'google'})` + `/auth/callback` 라우트로 교체했다. **다만 Google Cloud OAuth 클라이언트 등록과 Supabase Authentication → Google Provider 활성화는 콘솔 작업이 필요해 아직 완료되지 않았다** — 코드만 준비된 상태(아래 "미완료 항목" 참고).

## 7. 원문 본문 스냅샷 — 저장 안 함 → 저장함(확정)

v1은 "본문 전체를 저장해 서비스 내에서 렌더링"이 정책이었지만, 실제로는 한 번도 구현되지 않고 `FEATURE_ORIGINAL_SNAPSHOT=false`로 꺼진 채 방치돼 있었다. 오늘 실제로 구현해서 `true`로 전환했다.

- `@mozilla/readability` + `jsdom`으로 원문에서 본문만 추출 → `sanitize-html`로 정제(스크립트/이벤트 핸들러 제거, 외부 링크는 `noopener noreferrer` 강제) → 글 상세 화면에 렌더링
- 추출 실패(사이트 차단 등) 시 "본문 불러오기" 버튼으로 재시도 가능
- 형광펜·메모·AI 쉬운 설명 기능이 이제 원문 본문에도 그대로 적용됨(기존엔 AI 요약/독후감 텍스트에만 한정)

## 8. 자동 수집(RSS) — 정책만 있던 상태 → 실제 파이프라인 구현 + 1회 실행 완료

v1/v2 PRD에는 "꾸준히 올리는 기업 대상, 2025-07-01 이후 글만 수집"이라는 정책만 있었고 코드는 없었다. 오늘 실제로 구현하고 로컬에서 1회 실행까지 완료했다.

- 대상 기업(RSS 피드 URL을 실제로 검증한 곳만 등록): **토스 기술 블로그, 우아한형제들 기술블로그, 당근 기술 블로그** — 네이버 D2·컬리·오늘의집은 피드 접근이 막혀있거나 확인 실패해 보류
- `rss-parser`로 피드를 폴링 → 신규 글만(URL 중복 검사) 저장 → 본문 추출 → AI 요약 생성 → 좋아요한 기업 팔로워에게 알림 발송까지 한 번에 처리(`lib/rss/collect.ts`)
- Vercel Cron 엔드포인트(`/api/cron/collect`, `vercel.ts`)로 스케줄링 준비 완료(매시 정각). `CRON_SECRET` 인증 지원
- **실행 결과**: 토스 19개, 우아한형제들 10개, 당근 10개 = 총 39개 실제 글을 수집해 AI 요약까지 생성 완료(로컬 `.local-data/articles.json`에 반영됨)
- 자동 수집 글은 등록자가 없어 독후감이 비어있을 수 있다는 점을 반영해, `impressive_part`/`apply_idea`/`discussion_question` 컬럼을 nullable로 변경(마이그레이션 `013_auto_collection.sql`)하고, 팀원이 나중에 독후감을 채우는 "독후감 추가" 플로우를 신설(`components/add-note-form.tsx`, `POST /api/articles/[id]/note`)

## 9. 하이라이트 + 개인 메모 — 확장

- 기존엔 AI 요약/독후감 텍스트에만 한정돼 있던 형광펜 범위를 **원문 본문까지 확장**(7번 항목과 연동)
- 하이라이트가 AI요약/독후감/본문 중 **어느 영역에서 나왔는지(zone)** 태깅하도록 스키마 확장(마이그레이션 `016_highlight_zones.sql`) — 글 상세의 "하이라이트" 탭에서 영역별 분포 막대그래프로 확인 가능
- 공개 범위는 v1/v2 모두 "나만 보기"로 동일(변경 없음, 재확인만 함)

## 10. 알림 — PRD엔 있었지만 미구현이던 것을 신설

PRD 공통 헤더에 "알림 유틸리티(좋아요한 기업의 새 글 / 내 독후감의 댓글 / 대댓글)"가 명시돼 있었지만 코드는 없었다. 오늘 처음 구현했다.

- `/notifications` 전용 화면 신설, **"기업 소식" / "댓글"** 두 탭으로 분리(사용자 요청 반영)
- 개별 알림 읽음 토글 + 삭제, 전체 읽음 처리
- 트리거 지점: 좋아요한 기업의 새 글 등록/수집 시, 내 독후감에 댓글이 달렸을 때, 내 댓글에 대댓글이 달렸을 때
- 기업 "좋아요"(팔로우) 기능도 함께 신설(`company_follows` 테이블) — 헤더 알림 정책의 전제 조건이었으나 이것도 미구현 상태였음

## 11. 검색 — 최근/추천/급상승 실제 구현

PRD엔 있었지만 인기 태그 검색만 구현돼 있던 상태에서, 세 가지를 모두 구현했다.

- 최근 검색어: 기기(브라우저) 로컬 저장
- 추천 검색어: 질문형 문구 고정 큐레이션(개인화 엔진 이전 단계)
- 급상승 검색어: 실행된 검색어를 로그로 쌓아 누적 횟수로 집계(`search_logs` 테이블)

## 12. 마이페이지 — 구조 재설계

- 기존엔 6개 섹션(임시저장/내 글/내 댓글/북마크/하이라이트·메모/읽은 아티클)이 세로로 전부 나열되던 것을 **탭 전환 구조**로 변경
- 프로필 영역에 커버+아바타, "내 글·댓글·북마크" 통계 추가
- **이번 달 읽은 글 수 + 읽음 활동 캘린더**(실제 읽음 기록 기반, 이번 달에 글을 읽은 날짜가 표시됨) 신설
- "내 글" 판정 로직을 `source_type`(manual/auto) + `note_author` 기준으로 정교화 — 수동 등록 글과 자동 수집 후 내가 독후감을 채운 글을 모두 포함하도록 수정

## 13. 홈 · 피드 — UI/UX 리디자인

- **홈**: 추천 글을 리스트가 아니라 **스와이프 가능한 큰 카드 캐러셀**로 변경, 제목을 "{이름}님을 위해 모아봤어요"로 변경. 기업 칩에 **1개 이상 선택 시 "초기화" 칩으로 전환**되는 로직 추가
- **피드**: 기업 칩 과다 문제(v1/v2 PRD의 오픈 이슈였음) 대응으로 "자주 쓰는 기업 5개 + 기업 + 드롭다운" 패턴 적용, 기업 선택 시 하위 카테고리 필터 노출, **최신순/조회순 정렬** 신설(조회순은 실제 읽음 기록 집계 기준)
- **썸네일 폴백**: 원문 썸네일이 없으면 기업 브랜드 컬러 배경 + 로고로 대체(`lib/companies/brand.ts`)
- 모든 가로 스와이프 영역(캐러셀, 필터 칩, 탭)에서 OS 스크롤바가 겹쳐 보이던 것을 CSS로 숨김 처리

## 14. 디자인 시스템 도입

기존 v0.2 PRD의 오픈 이슈였던 "각자 디자인 진행 시 일관성을 어떻게 맞출지"에 대한 답으로, 독서 리뷰 앱 "사락(sarak)" 캡처를 레퍼런스로 한 공통 디자인 시스템을 도입했다(`DESIGN.md`, `.claude/rules/design-system.md`). 컬러 토큰(`featured`/`highlight` 추가), 라운드 규칙(행동 요소는 pill, 콘텐츠는 `rounded-xl`+), 리스트/탭/빈 상태 공통 패턴을 정의하고 오늘 만든 화면 대부분에 적용했다. 글 상세 화면도 이 참고 앱의 도서 상세 화면 구조(AI 요약 카드, 하이라이트 분포+목록, 원문정보/하이라이트·댓글 탭)를 우리 데이터에 맞게 재구성했다.

## 15. 아직 안 된 것 (미완료 항목)

- **Google OAuth 콘솔 설정**: 코드는 준비됐지만 Google Cloud Console에서 OAuth 클라이언트 발급, Supabase Authentication에서 Google Provider 활성화는 아직 안 함 → 지금은 실제 구글 로그인이 동작하지 않음
- **Supabase 실 프로젝트 연동**: 기존 프로젝트가 일시 중지/만료된 상태라 `DATA_BACKEND=local`(로컬 파일 스토어)로 개발 중. 마이그레이션 SQL(001~017)은 전부 작성돼 있으나 실제 Supabase 프로젝트에는 아직 적용 안 함
- **자동 수집 대상 기업 확장**: 네이버 D2·컬리·오늘의집 RSS 피드 URL 미확인(보류)
- **Vercel 배포/Cron 실제 등록**: `vercel.ts`에 크론 설정은 있으나, 실제 Vercel 프로젝트 배포·연결·`CRON_SECRET` 환경변수 설정은 안 함
- **서비스 이름 최종 확정**: v1부터 이어지는 오픈 이슈, 그대로 미해결
