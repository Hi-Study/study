## 1. 개요

### 1.1 배경
네이버, 컬리, 당근마켓, 토스, 우아한형제들, 오늘의집 등 국내 빅테크/스타트업 기업들이 운영하는 기술 블로그에는 실무에 도움이 되는 아키텍처, 조직 문화, 트러블슈팅 사례가 많지만, 흩어져 있는 글을 팀원들이 각자 찾아 읽고 개인적으로만 소비하는 경우가 많습니다. 좋은 글을 발견해도 팀 내에 공유되지 않거나, 공유되더라도 링크만 던져지고 논의가 이어지지 않아 휘발되는 문제가 있습니다.

### 1.2 목적
팀원들이 함께 기업 기술 블로그 글을 **모으고(큐레이션), 읽고 나서 독후감을 남기고, 그 독후감을 기준으로 토론**할 수 있는 소규모 팀 전용 서비스를 만든다. "링크만 공유하고 끝"이 아니라, 읽은 사람이 **인상 깊었던 부분·자신의 업무에 접목할 방법·토론하고 싶은 지점**을 직접 정리하게 함으로써 콘텐츠 소비를 팀의 학습과 논의로 연결한다.

### 1.3 핵심 가치 제안 (Value Proposition)
- **모은다**: 꾸준히 좋은 글을 올리는 기업들의 기술 블로그를 큐레이션
- **독후감을 남긴다**: 단순 링크 공유가 아니라 인상 깊은 부분 / 접목하고 싶은 방법 / 토론 주제를 스스로 정리하게 한다
- **함께 토론한다 (우리 서비스의 핵심 가치)**: 독후감을 기준으로 다른 팀원과 의견을 주고받는다
- **쉽게 읽는다**: AI 요약(무슨 문제를 다뤘는지 / 어떻게 해결했는지 / 디자이너·PM 관점에서 무엇을 배울 수 있는지)과 하이라이트+개인 메모로 어려운 글의 진입장벽을 낮춘다
- **다시 찾는다**: 북마크와 마이페이지로 나중에 다시 꺼내볼 수 있게 한다

### 1.4 타겟 사용자
- 1차 타겟: 함께 스터디하거나 기술 트렌드를 공유하고 싶은 소규모 팀(사내 스터디 그룹, 소수 팀 단위, 10~30명 내외)
- AI 요약 항목에 "디자이너·PM 관점에서 배울 점"이 포함될 만큼, 개발자뿐 아니라 **디자이너/PM도 함께 참여하는 팀**을 전제로 한다
- 사용자는 모두 로그인된 팀 구성원이며, 외부 공개 서비스가 아닌 **팀 전용(클로즈드) 서비스**를 우선 가정

### 1.5 페르소나 (예시)
| 페르소나 | 특징 | 니즈 |
|---|---|---|
| 주니어 개발자 A | 좋은 아티클을 발견하면 저장은 하지만 끝까지 안 읽고 방치 | AI 요약으로 핵심만 빠르게 파악, 어려운 용어는 하이라이트+메모로 바로 정리 |
| 시니어 개발자 B | 좋은 글을 팀에 공유하고 토론하고 싶음 | 독후감을 남기고 팀원 반응을 확인, 독후감에 달린 댓글로 깊이 논의 |
| PM/기획자 C | 기술 용어가 낯설어 완독이 어려움 | AI 요약의 "디자이너·PM 관점에서 배울 점" 항목으로 실무 시사점만 빠르게 파악 |

## 2. 정보 구조 (IA) — 하단 탭바 구성 (2026-08-06 확정)

앱은 하단 탭바 **5개 탭**을 기본 골격으로 하고, 글 상세·글 등록은 탭에 속하지 않는 별도 화면으로 둔다.

```
┌─────────────────────────────────────────────────┐
│                                                 │
│                 (콘텐츠 영역)                     │
│                                                 │
├─────────────────────────────────────────────────┤
│  🏠 홈   📰 피드   💬 토론   🔍 검색   👤 마이     │
└─────────────────────────────────────────────────┘
```

| 탭 | 역할 |
|---|---|
| **홈** | 큐레이션 화면. 상단 추천 글, 중단 기업별 칩(다중 선택), 하단 기업별 글 스와이프로 구성 |
| **피드** | 전체 글 목록. 홈에서 특정 기업 칩을 클릭하면 이동되는 페이지이기도 하며, 기업 필터링을 지원 |
| **토론** | **우리 서비스의 핵심 가치.** 팀원들이 남긴 독후감이 토론의 단위가 되어 노출되고, 팀원은 그 독후감에 댓글을 달아 토론한다 |
| **검색** | 최근 검색어 / 추천 검색어(질문형) / 급상승 검색어 기반 탐색 |
| **마이** | 임시저장, 내 글(등록한 글 + 크롤링한 글, 독후감 기준), 내 댓글, 북마크, 하이라이트/메모, 읽은 아티클 |

> 기존 v0.1의 "탐색(최신 전체 피드) + 큐레이션(개인화 추천)" 2탭 분리 구조는 폐기되었다. **홈이 큐레이션(추천+기업칩) 역할을, 피드가 최신 전체 피드 역할을 맡는 구조로 단순화**되었고, 개인 관심 키워드 매칭 기반 추천 로직(v0.1 3.6)은 더 이상 사용하지 않는다. 대신 **토론 탭이 신규 5번째 탭으로 추가**되어 핵심 가치로 격상되었다.

## 4. 핵심 기능 명세

### 4.1 홈 — 큐레이션

**목표**: 진입 즉시 팀이 관심 가질 만한 글과 기업별 콘텐츠를 한눈에 보여준다.

- **상단**: 추천 글
- **중단**: 기업별 칩 (다중 선택 가능)
- **하단**: 기업별 글 스와이프
- 기업 칩/스와이프 항목을 탭하면 해당 기업으로 필터링된 **피드** 화면으로 이동

### 4.2 피드 — 전체 글

**목표**: 전체 글을 최신순으로 훑어볼 수 있는 기본 목록.

- 전체 피드이자, 홈에서 기업 클릭 시 이동되는 페이지
- 기업 칩으로 필터링 가능
- ⚠️ **오픈 이슈**: 등록 대상 기업이 늘어날수록 기업 칩이 너무 많아지는 문제 — 표현 방식은 각자 고민 후 확정 필요 (10.2 참조)

### 4.3 아카이빙 구조 — 데이터 모델

- **글(Post)**: 제목, 원문 URL, 출처 기업, 저자, 발행일, 썸네일, 출처 타입(자동 수집/팀원 등록), 등록자(팀원 등록인 경우), 등록일, 키워드 태그
- **독후감(Reading Note, 구 "등록자 노트")**: 글 등록 시 작성자가 남기는 서술형 3항목 — 4.4 참조. 토론 탭에 노출되는 단위이자 마이 탭 "내 글" 정렬 기준
- **기업(Company/Source)**: 이름, 로고, 블로그 홈 URL, RSS 피드 URL(자동 수집용)
- **사용자-글 관계(User-Post)**: 북마크 여부, 읽은 아티클 여부, 하이라이트/메모, 임시저장 여부
- **콘텐츠 대상 기업 선정 기준 (확정)**: 꾸준히 콘텐츠를 올리는 기업만 대상으로 큐레이션
- **과거 글 수집 범위 (확정)**: 2025년 7월 1일 이후에 발행된 글만 포함

### 4.4 글 등록 — 독후감 (v0.1 "등록자 노트"를 대체)

**목표**: 링크만 던지고 끝나는 아카이빙이 되지 않도록, URL과 함께 **독후감**을 남기게 한다. 이 독후감이 곧 토론 탭에 노출되는 단위가 된다.

- **등록 항목**
  | 항목 | 설명 |
  |---|---|
  | **URL** | 원문 링크. 오픈그래프 기반 제목/썸네일/발행일/기업 자동 추출 시도 |
  | **독후감 — 인상 깊은 부분** | 이 글에서 인상 깊었던 지점 |
  | **독후감 — 접목하고 싶은 방법** | 내 업무/팀에 접목하고 싶은 방법 |
  | **독후감 — 질문 / 토론하고 싶은 것** | 팀원과 논의하고 싶은 질문이나 주제 |
- 중복 URL 등록 방지(이미 등록된 글이면 안내 후 기존 글로 이동)
- 등록한 독후감은 **토론 탭**에 노출되어 다른 팀원의 댓글을 받는다

### 4.5 글 상세

- **의견**: 글에 대한 팀원들의 의견
- **의견에 대한 댓글**
- **하이라이트 + 메모 (나만 보기, 확정)**: 본문 드래그로 하이라이트하고 그 위에 개인 메모를 남긴다. 팀 공개가 아닌 **개인 전용**이 기본값이자 유일한 범위로 확정됨
- **AI 요약**: 아래 3개 관점으로 구조화하여 제공
  - 무슨 문제를 다뤘나?
  - 어떻게 해결했나?
  - 디자이너·PM 관점에서 무엇을 배울 수 있나?
- **키워드 태그**

### 4.6 토론 — 우리 서비스의 핵심 가치

**목표**: 읽고 흘려보내는 것이 아니라, **읽은 글을 바탕으로 다른 사람과 토론하며 내 견해를 넓혀가게** 한다 — 독후감을 남긴 사람과 그것을 읽은 사람이 실제로 대화를 나누는 것이 핵심.

- **노출 방식**: 독후감 기준으로 노출된다 — 즉 토론 탭의 목록 단위는 "글"이 아니라 "독후감". 목록에는 기반 글 썸네일, 어떤 글을 기반으로 한 토론인지, 참여 인원, 댓글 수가 함께 보인다
- **참여 방식**: 독후감에 댓글을 달아 토론한다. 추가로 **가벼운 "참여하기" 토글**을 제공해 관심 있는 토론에 참여 의사를 표시할 수 있다(2026-08-XX 재도입, 아래 참고)
- **필터/정렬**: 상단 인기·최신·추천 탭 + 카테고리 칩으로 토론 목록을 필터링한다. 인기는 참여 인원+댓글 수, 추천은 북마크 수 기준
- v0.1의 "토론 신청"(모집 중/진행 중/종료 상태, 개설자만 종료 가능, 전용 스레드) 같은 **무거운 상태 관리는 여전히 도입하지 않는다.** 신청·모집·개설·종료 절차 없이, 독후감이 등록되는 즉시 토론 가능한 대상이 되고, 참여는 단순 토글(참여/참여 취소)일 뿐 전용 스레드나 정원 제한은 없다

### 4.7 검색

**목표**: 팀원이 자신의 관심사를 쉽게 찾을 수 있게 한다.

- 최근 검색어
- 추천 검색어 (질문형 문구로 제공 — 예: "A/B 테스트, 어떻게 설계하지?")
- 급상승 검색어

### 4.8 마이 페이지

- 임시저장 (글 등록 중 이어 쓰기)
- **내 글**: 내가 등록한 글 + 크롤링(자동 수집)되어 내가 노트를 남긴 글 포함, **독후감 기준**으로 정렬/노출
- 내 댓글
- 북마크
- 하이라이트 / 메모
- 읽은 아티클

### 4.9 형광펜 + 개인 메모

- 본문 드래그 시 하이라이트 적용 가능
- 하이라이트 구간에 메모를 남길 수 있으며, **개인 전용(나만 보기)이 기본값이자 확정된 유일한 공개 범위**다 — v0.1에 있던 "팀 전체 공개 기본값 + 개인 토글" 방식은 폐기
- 마이 탭 "하이라이트 / 메모"에서 모아보기

### 4.10 AI 요약

**목표**: 글이 등록(또는 자동 수집)되면 AI가 본문을 분석해 4.5의 3가지 관점(문제/해결/디자이너·PM 관점)으로 구조화된 요약을 자동 생성한다.

- **트리거 시점**: 팀원 등록 직후 또는 자동 수집 직후 서버에서 비동기로 생성
- **출력 스키마(제안)**: `{ "problem": "...", "solution": "...", "designerPmTakeaway": "...", "keywords": ["...", "..."] }`
- Gemini(요약)·Groq(하이라이트 구간 쉬운 설명) 조합은 v0.1 6.2 기술 방안을 그대로 따른다 (7장 참조)

### 4.11 콘텐츠 소싱 — 자동 수집(크롤링) + 팀원 수동 등록

- 마이 탭에 "크롤링한 글"이 노출되는 것에서 알 수 있듯, **자동 수집 파이프라인은 계속 유지**된다
- **대상 기업 선정 기준(확정)**: 꾸준히 콘텐츠를 올리는 기업만 선정 — 특정 기업 목록을 고정하기보다 게시 빈도를 기준으로 선정/제외
- **수집 범위(확정)**: 2025년 7월 1일 이후 발행된 글만 수집 대상
- 세부 수집 방식(RSS 폴링 주기 등)은 v0.1 6.3의 기술 방향을 유지하되, 실제 대상 기업 목록은 위 기준에 따라 팀이 확정

## 5. 대표 사용자 플로우 (User Flow)

### 5.1 글 등록 → 독후감 작성 플로우
```
[홈 또는 피드] → [+ 글 등록]
  → URL 입력 → 메타데이터 자동 추출(제목/썸네일/기업/발행일)
     → 이미 등록/수집된 글이면 기존 글로 안내
  → 독후감 작성: 인상 깊은 부분 / 접목하고 싶은 방법 / 질문·토론하고 싶은 것
  → 등록 완료 → (비동기) AI 요약 생성(문제/해결/디자이너·PM 관점)
  → 등록한 독후감이 [토론] 탭에 노출됨
```

### 5.2 토론 참여 플로우
```
[토론 탭] → 독후감 목록 확인
  → 관심 있는 독후감 선택
  → 댓글로 의견/질문 남기기
  → 독후감 작성자에게 "내 독후감의 댓글" 알림 발송
  → (대댓글 발생 시 "대댓글" 알림 발송)
```

### 5.3 글 읽기 → 하이라이트/메모 플로우
```
[홈 또는 피드에서 글 선택] → [글 상세]
  → AI 요약(문제/해결/디자이너·PM 관점) 먼저 확인
  → 본문 읽던 중 인상 깊거나 어려운 문장 드래그 → 하이라이트
  → 그 구간에 개인 메모 남기기(나만 보기)
  → 의견 남기기 → 다른 팀원의 댓글 확인
```

### 5.4 홈 → 검색 플로우
```
[홈] → 기업 칩 선택(다중 선택) 또는 추천 글 확인
  → 기업 칩 클릭 시 [피드]로 이동해 해당 기업 글만 필터링
[검색] → 최근/추천(질문형)/급상승 검색어 확인 → 검색 실행 → 결과에서 글 선택
```

### 5.5 마이페이지 확인 플로우
```
[마이 탭] → 임시저장 / 내 글(독후감 기준) / 내 댓글 / 북마크 / 하이라이트·메모 / 읽은 아티클 탭 전환
  → 목록에서 글 선택 → 글 상세로 이동
```

## 7. 기술 스택 및 AI 연동 제안

### 7.1 전체 스택 방향
- **Frontend**: Next.js(App Router) 기반 웹 우선 출시
- **Backend/DB**: Supabase (Auth, DB, RLS 기반 접근 제어)
- **인증(확정)**: **구글 로그인만 지원** — v0.1의 "초대 코드 + 이메일/소셜 로그인" 방침은 폐기하고 구글 로그인 단일 방식으로 단순화
- **메타데이터 추출**: URL의 오픈그래프 태그 파싱, 실패 시 수동 입력 폴백
- **자동 수집(크롤링) 배치**: 꾸준히 콘텐츠를 올리는 기업의 RSS/Atom 피드를 폴링하는 스케줄러. 2025-07-01 이후 발행 글만 수집 대상

### 7.2 AI 요약/설명 파이프라인
- **AI 요약(Gemini)**: 등록/수집 직후 비동기로 문제/해결/디자이너·PM 관점 3항목 구조화 요약 생성
- **하이라이트 구간 쉬운 설명(Groq)**: 사용자가 드래그한 짧은 텍스트에 한해 실시간 응답
- 두 제공사 모두 무료 한도 초과 가능성이 있으므로, 초과 시 에러 안내 처리(`FEATURE_AI_FALLBACK` 플래그로 폴백 전환 여부 관리, SCOPE.md 참조)
- 본문 추출(리더빌리티 라이브러리) → 청킹 → JSON 스키마 강제 출력 → 캐싱(URL/본문 해시 기준 중복 호출 방지)의 기본 파이프라인은 v0.1 6.2.2 방향을 유지

### 7.3 크롤링/메타데이터 유의사항
- 대상 기업의 `robots.txt` 및 이용약관을 확인해 허용 범위 내에서만 수집
- 가능한 경우 공식 RSS/Atom 피드를 우선 사용
- 대상 기업은 게시 빈도 기준으로 선정되므로, 신규 기업 편입/기존 기업 제외를 주기적으로 재평가하는 운영 프로세스 필요

## 8. 비기능 요구사항

- **권한/보안**: 팀 전용 클로즈드 서비스. 구글 로그인 사용자만 접근 가능. 글/댓글 삭제는 작성자 본인 또는 관리자만 가능
- **하이라이트/메모 공개 범위(확정)**: 개인 전용(나만 보기) — 팀 공개 옵션 없음
- **성능**: AI 요약은 비동기 처리(등록 즉시 사용자를 기다리게 하지 않음)
- **알림**: 좋아요한 기업의 새 글 / 내 독후감의 댓글 / 대댓글 — 인앱 알림 기본
- **접근성**: 하이라이트 색상은 색약 사용자도 구분 가능하도록 색상+아이콘 병행 고려

## 9. MVP 범위 제안

1. 하단 탭바(홈/피드/토론/검색/마이) 골격
2. 구글 로그인
3. 자동 수집(크롤링) — 꾸준히 올리는 기업 대상, 2025-07-01 이후 글만
4. URL 등록 + 독후감 작성(인상 깊은 부분/접목하고 싶은 방법/질문·토론 주제) + 중복 방지
5. 글 상세: 의견/댓글 + AI 요약(문제/해결/디자이너·PM 관점) + 키워드 태그
6. 하이라이트 + 개인 메모(나만 보기)
7. **토론 탭**: 독후감 목록 노출(인기/최신/추천 + 카테고리 필터) + 댓글 + 가벼운 참여 토글(참여 인원 표시)
8. 검색: 최근/추천(질문형)/급상승 검색어
9. 마이: 임시저장/내 글(독후감 기준)/내 댓글/북마크/하이라이트·메모/읽은 아티클
10. 알림: 좋아요 기업 새 글/내 독후감 댓글/대댓글

**MVP 이후 고려**
- 피드 기업 칩 과다 문제 해결 후 고도화
- 검색 고도화(태그/기업/작성자 복합 필터)
- 컬렉션(주제별 글 모음)

- **디자인**: 독서 리뷰 앱 "사락(sarak)" 캡처를 레퍼런스로 한 공통 디자인 시스템(DESIGN.md, `.claude/rules/design-system.md`)을 도입 — 토큰(컬러/라운드/타이포)·공통 컴포넌트 패턴을 팀 전체가 공유한다(2026-08-18, 기존 "각자 진행" 방침에서 전환)
