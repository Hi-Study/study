# 디자인 시스템 (v0.2 — 코드 반영 완료)

- 레퍼런스: 독서 리뷰 앱 "사락(sarak)" — 홈/탐색, 독서모임, 독서노트, 나의 사락, 통합검색, 도서 상세(리뷰/밑줄) 캡처
- 작성 배경: [PRD](../테크블로그_아카이빙_서비스_PRD_1.md) 10.1 "디자인: 각자 진행 — 통일된 디자인 시스템 없음", 10.2 "개별 디자인 진행 시 화면 간 일관성을 어떻게 맞출지" 오픈 이슈에 대한 답
- 목적: 팀원이 화면을 각자 만들어도 톤·컴포넌트가 어긋나지 않도록, **토큰 + 화면별 패턴 매핑표**를 공통 기준으로 둔다
- 우리 서비스 IA(하단 5탭: 홈/피드/토론/검색/마이 + 글 상세/글 등록)는 사락의 IA(홈/독서노트/독서모임/나의 사락 + 도서 상세)와 탭 구조가 거의 동형이라, 화면 단위로 그대로 대응시킬 수 있다.
- **v0.2 변경 요약**: v0.1은 문서만 있었고 코드에는 반영되지 않은 상태였다. v0.2에서 실제 사용성 문제(폰트 로딩, 중복 헤딩, 하드코딩 색상, 탭마다 따로 있던 글쓰기 진입점 등)를 함께 점검해 5장 체크리스트를 실제 코드에 반영했다. 세부 변경 이력은 7장 참고.

## 1. 디자인 원칙 (사락 캡처에서 읽은 톤)

1. **플랫 + 라운드**: 그림자를 거의 안 쓰고, 카드 사이는 얇은 회색 구분선(divider)로 나눈다. 둥근 모서리(카드/이미지)와 완전한 알약형(pill, 버튼/칩/배지)을 함께 쓴다.
2. **행동은 알약형, 콘텐츠는 카드형**: 버튼·필터칩·상태선택(읽고싶어요 ▾)은 `rounded-full`. 썸네일·카드·AI 요약박스는 `rounded-xl`~`rounded-2xl`.
3. **색은 절제, 포인트만 원색**: 배경은 흰색, 텍스트는 그레이 스케일. 컬러는 배지/CTA/그래프 등 "지금 눈에 띄어야 하는 요소"에만 쓴다.
4. **숫자를 크게, 근거는 옆에 작게**: 별점 "9.7"처럼 핵심 수치는 크고 굵게, 그 옆에 근거(평가 46명)를 작은 회색 텍스트로 붙인다. 통계/요약 카드에서 반복되는 패턴.
5. **빈 상태는 짧은 문장 + 단일 CTA**: 로그인 안 된 탭(독서노트/나의 사락)은 안내문 1~2줄 + 검정 알약 버튼(로그인) 하나만 놓는다. 장식 없이 깔끔하게.

## 2. 토큰

기존 `app/globals.css`의 CSS 변수(HSL) 체계를 그대로 따르되, 사락 캡처에서만 보이고 현재 팔레트에 없는 강조색 2종을 추가한다.

### 2.1 색상 — 기존 유지

| 토큰 | 현재 값 | 용도 |
|---|---|---|
| `--primary` | `217 91% 60%` (블루) | 사락의 메인 블루(선택된 칩, 별점 채움, 탭 밑줄)와 근사치라 **그대로 재사용** |
| `--secondary`, `--muted` | 그레이 | 보조 배지, 캡션 텍스트 |
| `--accent` | 옅은 블루 | AI 요약 박스 배경으로 이미 적합 |
| `--destructive` | 레드 | 삭제/에러 |
| `--radius` | `0.9rem` | 카드 라운드 기준값, 유지 |

### 2.2 색상 — 신규 추가 제안

사락 캡처 기준 근사치다(실 스크린샷 스포이드 값 아님 — 적용 시 팀 톤에 맞게 보정).

| 신규 토큰 | 근사 HSL | 참고 캡처 | 우리 서비스 용도 |
|---|---|---|---|
| `--featured` | `45 93% 58%` (앰버/골드) | "주간 우수", "리뷰어클럽", "우수 모임" 배지, 프로모 배너(크림톤) | 인기글/추천글 배지, 공지 배너 |
| `--featured-foreground` | `20 40% 20%` | 위 배지 텍스트 | — |
| `--highlight` | `330 75% 65%` (핫핑크/마젠타) | "밑줄" 탭 히스토그램, `p.10` 페이지 배지 | 하이라이트/메모 관련 UI 전용 포인트색 |
| `--highlight-foreground` | `0 0% 100%` | 위 배지 텍스트 | — |

`tailwind.config.ts`의 `colors` 확장에 `featured`, `highlight`를 `card`/`accent`와 같은 패턴(`DEFAULT` + `foreground`)으로 추가하면 기존 컨벤션과 맞는다.

### 2.3 반경(Radius) — 용도별로 분리해서 쓴다

| 용도 | 반경 | 캡처 근거 |
|---|---|---|
| CTA 버튼, 필터 칩, 상태 드롭다운 알약(읽고싶어요 ▾), 배지 | `rounded-full` | 사락 전 화면의 버튼·칩이 전부 완전 알약형 |
| 카드, 썸네일, AI 요약 박스, 프로모 배너 | `rounded-xl` (`1rem`) ~ `rounded-2xl` | 도서 커버, 모임 카드, AI 요약 박스 |
| 리스트형 아이템(피드 행, 검색 결과 행) | 없음 + `border-b` 구분선 | 카드가 아니라 목록이므로 라운드 대신 얇은 divider |

> 현재 `components/ui/button.tsx`, `badge.tsx`는 `rounded-md`(약 12.4px)만 쓴다 → CTA/칩용으로 `rounded-full` variant를 추가하는 게 이번 시스템의 핵심 변경점.

### 2.4 타이포그래피

**v0.2에서 변경**: 기존엔 `globals.css`에서 `@import url("https://cdn.jsdelivr.net/.../WantedSansVariable.min.css")`로 Wanted Sans를 CDN에서 불러왔다. 이 방식은 (1) CSS 파싱 전에 외부 요청이 하나 더 끼어드는 렌더링 블로킹 리소스라 첫 페인트가 느려지고, (2) `font-display` 제어가 안 돼 폰트 로딩 중 텍스트가 안 보이거나(FOIT) 스타일이 튀는(FOUT) 현상이 있었고, (3) jsdelivr가 느리거나 막히면 폰트 자체가 아예 안 뜨는 외부 의존성 문제가 있었다. **Pretendard Variable로 교체하고 `next/font/local`로 자체 호스팅**했다(`app/fonts.ts`) — 국내 프로덕트에서 가장 널리 검증된 UI 서체 중 하나이고, 기존 fallback 체인에도 이미 2순위로 들어 있던 폰트라 실제 화면 톤 변화는 크지 않으면서 로딩 안정성만 확보했다. `font-display: swap` + Next.js 빌드 시 자체 서빙이라 외부 요청 자체가 사라진다.

스케일:

| 레벨 | 크기/굵기 | 예시 |
|---|---|---|
| 통계 강조 숫자 | 28~32px bold | "9.7", "50%" |
| 섹션 타이틀 | 18~20px bold | "사락 PICK", "독서모임" |
| 카드/리스트 제목 | 15~16px semibold | 글 제목 |
| 본문/설명 | 14px regular, `line-clamp-2` | 2줄 요약 |
| 캡션/메타 | 12~13px, `text-muted-foreground` | 작성자·날짜·구분점(·) |

### 2.5 간격

- 섹션 간 세로 여백: `py-8`(32px)
- 카드 내부 패딩: `p-4`(16px)
- 리스트 행: `p-4` + `border-b`, 좌우 아이콘은 `gap-3`

## 4. 화면별 매핑 — 사락 → 우리 서비스

| 사락 화면(캡처) | 우리 서비스 화면 | 가져올 패턴 |
|---|---|---|
| 홈/탐색 — "사락 PICK" 2열 카드 그리드 + 프로모 배너 | **홈** (4.1, 상단 추천글/중단 기업칩/하단 기업별 스와이프) | 프로모 배너(공지), 배지 오버레이 카드, 필터 칩 로우 |
| 피드(리뷰 리스트) — 목록형 카드(썸네일+제목+메타+좋아요/댓글) | **피드** (4.2, 전체 글 최신순) | 리스트 행 패턴 그대로 → `article-card.tsx` 리디자인에 직접 사용 |
| 도서 상세 — AI 리뷰 요약 박스("AI가 리뷰를 요약했어요!" + 도움됐어요 👍👎) | **글 상세 AI 요약** (4.5, 4.10 — 문제/해결/디자이너·PM 관점) | **거의 1:1 재사용.** AI 뱃지 원형 + 굵은 타이틀 + 하단 피드백 버튼(👍👎) 구조를 그대로, 3항목만 세로로 펼치면 됨 |
| 도서 상세 — 밑줄 탭(페이지 배지 `p.10` + 인용문 + 좋아요/댓글/북마크) | **하이라이트 + 개인 메모** (4.9) | 페이지 배지 → 문단 위치 배지로 변경, 인용문 스타일(따옴표+들여쓰기) 그대로, `--highlight` 포인트색 적용 |
| 도서 상세 — 별점 분포 막대그래프 | (선택) 사용 안 함 — 우리 서비스엔 별점 없음 | 미적용 |
| 도서 상세 — 상태 드롭다운 알약(+ 읽고싶어요 ▾) | 북마크/읽음 상태 토글 | `rounded-full` 드롭다운 버튼 |
| 독서모임 — 이벤트 카드(배너+배지+날짜/장소/인원 아이콘 행) | **토론 탭 독후감 카드** (4.6) | 아이콘+텍스트 메타 행(날짜 대신 기업/발행일, 인원 대신 댓글 수) 구조만 차용, 배너는 미적용 |
| 독서노트 — 목표 카드(퍼센트 크게) + 미니 캘린더 | (선택) 마이 탭에 "이번 주 읽은 글 N개" 같은 요약 카드로 변형 가능 | 우선순위 낮음, MVP 이후 고려 |
| 나의 사락 — 커버+아바타 오버랩, 통계 행(팔로워/팔로잉/읽은 책), 원형 아이콘 버튼 행 | **마이** (4.8: 임시저장/내 글/내 댓글/북마크/하이라이트·메모/읽은 아티클) | 통계 행 → "등록한 글 · 댓글 · 북마크" 카운터로 변형. 원형 아이콘 버튼 행(4개) → 마이 탭 6개 섹션 진입점을 아이콘+라벨 그리드로 배치 |
| 통합검색 — 검색창 + 최근검색어(전체삭제) + "요즘 리뷰 많은 책" 리스트 | **검색** (4.7: 최근/추천(질문형)/급상승 검색어) | 구조 거의 동일. "요즘 리뷰 많은 책" 자리에 "급상승 검색어"를 리스트가 아닌 텍스트 태그 리스트로 대체 |

## 6. 이 문서를 쓰는 법

- 새 화면을 만들 때: 4장 매핑표에서 대응 화면을 찾고 → 2장 토큰과 3장 공통 패턴만 조합해서 구성한다. 새로운 색/모양이 필요하면 이 문서에 먼저 추가하고 코드에 반영한다.
- `.claude/rules/design-system.md`에 핵심 규칙만 요약해 AI 코딩 시에도 자동으로 참조되게 해둔다.
- **이 문서를 고치고 코드에 맞춰 반영하고 싶을 때**: Claude Code에서 `/sync-design`을 실행한다 — 이 문서와 실제 코드(토큰·컴포넌트·화면)를 비교해 달라진 부분만 반영하고, 5장 체크리스트와 7장 변경 이력을 갱신한다. 자세한 동작은 `.claude/commands/sync-design.md` 참고.
