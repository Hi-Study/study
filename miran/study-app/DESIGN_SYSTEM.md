# distill 디자인 시스템 (DESIGN_SYSTEM.md)

> 이 문서는 **어떻게 보이는가**만 다룬다. 어떤 기능이 있고 무엇은 안 하는지는
> **`PRODUCT.md`** 가 정본이다.

이 문서는 앱 전체의 **시각 언어(비주얼) 정본**입니다. 값은 전부 `src/theme/*` 와 화면 코드에서
가져온 **현재 값**입니다. 문서와 코드가 어긋나면 **코드가 맞습니다** — 이 문서를 고치세요.

> **불변 규칙 1 — 색은 토큰으로만.** 하드코딩 hex 금지(예외: 흰색 `#fff` 같은 극소수).
> **불변 규칙 2 — 원문에 덧붙이기만.** 글 상세의 읽기 가이드(읽기 전 / 흐름 / 읽고 나서)는
> 원문 위에 얹는 **층**입니다. 원문의 **순서·문장을 바꾸지 않습니다.** 가이드가 없거나
> 생성에 실패해도 화면은 예전 모습(본문 통짜 + AI 요약)으로 그대로 떠야 합니다.

## 0. 디자인 원칙
1. **한 번에 하나에 집중** — 화면당 강조 요소 1개. 나머지는 조용하게(중립색).
2. **여백이 위계다** — 섹션 사이 14~20, 카드 안 14~16, 글 본문 좌우 20.
3. **부드러운 라운드** — 카드 16, 큰 시트 20(상단만), 칩 pill(999). 날카로운 모서리 없음.
4. **강조는 절제** — **바이올렛 1색** + 주제 파스텔. 카드 한 장에서 색을 갖는 건 주제 칩 하나뿐.
5. **스캔 가능** — 섹션 헤더(친근한 문장) → 가로 캐러셀/리스트. 카드로 끊어 읽기.
6. **건너뛸 자유를 준다** — 접힌 것도 제목과 한 줄 안내는 보인다. 접힘 ≠ 숨김.

## 2. 타이포그래피
Pretendard 를 **굵기별로 번들**한다(`theme/fonts.ts`). RN 커스텀 폰트는 `fontWeight` 에
반응하지 않으므로 **스타일마다 `fontFamily` 를 함께 준다**(`pretendard(weight)` / `PRETENDARD[...]`).
빠뜨리면 그 글자만 시스템 폰트로 떨어져 화면이 섞여 보인다.

### 2.1 UI 스케일 `dtype` (`theme/distill.ts`)
| 토큰 | size / line / weight | 용도 |
|---|---|---|
| display | 28 / 38 / 800 | 인사말·화면 대제목 |
| titleL | 22 / 30 / 700 | 글 상세 제목·히어로 |
| title | 18 / 26 / 700 | 섹션 헤더 |
| cardTitle | 16 / 23 / 600 | 카드 제목·버튼 글자 |
| body | 15 / 24 / 400 | 카드 본문 |
| bodyS | 13.5 / 20 / 400 | 보조 본문·부제 |
| meta | 12 / 17 / 500 | 날짜·수치 메타 |
| label | 12 / 20 / 700 | 칩·배지·작은 액션 |

> **lineHeight 는 fontSize 의 1.35배 이상.** 안드로이드 RN 은 lineHeight 를 줄 높이 상한으로
> 강제해서 빠듯하면 한글이 잘린다. 호출부가 `{...dtype.label, fontSize: 14}` 처럼 **크기만**
> 덮어쓰는 일이 많으니 큰 쪽을 기준으로 여유를 둔다.

### 2.2 장문 조판 `reading` (본문 전용 — dtype 과 분리)
`para 17/30/-0.3` · `heading 19/28/-0.4(800)` · `list 17/29/-0.3`
`blockGap 20` · `headingTop 28` · `pagePadding 20` · `listIndent 16`

좌우 20 + 17px = 한 줄 19~20자(한글 장문 최적 18~24자). **lineHeight 는 1.7배 이상** —
카드용 1.35 규칙보다 강하다.

### 2.3 참고
`theme/tokens.ts` 의 `typeScale · spacing · radius` 는 웹 디자인시스템 CSS 에서 옮겨온 값으로
**distill 화면에서는 쓰지 않는다**(현재 사용처 0). 화면은 `dtype` / `reading` 과 아래 §3 의 숫자를 직접 쓴다.

## 3. 간격·라운드·그림자
- **간격**: 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24. 화면 좌우 패딩 **16**(글 본문만 **20**).
  세로 간격은 컨테이너의 **`gap` 하나로만** 준다 — 요소마다 marginBottom 을 달면 새 요소를 넣을 때 빠뜨린다.
- **라운드**: 카드·타일 **16**, 큰 카드(완독률·캘린더) **18**, 바텀시트 **20**(상단만),
  칩/배지/진행바 **999**, 버튼·입력·검색바 **12**, 리스트 행 썸네일 **12**, 그리드 카드 **14**,
  아이콘 타일 **10~11**, 태그 칩 **8**.
- **그림자는 카드 위로 뜨는 것만** — 플로팅 pill(이어읽기):
  `shadowColor #000, opacity 0.2, radius 6, offset (0,2), elevation 5`.
  일반 카드는 그림자 대신 **1px hairline 보더**(플랫·깔끔).

## 4. 핵심 컴포넌트

### 4.1 아이콘 그리드 (기업별로 모아보기)
- **카드 없이** 파비콘 + 이름만. 2행 가로 스와이프. 셀 폭 `(W-32)/5.4`, 높이 72(다음 칸 살짝 노출 → 스와이프 유도).
- 아이콘 38, 이름 `11.5/16/700`, 1줄 말줄임, 그리드 gap 8.
- ⚠️ 가로 스크롤 안에서 2줄을 만들려면 **세로로 감아야** 한다:
  `flexDirection: "column"` + `flexWrap: "wrap"` + **고정 높이**(`CELL_H*2 + 6`).
  `row + wrap` 은 **폭**을 기준으로 감기는데 가로 스크롤 안에는 폭 제한이 없어서,
  `maxHeight` 를 줘도 `height` 를 줘도 스무 곳이 한 줄로 늘어섰다.
  세로로 감으므로 순서는 ①② / ③④ … **위아래가 먼저**다.
- ⚠️ 셀은 `alignItems: "flex-start"` — 가운데 정렬이면 첫 아이콘이 섹션 제목보다 안쪽으로
  밀려 보인다. **아이콘 왼쪽 끝이 제목 첫 글자와 같은 선**에 서야 한다.

### 4.2 칩 · 배지
- **주제 칩**: `paddingH 8, paddingV 3, radius 999`, 글자 `dtype.label`, tint 배경 + color 글자.
- **난이도 배지**: 같은 규격, `surfaceSunken` 배경 + `textSecondary` 글자(색 없음).
  라벨은 "누구나 이해 가능 / 기초 개발지식 필요 / 개발지식 필요".
- **필터 칩(가로 스크롤)**: pill, 미선택 `surfaceCard + hairline` / 선택 `primaryTint + primary`.
  (아카이브 상세의 읽음 필터만 선택 시 `textPrimary` 로 채운다 — 그 줄에 보라를 또 쓰지 않으려고.)
- **태그**: `#태그`, `surfaceSunken` 배경, radius 8, `paddingH 9 / paddingV 4`. 글 상세에선 6개까지.

### 4.3 아티클 카드 — 4형태
| 형태 | 규격 |
|---|---|
| `FeaturedCard` | radius 16, 보더 1, 썸네일 `aspectRatio 2` |
| `ArticleCardH` (가로 캐러셀) | radius 16, 보더 1, 썸네일 16:9 |
| `ArticleRow` (리스트 행) | 썸네일 **156×104 고정(3:2 가로형)** radius 12 + 글 블록도 같은 104 고정, 위아래 16 |
| `ArticleGridCard` (2열) | radius 14, 썸네일 16:9, 폭 `(W-32-12)/2` |

- 구성: [주제칩 · 난이도 배지 · **읽음 배지**] → 제목(`cardTitle`, 2줄)
  → 메타 줄(출처 로고 18~24 · 날짜 · **기획자 N** · 조회·인사이트 수).
  **읽기시간은 붙이지 않는다.**
- **모든 행이 같은 크기다.** 썸네일과 글 블록을 **둘 다 104 로 못 박고**(`rowText` 에 `height`),
  남는 자리는 `justifyContent: "space-between"` 이 메타 줄을 바닥에 붙인다.
  제목이 한 줄인 글과 두 줄인 글이 섞여도 행이 흔들리지 않는다 — 목록은 크기가 같아야 훑어진다.
- 행 위아래 여백은 **16**. 12 였을 때 행 사이가 24px 밖에 안 떠서 목록이 뭉쳐 보였다.
- **제목은 네 형태 모두 2줄 자리를 늘 차지한다**(`minHeight = lineHeight × 2`), 넘치면 말줄임.
  `numberOfLines` 만 주면 한 줄짜리 제목에서 카드가 한 줄만큼 짧아져, 나란히 놓인 카드들의
  아래 줄이 어긋난다. 목록은 **줄이 맞아야** 훑어진다.
- **출처는 로고 + 이름**으로 메타 줄에 늘 붙는다(`ServiceLogo 18~24`). 이름만 있으면
  어느 회사 글인지 한 박자 늦게 읽힌다.
- **피드와 마이 "읽음" 탭은 같은 `ArticleRow` 를 쓴다** — 목록 규격을 한 곳에서만 고치면 되게.
- **썸네일은 3:2 가로형.** 기술 블로그 대표 이미지는 거의 다 가로형이라,
  정사각으로 담으면 양옆이 잘려 무슨 그림인지 알 수 없게 된다.
- **"~한 사례" 한 줄(`ImprovementLine`)은 카드에서 뺐다.** 결정 카드가 있는 글에만 붙어서,
  있는 글과 없는 글이 섞이면 높이가 제각각이 됐다. 기업별 목록의 "개선 사례" 묶음을 **고르는
  기준**으로는 `lib/improvement.ts` 가 그대로 남아 있다(화면에 문장을 그리지 않을 뿐).
- **읽음 배지**(`Check 10` + "읽음", `surfaceSunken`, radius 999, `paddingH 7 / paddingV 3`,
  `label 11`): 이미 본 글을 목록에서 지나칠 수 있어야 한다.
  **카드를 통째로 흐리게 만들지 않는다** — 흐린 카드는 "읽었다"가 아니라 "못 누른다"로 읽히고,
  읽은 글을 다시 찾으러 온 사람에게는 오히려 방해가 된다. 제목은 그대로 두고 표시만 붙인다.
- **"기획자 N"은 메타 줄 안에 있다.** 예전엔 제목 아래 독립된 줄이었는데, 있는 글과 없는 글이
  섞여 카드 높이가 들쭉날쭉했다. 늘 있는 메타 줄로 들여보내면 있든 없든 높이가 변하지 않는다.
- 썸네일이 없으면 **브랜드 로고로 채운다**(빈칸 금지).

### 4.4 섹션 헤더
제목(`dtype.title`) + 선택 부제(`bodyS`, muted), 우측 "더보기 ›". **친근한 문장형 타이틀.**

### 4.5 바텀시트 / 드롭다운
- 바텀시트: 하단 정렬, 상단만 radius 20, `paddingH 16 / paddingTop 8 / paddingBottom 28`,
  `maxHeight 72%`, 상단 그립 40×4(radius 2), 백드롭 `rgba(0,0,0,0.35)`.
- 드롭다운(아카이브 전환 등): 카드 radius 14 + hairline, 행 `paddingH 14 / paddingV 11`.

### 4.6 탭
- **하단 탭(4개)**: 홈 · 피드 · 아카이브 · 마이.
  아이콘 `Home / LayoutGrid / FolderOpen / User`(lucide).
  높이 **70**, paddingTop 8, paddingBottom 12, 라벨 `11.5/600`,
  활성 `primary` · 비활성 `textMuted`, 배경 `surfaceNav` + 상단 hairline.
  **검색은 탭이 아니라 상단 유틸 아이콘.**
- **글 상세에는 세그먼트 탭이 없다.** 인사이트는 하단 플로팅에서 시트로 연다(§4.11).
  남의 인사이트를 모아 보는 탭도 없다 — 인사이트는 그 글 안에서만 읽고 남긴다.
- **마이 세그먼트("내 활동")**: pill 5개(내 인사이트·하이라이트·댓글·읽음·단어장), 가로 스크롤.
  활성 `primary` 배경 + `actionOn` 글자 / 비활성 `surfaceSunken` + `textSecondary`.

### 4.7 버튼 · 입력
- 주요 버튼: `primary` 배경 + `actionOn` 글자, radius 12, paddingV 14~15, `dtype.cardTitle`.
- 보조 버튼: `surfaceCard` + hairline 보더, radius 12, paddingV 11~12.
- 만들기 흐름의 제출 버튼만 `textPrimary` 배경(비활성 `surfaceSunken` + `textMuted`).
- 검색바/입력: radius 12, `paddingH 12~14 / paddingV 11~12`, 좌측 아이콘 16~18.
- 플로팅 뒤로가기: 40 원형, `surfaceCard` + hairline.
  **FAB 은 없다** — 글을 직접 등록하는 입구를 걷어냈고, 글은 수집 배치로만 들어온다.

### 4.8 아바타 · 로고
- 아바타: 이름 해시 배경 `hsl(h,34%,44%)`, 원형.
- 워드마크: 소문자 `distill` + **바이올렛 마침표**. `fontSize 20 / weight 800 / letterSpacing -0.4`.
- 서비스 로고: 브랜드 파비콘(`brandIcon.ts`), 실패 시 브랜드색 + 이니셜.

### 4.9 상태(빈/로딩/에러)
로딩 `Loading("불러오는 중…")` · 빈 `EmptyState(title + hint)` · 에러 `ErrorState(재시도)`.
**조건부 섹션**: 데이터가 없으면 섹션 자체를 숨긴다. **0 을 보여주지 않는다**(숫자가 벌칙처럼 읽힌다).

### 4.10 읽기 다이제스트 `ReadingDigest` (= 본문)
글 상세의 본체. **원문을 재배열하지 않는다** — 원문은 원문 보기(웹뷰)가 맡고,
여기는 "1분 안에 무슨 일이 있었는지"를 뉴스 다이제스트처럼 세 덩어리로 세운다.
바깥 `gap 22`, `fontScale`(가/가 토글)이 세 덩어리에 모두 먹는다.

| | 덩어리 | 규격 |
|---|---|---|
| ① | **알아두면 편해요** | `primaryTint` + `accentTintBorder` 카드, radius 16, padding 16, gap 10. 헤더 `BookOpen 15` + 라벨(`label 12.5`, primary). 행마다 용어명(`cardTitle 14.5`) + 쉬운 말(`bodyS/21`). **최대 8개.** |
| ② | **한눈에** | 헤더(`title`) + `1분 파악` 칩. 카드 하나 안에 **질문 3줄**: `무슨 일이에요?` / `왜 했대요?` / `그래서 뭐가 달라졌어요?`. 질문 `label 12.5`(primary) + 답 `15.5/26`. 줄 사이는 `dividerSoft` 1px. |
| ③ | **기획 포인트** | `primaryTint` + `accentTintBorder` 카드, radius 16, padding 16, gap 8. 헤더 `Compass 15` + 라벨(primary) + 본문(`15/25`). **비어 있으면 숨긴다.** |
| ④ | **더 들어가 볼까요?** | 카드마다 **질문형 소제목**(`cardTitle 16/24`) + 답 문단 2~3개(`14.5/24`). 없으면 덩어리째 숨긴다. |

**시간순 한 줄 나열(v2)을 버렸다.** 실제로 나온 줄이 "원천 데이터에 메타데이터를 붙여
임베딩을 만든다" 같은 것이었다 — 개발자가 한 일의 순서일 뿐이다. 읽는 사람이 묻는 건 늘 셋이다:
무슨 일이야, 왜 했대, 그래서 뭐가 달라졌어. 그래서 **질문을 화면에 글자로 적어둔다** —
답만 있으면 무엇에 대한 답인지 읽는 사람이 스스로 맞춰야 하고, 그 순간 다시 어려운 글이 된다.

- **③ 기획 포인트는 ② 와 다른 것을 말한다.** `그래서 뭐가 달라졌어요?` 는 *그 팀에게* 뭐가
  달라졌는지다. 기획 포인트는 **읽는 사람에게** 무엇이 남는지다 — "파악했다"와
  "내 일에 쓸 수 있다" 사이가 이 한 칸이다.
  ⚠️ **AI 가 가장 지어내기 쉬운 칸이다.** 원문에 그 팀이 무엇을 확인·비교·선택했는지가
  없으면 서버가 빈 문자열로 보내고, 화면은 그리지 않는다. 억지 교훈보다 빈 자리가 낫다.
  게이트가 떨어뜨리는 것(전부 실측에서 나온 것):
  - 20자 미만 — "참고할 만해요"는 아무것도 말하지 않는다.
  - "~참고하면 ~이해할 수 있습니다" 류 — 글을 읽으라는 말의 반복이다.
  - `soWhat` 과 2글자 묶음이 **60% 넘게 겹치는 문장** — 바로 위 칸을 바꿔 쓴 것이라 한 칸을 버린다.
  - 원문에 없는 숫자.
  프롬프트도 "교훈을 써라"가 아니라 **"이 팀이 실제로 확인한 것 + 비슷한 상황이면 같은 것을
  확인해 보라"**로 잡는다. 교훈을 요구하면 모델이 빈 문자열로 도망가거나 상투어를 쓴다.
- **용어는 최대 8개.** 4개로 막아 뒀더니 비개발자가 실제로 막히는 말이 줄줄이 빠졌다.
  영어 약어(OOM·API·TPS) · 업계 은어(배치·워커·파티션) 뿐 아니라
  **한국어인데 이 분야에서 다른 뜻으로 쓰는 말**(적재·정산·동기화·롤백)을 반드시 포함한다 —
  한국어라 쉬워 보여서 예전 규칙("개발 용어만")에 걸려 빠졌는데, 제일 많이 막히는 종류다.
- **④ 의 소제목은 ② 를 파고드는 질문이어야 한다.** 예전엔 "컨텍스트 엔지니어링" 같은
  새 개념이 갑자기 소제목으로 올라와, 원문을 안 본 사람은 거기서 길을 잃었다.
  서버 게이트가 **물음표로 끝나지 않는 소제목을 통째로 탈락**시킨다.
- **원문 펼치기**: 소제목 카드 아래 `원문에서 확인 ▾`(`label 12`, primary, 글자만).
  펼치면 **그 칸의 근거가 된 원문 덩어리가 그대로** 들어간다 — 왼쪽 막대 3px(`accentTintBorder`)
  + `surfaceSunken` 배경 + radius 12 + `paddingH 12 / paddingV 10`, 라벨 "원문"(`meta 10.5`),
  본문 `15/25`(`fontScale` 적용). **요약과 같은 모양으로 그리지 않는다** — 어느 쪽이 글쓴이의 말인지
  구별되어야 한다. 여러 칸을 동시에 펼 수 있다.
  - 가이드의 `block` 은 `bodyBlocks()` 배열의 **순번**이다. 앱과 엣지가 같은 방식으로 나눠야
    맞는 문단이 열린다 — 한쪽만 고치면 엉뚱한 문단이 펼쳐진다.
  - 원문 덩어리를 못 찾으면 **버튼 자체를 숨긴다.** 눌렀는데 아무 일도 안 일어나면 다음부터 아무도 안 누른다.
- **개발 용어 자동 밑줄**: 문장 안에서 `guide.terms` 의 용어에 `primary` 글자 +
  `accentTintBorder` 밑줄. 누르면 §4.5 시트에서 뜻이 뜬다(제목 `titleL 20` + 풀이 `body/25`).
  긴 용어부터 매칭한다 — 안 그러면 "AB 테스트"가 "AB"에서 잘린다(`splitByTerms`).
- **문장을 길게 눌러 단어를 고르게 하지 않는다.** 그건 *어떤 단어가 어려운지 아는 사람만*
  쓸 수 있는 방식이었다. 막힐 단어를 미리 골라 표시해둔다.
- 다이제스트가 없으면(생성 실패) 안내 카드 + **실패 이유**(`meta 11`) + `다시 시도` pill.
  조용히 넘어가지 않는다 — 며칠째 생성이 안 되고 있는 걸 아무도 몰랐던 적이 있다.
- **③ 의 답은 원문 전문을 읽고 쓴다(2단계 생성).** 1단계에서 근거 블록을 고르고,
  2단계에서 그 블록의 전문만 다시 보내 답을 쓴다. 1단계만 쓰던 때는 모델이 문단 앞
  140자만 봐서 소제목 답이 얕았다 — 화면 문제가 아니라 **모델이 읽은 양의 문제**였다.
- 저장된 가이드가 **옛 형식(v1 steps · v2 points)** 이면 `toReadingGuide` 가 null 을 준다.
  그게 맞다 — 화면은 "값이 있나"가 아니라 **"읽을 수 있나"**로 판단해 다시 만든다.

### 4.11 글 상세 전용 조각

- **히어로**(16:9): 이미지 + `rgba(0,0,0,0.45)` 스크림, 글자 영역 `padding 20 / gap 8`.
  제목 `22/30/800 #fff`(= `titleL` 크기), 그 아래 **한 줄 요약** `14/21/400 rgba(255,255,255,0.88)`.
  요약은 가이드 → `summary` → 본문 첫 문장 순으로 떨어진다(`summaryLine`) — **빈 채로 두지 않는다.**
- **메타 줄**: `[로고 20] 출처 · 게시일` + 우측 아이콘 32(담기 · 공유 · 가/가).
  날짜는 **게시일 그대로**(`2026. 9. 14.`) — "1개월 전"은 언제 글인지 알려주지 않는다.
- **원문 카드**: `surfaceCard` + hairline, radius 16, padding 18, 가운데 정렬.
  "원문을 보러 가볼까요?"(`cardTitle`) + 한 줄 안내(`bodyS`) + primary 버튼(radius 12, `paddingH 20 / paddingV 12`).
- **질문 카드**: `primaryTint` + `accentTintBorder`, radius 16, padding 16.
  라벨 "생각해볼 질문"(`label 12`, primary) + 질문(`cardTitle 16/25`). **질문만 둔다** — 답은 인사이트에서 받는다.
- **플로팅 액션 바**: 하단 고정 pill(radius 999, 보더 1, `paddingV 8`, 좌우 16, 바닥 12,
  그림자 §3). 3칸 균등(`flex 1`) — 인사이트 · 원문 보기 · 다음 글. 칸 사이 1px 세로 구분선(높이 26).
  아이콘 위 라벨 `meta 11`. **FAB(원형 하나)이 아니다** — 셋 다 같은 무게의 다음 행동이다.
- **인사이트 시트**: 플로팅의 "인사이트"를 누를 때만 §4.5 시트로 올라온다.
  머리(`title` + 닫기) → 남의 인사이트 목록 → 하단 primary "내 생각 남기기".
  **본문 아래에 깔지 않는다** — 다 읽고 나서 여는 것이지, 스크롤에 섞일 것이 아니다.

### 4.13 아카이브 타일 (그리드 2열)

### 4.14 담기 시트 `ArchivePickerSheet`
§4.5 시트 규격. "아카이브에 담기" + 힌트 "담으면 저장함에도 함께 들어가요".
행: radius 14 / padding 12 / gap 12, 아이콘 타일 34(radius 10, 아이콘 17), 이름 + "N개",
선택 시 `primaryTint` 배경 + `primary` 보더 + `Check 18`. 맨 아래 점선 "새 아카이브 만들기".
보관함이 하나도 없으면 목록 대신 **만들기 안내**를 보여준다(빈 목록은 길이 막힌 화면이다).

### 4.15 카드 크기 슬라이더 `SizeSlider`
**3단 눈금**(연속 슬라이더 아님): `0 리스트 · 1 그리드(2열) · 2 큰 카드`.
트랙 높이 28, 레일 4(radius 2, `surfaceSunken`), 채움 `primary`,
눈금 10 / 현재 눈금 손잡이 18(보더 3 `surfaceCard`). **탭과 드래그를 둘 다** 받는다.
라벨은 우측 정렬 `meta`. 처음 한 번만 뜨는 안내는 `primary` pill.

### 4.16 활동 스트립 `ActivityCalendar`
**한 주(7칸) 한 줄.** 한 달 그리드가 아니다 — 마이에서 달력이 답하는 질문은
"이번 달 며칠 읽었나"가 아니라 **"요즘 읽고 있나"** 하나이고, 그건 한 줄이면 된다.
한 달 그리드는 세로로 길어서 아래 활동 목록으로 가는 길을 매번 막았다.

- 카드: 보더 1 + radius 18 + padding 16 + gap 10. 선택적 `title`(`title`)은 카드 **밖 위**.
- 머리줄: `YYYY년 MM월`(`cardTitle`) + 우측 `‹ ›` 32(주 단위 이동).
  **다음 주로는 못 간다** — 오지 않은 날의 빈 줄을 보고 "안 읽었다"로 읽는다.
- 칸: 월~일 7등분, 요일(`11.5/16/700`, 오늘은 `primary`) 위 / 날짜 원 32 아래.
  활동일 = `primary` 채움 + `actionOn` 글자, 오늘인데 활동 없음 = `primary` 보더 1.5만,
  미래 = `textMuted`(누를 수 없다).
- 꼬리줄(`meta`): `9월 15일 – 21일 · 이번 주 4일 읽었어요`. 활동이 없으면 숫자 대신
  "글을 읽은 날이 여기에 쌓여요" — **0 을 보여주지 않는다.**
- 주가 달을 넘어가면 꼬리줄에 양쪽 달을 다 적는다(`9월 29일 – 10월 5일`).

### 4.17 대분류 섹션 (홈)
기준 v1 의 7칸(`TOPIC_ORDER` = **판단 순서**)이 **각각 자기 섹션**을 갖는다.
위에 그룹 제목 "어떤 이야기를 찾으세요?"(`titleL 20`) + 부제 하나를 두고, 그 아래로 섹션이 이어진다.

- 섹션 머리: 32 색 타일(`TOPIC_META[t].tint` 배경, radius 10) + **아이콘 17**(`.color`)
  → 이름(`title`) + **큐레이션 한 줄**(`bodyS`, muted) → 우측 `더보기 ›`(`meta`).
  ⚠️ 처음엔 타일에 **라벨 첫 글자**를 넣었다("품"). 무슨 뜻인지 알 수 없는 네모가 일곱 개
  생겼을 뿐이다. 아이콘은 글자보다 먼저 읽히고 칸끼리 구분도 확실하다
  (`TOPIC_META[t].icon` — ShieldCheck · Sparkles · Rocket · BarChart3 · HeartHandshake ·
  TrendingUp · Workflow).
- 몸: `ArticleCardH` 가로 캐러셀(`useArticlesByTopic(topic, 8)`).
- **칸 목록이 아니라 글이 보인다.** 예전엔 7칸을 깔고 눌러야 글이 나왔다. 그러면 홈에서
  할 수 있는 일이 "고르기"뿐이라, 무엇을 고를지 모르는 사람은 아무것도 못 한다.
- **큐레이션 한 줄은 `TOPIC_META[t].blurb`** 다. 예: 품질·위험 관리 →
  "서비스 품질을 지키고 사고를 줄이는 방법".
- **글이 없는 대분류는 통째로 숨긴다** — 빈 줄은 분류가 비어 있다는 사실만 드러낸다.
  대분류가 비어 있는 글이 많으면 홈이 통째로 짧아진다. 그건 화면 문제가 아니라
  **분류가 안 끝났다는 신호**다(`npm run classify`).

### 4.18 연속 읽기 히어로 `ReadingStreakHero` (마이 맨 위)
`primary` 배경 카드, radius 18, padding 18, gap 14.
- 왼쪽: 숫자 `42/50/800` + 단위 "일"(`20/28/700`) + 설명(`cardTitle 15`), 전부 `actionOn`.
- 오른쪽: 62 원형 **테두리만**(`primaryOnDark` 2px) + `Flame 30`.
  배경이 이미 primary 라 안까지 채우면 덩어리가 하나로 뭉갠다.
- 아래 흰 서브카드(`surfaceCard`, radius 14, `paddingV 12`): 이번 달 읽은 글 · 남긴 인사이트.
  칸 사이 1px 세로 hairline. **값이 0 인 칸은 만들지 않는다.**
- **연속이 끊기면 0 을 띄우지 않는다.** "오늘 한 편 / 읽으면 연속이 시작돼요"로 바뀐다 —
  15분짜리 아티클에서 0 은 벌칙으로 읽힌다.

### 4.19 목적 태그 칩 (홈 ② · 피드 상단)
`purpose_tag` 하나를 담는 칩. radius 999, `paddingH 13 / paddingV 7`, `label 12.5`.
- 홈: `surfaceCard` + hairline. 누르면 피드가 그 목적으로 좁혀진다.
- 피드: 켜져 있으면 `primaryTint` + `accentTintBorder` + `X 13` — **지울 수 있어야 한다.**
  왜 목록이 짧은지 모른 채 헤매게 두지 않는다.
- **대분류 칩과 같은 줄에 두지 않는다.** 대분류는 "결론이 무엇인가", 목적은 "무엇을 이루려 했나"라
  나란히 놓으면 둘을 같은 종류로 읽는다.

### 4.20 지금 뜨는 아티클 `HotTicker` (홈 맨 위)
1~10위를 **한 번에 한 줄씩** 3초마다 돌린다. 카드 열 개를 깔면 그걸 또 고르게 되고 홈이 길어진다.
- 카드: `surfaceCard` + hairline, radius 16, `paddingH 14 / paddingV 10`, gap 6.
- 머리: `Flame 13`(primary) + "지금 뜨는 아티클"(`label 12.5`) + 우측 `3 / 10`(`meta 11`).
- 줄: 순위(`15/22/800`, primary, **폭 16 고정** — 한 자리→두 자리에서 제목이 덜컥 밀린다)
  + 제목(`cardTitle 14.5`, 1줄) + `ChevronRight 16`.
- 바뀔 때 180ms 페이드 아웃 → 교체 → 페이드 인. 툭 바뀌면 읽던 줄을 놓친다.
- **멈춤 버튼을 두지 않는다** — 이 작은 줄에 버튼이 둘이 된다. 대신 줄 전체가 링크다.
- 글이 없으면 **아무것도 그리지 않는다.**

### 4.21 서비스 종류 칩 (홈)
`serviceKind.ts` 의 표로 묶은 칩 — radius 999, `paddingH 13 / paddingV 7`, `label 12.5`,
`surfaceCard` + hairline. 섹션 제목은 "서비스 종류별로 모았어요".
- **이름만 담는다.** "사고파는 서비스" 같은 풀이를 붙이면 칩이 카드가 되어 자리를 뺏는다.
- 기업 이름으로만 모으면 토스·카카오페이·네이버페이·뱅크샐러드가 서로 멀리 떨어진다.
- **글이 있는 종류만 그린다** — 눌러서 "0개"를 보게 하지 않는다.
- 누르면 피드가 그 종류의 기업들로 좁혀지고, 상단에 지울 수 있는 칩이 뜬다(§4.19 규격).

### 4.22 시리즈 카드 `SeriesCard` (글 상세)
여러 편으로 나뉜 글을 잇는 카드 — `surfaceCard` + hairline, radius 16, padding 16, gap 12.
머리줄에 `Layers 15` + "이어지는 이야기예요", 오른쪽 끝에 "N편 중 M편"(`meta`).
편마다 한 줄: 회차 뱃지(원 22, radius 999) + 제목 2줄(`body 14/20`).
- **지금 편은 누를 수 없다.** 같은 화면으로 가는 버튼은 눌러도 아무 일이 없어서 "고장났나"로 읽힌다.
  대신 `primary` 테두리 + `primaryTint` 배경 + 채운 뱃지 + `Check 15` 로 여기임을 보인다.
- **제목은 두 줄까지.** 한 줄로 자르면 편마다 부제가 달라 무엇인지 구분이 안 된다.
- 2편 미만이면 **아무것도 그리지 않는다**(빈 카드를 남기지 않는다).
- 시리즈 판정은 `src/lib/series.ts` 의 `seriesOf()` 가 정본이고, DB `series_key/series_no`(스키마 §40)에 적혀 있다.

## 5. 화면별 적용 노트

> 화면은 **목록(홈·피드) · 상세 · 인사이트(글 상세 안) · 마이(아카이브 포함)** 넷뿐이다.
> 알림·커뮤니티 자유글·인사이트 피드·팔로우·글 등록·스터디 화면은 앱에서 걷어냈다.

- **홈**: 워드마크(+연속 pill)·🔍⚙ → 밀린 글 배너(primary) → 검색바
  → ⓪**지금 뜨는 아티클** 티커(§4.20) ①오늘의 글(큰 카드 1편) ②이런 걸 풀었어요(목적 태그 칩)
  ③**대분류 섹션 ×7**(§4.17) ④숫자로 답한 글 ⑤이어읽기 ⑥관심 기업의 새 글 ⑦이번 주 같이
  ⑧서비스 종류 칩(§4.21) ⑨기업별 아이콘 2줄(§4.1).
  **칸 순서 = 기획자의 질문 순서**(PRODUCT.md §2.4). "인기 글" 캐러셀은 없다 —
  인기는 ⓪ 티커 한 줄이 맡고, 인기순 정렬은 피드에 있다.
  **칸마다 부제로 "왜 이 칸인지"를 적는다** — 제목만 줄줄이 있으면 규칙이 없어 보인다.
  **완독률을 홈에 두지 않는다** — 아카이브 탭이 정본이다.
- **피드**: 제목 "피드"+🔍 → 필터 칩 한 줄(`FilterSheet variant="chips"`)
  → [N개 · **M번째 보는 중** · 안 읽은 글만] → `ArticleRow` 리스트.
  **무한 스크롤을 유지하되 그 약점 셋을 메운다**(페이지 번호는 모바일에서 매번 작은 버튼을
  눌러야 하고, 상세를 봤다 돌아오면 1페이지로 튕긴다):
  - **어디쯤인지** — 보이는 마지막 항목으로 `M번째 보는 중`. 끝이 안 보이는 목록에 유일한 좌표다.
  - **읽던 자리로** — 스크롤 위치를 **필터별로** 모듈 스코프 `Map` 에 기억한다(state·ref 는
    언마운트와 함께 사라진다). 복원은 내용이 **그 자리를 덮을 만큼 쌓였을 때 한 번만** —
    마운트 직후엔 1페이지뿐이라 옮길 자리가 없다.
  - **맨 위로** — 800 이상 내려가면 뜨는 pill(우하단 16/20, 그림자 §3).
    늘 떠 있으면 카드 한 장을 계속 가린다. 머리는 목록의 `ListHeaderComponent` 라 **같이 스크롤된다**(붙박이 금지).
  로딩·빈 상태에서도 머리는 남는다 — 0건일 때 필터까지 사라지면 정작 바꿔야 할 순간에 못 바꾼다.
- **아카이브(탭)**: 워드마크+🔍⚙ → 밀린 글 배너 → 완독률 카드 → "OOO님의 아카이브"(수정 토글)
  → 타일 그리드 2열(모든 저장글 → 내 아카이브 → 추가 타일).
- **아카이브 상세**: 이름을 누르면 보관함 전환 드롭다운. 검색 → [전체·읽음·안읽음] + 정렬 →
  "카드 크기 조절"(토글 → 슬라이더) → 목록. `archiveId === null` 이면 "모든 저장글".
- **아카이브 만들기**: 2단계 — ① 제목(최대 15자 + 카운터) ② 아이콘 9종(68 원형, 선택 시 `primary` 보더 2).
  상단에 2칸 진행 막대(높이 3, 50%→100%). `archiveId` 가 오면 같은 화면이 수정 모드.
- **마이**: 워드마크+🔍⚙ → 프로필 카드(테두리) → **연속 읽기 히어로**(§4.18)
  → **활동 스트립**(이번 주 한 줄, §4.16)
  → 메뉴 카드(내 아카이브 · 관심 기업을 테두리 하나에 묶음) → 자주 막히는 영역
  → "내 활동" 세그먼트 → 목록. 달력을 위로 올렸다 — 들어오자마자 이번 주가 보여야 의미가 있다.
- **글 상세**: §5.1.
- **원문 보기(웹뷰)**: 상단 바(뒤로 · 제목/도메인 2줄 · 새로고침 · 브라우저로 열기) + 웹뷰.
  실패하면 "이 블로그는 앱 안에서 열 수 없어요" + `브라우저로 열기` 버튼.
  **밑줄·용어 풀이는 여기서 안 된다**(남의 페이지라 손댈 수 없다) — 그건 상세의 '흐름'이 맡는다.

### 5.1 글 상세 — 구조 계약
원문을 재배열하지 않는다. **뉴스 다이제스트**처럼 요약이 본문이고, 원문은 웹뷰로 따로 연다.

```
① 히어로 16:9 — 이미지 + 스크림 + 제목(22/30) + 한 줄 요약   (+ 좌상단 플로팅 뒤로 40)
─ 본문 영역(좌우 20, paddingTop 16, gap 20) ─
② [로고 20] 출처 · 게시일                      [담기] [공유] [가/가]
   [대표 태그] [세부 태그…]                     ← 목적 태그가 맨 앞
③ 알아두면 편해요 — 개발 용어 카드          §4.10 ①
④ 한눈에 (1분 파악)                          §4.10 ②
   무슨 일이에요? / 왜 했대요? / 그래서 뭐가 달라졌어요?
⑤ 기획 포인트 — 기획자 눈으로 보면            §4.10 ③
⑥ 더 들어가 볼까요? — 질문형 소제목 + 답 문단  §4.10 ④
   └ 칸마다 [원문에서 확인 ▾] → 근거 원문 그대로
⑥ 원문을 보러 가볼까요? → [원문 보기] → 웹뷰   §4.11
⑦ 이어지는 이야기예요 — 시리즈가 있을 때만     §4.22
⑧ 생각해볼 질문 (질문만)                       §4.11
⑧ 다 읽으셨네요, 어떠셨어요? — 스탬프 · 직군 배지
─ 하단 플로팅 바: [인사이트] [원문 보기] [다음 글] ─  §4.11
```
- **읽기시간을 표시하지 않는다.** 사람마다 다르고, 숫자가 붙으면 "오래 걸리는 글"로 읽혀 안 들어온다.
- **세그먼트 탭(글 읽기 / 인사이트)은 없다.** 인사이트는 플로팅에서 시트로 연다 —
  다 읽고 나서 여는 것이지, 본문과 나란히 놓고 고르는 것이 아니다.
- **"핵심만 볼래요" 토글도 없다.** 요약이 이미 본문이라, 요약의 요약을 또 두면 어느 쪽이 정본인지 흐려진다.
- 가이드가 없으면 즉석 생성을 **화면당 한 번만** 시도한다. 실패하면 이유와 `다시 시도`를 보여준다
  (§4.10) — 실패를 숨기면 파이프라인이 멈춘 걸 아무도 모른다.
- 저장해 둔 가이드가 있어도 **읽을 수 있는 모양인지 먼저 확인**하고 아니면 다시 만든다
  ("값이 있다"와 "쓸 수 있다"는 다르다).
- 스크롤 90% 도달 = 읽음 처리 + 이어읽기 위치 제거.

## 6. 접근성·다크모드
- 텍스트 대비 AA 이상. 터치 타깃 ≥ 40, 작은 아이콘은 `hitSlop 6~8`.
- 색만으로 정보를 전달하지 않는다 — 중요도는 **라벨 + 접힘**, 핫은 **색 + 아이콘**, 난이도는 **글자**.
- 모든 색은 토큰 → 다크 자동 대응. 다크에서는 그림자 대신 `hairline` 으로 경계를 만든다.
- **화면 크기는 `useWindowDimensions()` 로 읽는다.** `Dimensions.get()` 을 모듈 최상위에서
  읽으면 그 값이 **페이지가 뜬 순간 한 번만** 잡혀 창 크기를 따라가지 않는다.
  웹에서 브라우저를 좁혔더니 캐러셀 카드가 옛 폭 그대로 남아 화면 밖으로 삐져나갔다(실측).
  카드 폭·히어로 높이·시트 높이처럼 화면에서 파생되는 값은 전부 훅으로 읽는다.
